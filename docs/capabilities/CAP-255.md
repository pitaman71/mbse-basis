# CAP-255: mbse-expressions' installs, writers and corpus typed

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Relates to* [QUA-014: precise typing for bespoke and generated source code](../QUALITIES.md#QUA-014), [PRI-015: concrete references are programmatic](../PRINCIPLES.md#PRI-015).

## Design

Not built. This capability is tech debt, incurred since mbse-expressions 0.7.0 as its dialects were made complete
([CAP-226: complete expression dialects](CAP-226.md)) and their domains made data. The installs, defines, writers and conformance corpus build
schemas and terms in fluent syntax through mbse-schemas' builder proxies, which no type checker sees, so each builder
callback is `any` in TypeScript and every install and define takes an untyped transaction, all 19 in each language:
`install(txn: any): any` in TypeScript, under a file-level `eslint-disable no-explicit-any` (in 26 files), and
`txn: Any` in Python. A misspelled property or a term of the wrong kind is then caught by
validation or a test, not by the compiler.

Counted in mbse-expressions' main at 3711f8a, against 0.7.0, by whole word:

| | 0.7.0 | main |
|---|---|---|
| `any` in `typescript5/src` | 931 | 2,480 |
| one-parameter `any` callbacks, `(x: any) =>`, in `typescript5/src` | 592 | 1,918 |
| of them, in the dialects' `Expressions.ts` (their installs and writers) | 503 | 1,395 |
| of them, in `Conformance/Corpus.ts` | 15 | 442 |
| `as any` casts in `typescript5/src` | 5 | 10 |
| `any` in `typescript5/tests` | 545 | 3,053 |
| `Any` in `python3/mbse` | 905 | 1,260 |

Among the new `as any` casts, the printers of `Python3` and `TypeScript5` dispatch on a kind's tag by method name
(``(this as any)[`_${tag}`]``, in `Python/Python3/Text.ts`, twice, and `TypeScript/TypeScript5/Text.ts`), and
`Framework/Terms.ts` walks a schema's `refines` through `as any`.

Met when the installs, defines, writers and corpus are typed: typed bindings for mbse-schemas' builder proxies, so that
a model used in code has typed bindings ([PRI-015: concrete references are programmatic](../PRINCIPLES.md#PRI-015)), and a typed dispatch table for the printers.

## Decided

- **Logged as tech debt** (2026-11-10): as the user decided, "Tech debt is capability codes, not notes in markdown",
  and "I don't know why you would expect a single feature to contain all tech debt items"; approving ("yes") that each
  debt be a capability of the feature whose work caused it, relating to [QUA-014: precise typing for bespoke and generated source code](../QUALITIES.md#QUA-014) where it concerns typing, and
  that a debt an existing capability already covers be linked to it rather than made a capability of its own.

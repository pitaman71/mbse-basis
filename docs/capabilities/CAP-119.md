# CAP-119: owned objects found by path

*Implements* [FEA-026: identity and transactions](../features/FEA-026.md). Index entry: [capabilities/README.md](README.md#CAP-119).

## As built: mbse-schemas

Met in mbse-schemas 0.20.0: the [store overhaul](../../../mbse-schemas/docs/proposals/store-overhaul/README.md)'s 4b, data objects by path (lookup by keys, paths), and 4c, released as 0.20.0.

### Reading and finding

A program does not read or write an identity through the visitor: `as_identity` goes (43). An owned object's path is
read off its ownership entries on demand, as a `Paths.OfRoot` value, by `Paths.of(obj)` (32). A program finds:

- a singleton by its global name, `store.Instances.wts.Features` (26);
- an owned object by calling an adjacency with the keys of the entry that leads to it, on any adjacency:
  `store.Instances.wts.Features.dir({ name: 'DEF-693' }).clauses({ name: 'C-1' })` (in Python, a mapping:
  `.dir({'name': 'DEF-693'})`); keys no entry has raise (26 to 28);
- a counted object only by visiting what links it (40 in [CAP-118: singletons, owned and counted objects](CAP-118.md#decided)).

### Paths as data

`Paths.OfX` are nestable value objects:

- `Paths.OfRoot` bears two properties: `singleton`, a globally unique singleton name, and `next`, a
  `Union[entry: Paths.OfEntry, target: Paths.OfTarget]`.
- `Paths.OfEntry` bears four properties: `i`, the name of the adjacency to the object addressed by the previous path
  element; `o`, the name of the adjacency to the object addressed by the next path element; `properties`, a value
  object literal assigning each property of the transited relation the value that uniquely continues the path to the
  target via this relation; and `next`, a `Union[entry: Paths.OfEntry, target: Paths.OfTarget]`.
- `Paths.OfTarget`: no more traversals, the object is found.

A key's value is a bool, an int or text, so that `properties` is written bare (`{"name": "DEF-693"}`): a float or bytes
would not be told apart from an int or text on the wire. Every store holds the path schemas, its own, as it holds its
mutation schemas.

A path has no shorthand: it is written as the nested value object it is, as any value is ([PRI-019: fluent builder syntax](../PRINCIPLES.md#PRI-019)). The
definition the Ownership example places, on the wire, its unions tagged by branch:

```json
{"singleton": "wts.Features", "next": {"entry": {
    "i": "dir", "o": "def", "properties": {"name": "DEF-693"}, "next": {"target": {}}}}}
```

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(object identity 1)** As the user decided (2026-10-16), on the questions put to them: A suffix is looked up by `as_instance`: "yes use as_instance". A suffix need not be an identifier (`FEA-001`, `Anna
  Baker`, a UUID), so `store.Instances.<path>.as_instance(suffix)` takes it as a string: the one place an object's
  identity references it ([PRI-015: concrete references are programmatic](../PRINCIPLES.md#PRI-015), Exceptions); the path is attributes. (How a path given as data reaches
  `as_instance`, now that an identity is a path rather than a suffix, is open; see below.) (Superseded by 26: a path's
  step is looked up by calling its adjacency with the entry's keys.)
- **(object identity 4)** On the wire: "use `Schema@Path/Suffix` and omit `Schema@` when it can be inferred from context". (Superseded by 8
  and 12: an identity is a path; `Schema@` only in `Exists`.)
- **(object identity 5)** "Programs cannot set or modify their identity": "yeah that rule is completely gone". (Superseded by 16:
  `as_identity` is read-only again outside deserialization.)
- **(object identity 7)** `as_identity`'s callback visits the identity: "yes, Schemas.OfIdentity now is an object" (its `suffix` and its
  module path, `module`). (Superseded by 18: an identity is a path, `Paths.OfX` value objects.)
- **(object identity 8)** `Schema@` is written only where an object is created, in `Mutations.OfObject.Exists`, which must know what to
  build; everywhere else the path references the object, "the path is sufficient to reference the object without the
  schema", since "there is one directory store per module within each store".
- **(object identity 16)** "as_identity can resume being read-only for code outside of deserialization". (Superseded by 43.)
- **(object identity 18)** Paths are data, `Paths.OfX`, "nestable value objects": `Paths.OfRoot`, `Paths.OfEntry` (its `i`, `o`,
  `properties` and `next`) and `Paths.OfTarget`, as
  Paths as data gives them, with the shorthand `path.to.root.singleton` `.{inAdj}-{entryProps}>{outAdj}` ...,
  for example `wts.Features.dir-{name:"FEA-693"}>def`, "oftarget is implied". (The shorthand is superseded by 23.)
- **(object identity 23)** No shorthand: "Maybe we should do without shorthand. Just write the path as a nested value object."
- **(object identity 24)** `Paths.OfEntry`'s `in` and `out` are named `i` and `o` ("just call them i and o"), since `in` is a Python keyword
  and a schema's properties are its builders' and proxies' members.
- **(object identity 25)** `next` is `Union[entry: Paths.OfEntry, target: Paths.OfTarget]`: its branches are `entry` and `target`.
- **(object identity 26)** Lookup by path in code calls each step's adjacency with the entry's keys, a mapping of its key properties to their
  values: `store.Instances.wts.Features.dir({ name: 'DEF-693' }).clauses({ name: 'C-1' })` (in Python,
  `.dir({'name': 'DEF-693'})`). `store.Instances.<singleton>` is the root; each call is one `Paths.OfEntry`.
- **(object identity 27)** Lookup is on any adjacency ("on any adjacency I should think"), not only under `store.Instances`: an object's
  adjacency called with a mapping of the entry's keys gives the object that entry links. And [PRI-015: concrete references are programmatic](../PRINCIPLES.md#PRI-015)
  "reverts to its original form. Code expressions that name a reference object use Paths, not string lookup": its
  `as_instance` exception (1) is withdrawn.
- **(object identity 28)** A lookup with keys no entry has raises: "adjacency is called with keys no entry has -> raise".
- **(object identity 32)** An identity is computed on demand ("yes, on demand"): no object holds one; its path is read off its ownership
  entries when asked, so a key written anew (an entry's `name`) renames the object, and another owner moves it.
- **(object identity 35)** `as_identity()` gives the path, a `Paths.OfRoot` value computed on demand ("The path value (Recommended)"). (Superseded by 43.)
- **(object identity 43)** "as_identity can go away" (superseding 16 and 35). An owned object's path is still read by `Paths.of(obj)` (32).

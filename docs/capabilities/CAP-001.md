# CAP-001: no-code index view

*Implements* [FEA-001: schema-driven UI](../features/FEA-001.md), [FEA-046: a React, TypeScript and CSS-in-TS UI stack](../features/FEA-046.md).

Service + UI code must be able to present a useful and usable
"index site" driven exclusively by the schema.

## As built

### The service for any MBSE app

Its factory and configuration as [CAP-290: a service's store stacked, with no snapshot](CAP-290.md) designs them,
built on mbse-rest's branch `CAP-290`, not yet merged; mbse-rest's main is given a persistence plugin in place of a
store below.

```python
from mbse.Services.Rest import Service

api = Service.app(installs, below=None, seed=None, origins=())  # a FastAPI application
```

- `installs`: the app's installs, each a callback given a transaction (`store.transaction(install)`), its schemas'.
  `Service.installs_of("my.App")` finds them by mbse-demo-apps' layout: `my.App.Schemas.INSTALLS` where the package
  lists them, else `my.App.Schemas.install`; `Service.seed_of("my.App")` its `my.App.Seed.seed`, where it has one.
- `below`: the store the service's store is stacked on, where it persists, as
  [CAP-290: a service's store stacked, with no snapshot](CAP-290.md#the-service) designs it; one in memory where None.
- `origins`: the origins a browser may call the service from (CORS, `GET` and `POST`): none by default.
- `api.state.service` is the `Service`: its `store`, `below` and `installs`.
- `Service.work_tracker(below)` is the stub server over the WorkTracker.

#### Running it

```sh
cd python3 && uv run python -m mbse.Services.Rest   # serves with uvicorn, as the environment configures it
```

| Variable | Default | What |
|---|---|---|
| `MBSE_REST_APP` | `mbse.Demos.Apps.WorkTracker` | the app's package, its installs by `installs_of` |
| `MBSE_REST_SEED` | `1` | whether its `Seed.seed` runs where the store below is new (`1`/`0`, `true`/`false`) |
| `MBSE_REST_STORE` | `memory` | the store below, by `store_of`'s name, e.g. `mbse.Persistence.DynamoDB.Store:Store` ([CAP-290: a service's store stacked, with no snapshot](CAP-290.md#the-service)) |
| `MBSE_REST_WINDOW` | `10000` | how many of the latest committed transactions the change feed keeps ([CAP-290: a service's store stacked, with no snapshot](CAP-290.md#the-service)) |
| `MBSE_REST_ORIGINS` | none | the UI's origins, comma-separated, e.g. `http://localhost:5173` |
| `MBSE_REST_USER` | `demo` | the identity the service stamps on writes ([CAP-015: transaction provenance](CAP-015.md)), standing in for a validated token |
| `MBSE_REST_HOST` | `127.0.0.1` | where it listens |
| `MBSE_REST_PORT` | `8000` | |

`Service.from_environment()` builds the same application, for any ASGI server:
`uv run uvicorn --factory mbse.Services.Rest.Service:from_environment`.

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-rest 17)** **The factory** takes `origins` by keyword; an app's installs are found by mbse-demo-apps' layout
  (`Schemas.INSTALLS` or `Schemas.install`, optional `Seed.seed`), and the store below by `memory` or
  `module:attribute`, made with no arguments.
- **(mbse-rest 18)** **Configuration by environment variables**, `MBSE_REST_*`, as in [Running it](#running-it); the app defaults to the WorkTracker, the demo, and CORS to no origin
  at all, so that a browser can call the service only from origins it is given.

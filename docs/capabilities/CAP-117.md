# CAP-117: extension adjacencies to any relation

*Implements* [FEA-031: schemas as extensible data](../features/FEA-031.md), [FEA-020: refinable models](../features/FEA-020.md). Index entry: [capabilities/README.md](README.md#CAP-117).

## Design

Not built:

### The limit Parametrics met

*Since store overhaul 4m, `Parametrics` is such an extension, installed before use: it gives `Schemas.OfParameter` its
`for_value` and `for_object` and every kind its `parameters`, which the core no longer declares; the parameters of
section 4 and of Decided, 6 in [FEA-024: expressions as data](../features/FEA-024.md#decided) and 14 in [CAP-112: parameters modeled as schema data](CAP-112.md#decided) are its ([CAP-112: parameters modeled as schema data](CAP-112.md)). The entries a
transaction writes from a schema object the store held before it began are written at once, in the transaction, as
data's are, not when it commits. An extension's adjacency is still to a relation of two links and no properties
(Decided, 18 in [CAP-116: framework schemas extended, checked](CAP-116.md#decided) and 22 in [FEA-024: expressions as data](../features/FEA-024.md#decided)), which keeps `Parametrics` from installing its bindings' adjacencies: open.*

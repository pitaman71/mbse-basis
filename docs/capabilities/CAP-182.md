# CAP-182: modeling system structure as containers, axes and containment

*Implements* [FEA-009: layered interaction models](../features/FEA-009.md). *Relates to* [CAP-028: layered interaction models](README.md#CAP-028), [CAP-041: every kind of participant](README.md#CAP-041), [CAP-183: modeling system interactions as modules, interfaces, ports, implementations, instances and channels](CAP-183.md).

## As built: mbse-sysarch

Met in mbse-sysarch 0.1.0, Python only, on mbse-schemas 0.22.0: checked in the code at 0.1.0
(`mbse.Architecture.Systems.Framework.Structure`; the STR and CHK suites). `Structure.define(store)` builds the
package in the caller's store: `Structure.Container` and `Structure.Axis` (OBJECT), and `Structure.Contains`,
`Structure.Organizes` and `Structure.Orients` (RELATION), their members and `uniques` as
[the design's Structure table](https://github.com/pitaman71/mbse-sysarch/blob/main/docs/SYSARCH.md#structure) gives
them. `Structure.Check()(root)` lists what no `unique` clause expresses, for everything reachable from `root`.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **The plan, as the user wrote it**, under "System Architecture + Interaction Models":

  > Repo: `mbse-sysarch`
  >
  > Files:
  > - `mbse-sysarch/python3/mbse/Architecture/Systems/Framework/Interactions`
  >
  > OBJECT denotes mbse-schemas.Schemas.OfObject (ref)
  > RELATION denotes mbse-schemas.Schemas.OfRelation (ref)

  Its organization:

  > - OBJECT Structure.Container
  > - RELATION Structure.Contains(c1, c2) # hard or soft containment depending on context
  > - OBJECT Structure.Axis # organizational direction
  > - RELATION Structure.Organizes(hard,soft) # makes one container a "soft" container inside of the "hard" container
  > - RELATION Structure.Orients(axis,soft_container) # soft containment

- **While building it**, recorded in [mbse-sysarch's design, Resolved](https://github.com/pitaman71/mbse-sysarch/blob/main/docs/SYSARCH.md#resolved):
  the repository and its scope, Python only for now (item 1); hard or soft is the container's, `Contains(c1, c2)`
  soft where `c1` is the `soft` end of an `Organizes` entry (item 3); implementations and instances are containers
  (item 4); and Structure a package of its own (item 5).

## Decided by an agent, for review

Recorded in [mbse-sysarch's design, Resolved](https://github.com/pitaman71/mbse-sysarch/blob/main/docs/SYSARCH.md#resolved),
not marked as the user's: each *proposed* until reviewed. Soft containment stays inside its hard container (item 15),
and checks are functions over a reachable graph, naming each object by its schema and path (item 16).

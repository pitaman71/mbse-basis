# CAP-179: dataclass schemas built through the store's builders

*Implements* [FEA-022: code generation](../features/README.md#FEA-022). Index entry: [capabilities/README.md](README.md#CAP-179). It follows [CAP-162: Python dataclasses translated to and from schemas](CAP-162.md).

## As built: mbse-schemas

Met in mbse-schemas 0.23.0, Python only, checked in the code at 0.26.4: the [store overhaul](../../../mbse-schemas/docs/proposals/store-overhaul/README.md)'s 4l.
`FromDataclass.install(txn, module, *classes)` writes the schemas it reads as one upsert of the install transaction it
is given, so that the store's builders build them ([CAP-162: Python dataclasses translated to and from schemas](CAP-162.md), as built). `FromDataclass.model(...)`,
which returned schema objects made outside any store for the caller to register, is gone.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(store overhaul 31)** The dataclass adapter writes an install ("sounds good"), so that it depends on the
  transaction's spec, not on the builders 4k rewrites; and "yes remove FromDataclass.model".

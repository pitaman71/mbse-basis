# CAP-005: label and summary view

*Implements* [FEA-003: no-code logical views](../features/FEA-003.md). Index entry:
[capabilities/README.md](README.md#CAP-005).

This is a minimum-sized logical view of an object or a relation entry.

Given a `References.OfObject` or `References.OfEntry`, 
UI can obtain a logical view template, the response for which
comprises two strings : 

- `label`: a one-line phrase
- `summary` : a sentence or short paragraph describing the object or relation entry

Each maps to a specific property. For now the sensible default is a naming
convention: `label` is the first of the properties `label`, `name` and
`title` that the object holds, and `summary` the first of `summary` and
`description`.

Where no property matches, `label` falls back to the schema's name and the
object's last path key; for a relation entry, to its relation's name and
the labels of its linked objects. Where no property matches, `summary` is
empty.

## As built

mbse-rest serves this as the `label` view kind: what its frames carry is in [FEA-003: no-code logical views](../features/FEA-003.md#view-kinds)'s view kinds, beside the other three.

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-rest 5)** **Relation entries (this capability, [CAP-006: chip view](CAP-006.md)
  given a `References.OfEntry`)** have no template of their own: a pattern's symbol binds an object, never an entry.
  Entries arrive in `detail` and `adjacency` frames, with their properties, and the client labels them
  (`Views.entryLabel`).
- **(mbse-rest 6)** **Label fallbacks** as in [FEA-003: no-code logical views](../features/FEA-003.md#view-kinds)'s view
  kinds: the schema's name only where the caller knows it (a frame does not carry an object's schema), the last key of
  the object's path, and `relation: label, label` for an entry.

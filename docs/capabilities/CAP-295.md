# CAP-295: simplification of single-dialect expressions with literal leaves

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Applies* [PRI-046: simplification, not evaluation](../PRINCIPLES.md#PRI-046). *Relates to* [CAP-099: partial evaluation](CAP-099.md), [CAP-106: expressions evaluated three-valued](CAP-106.md).

## As built: mbse-expressions

mbse-expressions built this capability in version 0.11.0, which is not yet released. The work was simplification's
step 2, and it ran over the framework that step 1 built (#48). Agents built one dialect family at a time: TypeScript5
in #49 and #50, then Python3 in #51, C and C++ in #52, and SystemVerilog in #53. The coordinating session integrated
the four families in #54.

[The evaluation inventory](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#evaluation-what-is-refused-and-why)
gives class (a) to every kind that is free of statements and has a value that its language defines. The inventory also
gives class (a) to some shapes within kinds that a dialect already folds, such as a keyword argument within a call.
Each family now folds all of its class (a) kinds and shapes, and it follows its own language's semantics when it does
so. The dialects Patterns, MATLAB and Excel already folded their class (a) kinds before this step.

When a value has a literal in its dialect, the simplifier replaces the subterm with that literal. When a value has no
literal in its dialect, as with a closure, a set, an array or a C `char`, the subterm stays in the residual, and the
simplifier simplifies the subterm's own subterms. The simplifier names every subterm that stays for want of a rule,
together with its class in the inventory.

Each family's detailed record is its As built section in
[the evaluation proposal](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-the-framework-0110).
This section summarizes those records and links to them:

- **TypeScript5** folds by ECMA-262's abstract operations, which both implementations model in the same way
  ([As built: TypeScript5](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-typescript5-0110)).
  ECMAScript's built-in methods and host values stay in the residual. They wait on
  [CAP-301: simplification delegated to a surrogate dialect](README.md#CAP-301).
- **Python3** folds by CPython 3.14's semantics. The Python implementation runs Python itself, and the TypeScript
  implementation models Python's rules
  ([As built: Python3](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-python3-0110)).
  Python3 now folds constants and complex numbers, displays, f-strings and t-strings, slices, comprehensions, lambdas
  and keyword arguments.
- **C and C++** fold by ISO/IEC 9899 and ISO/IEC 14882. They read each type's width and layout from the ABI dialect
  that the expression's holder names
  ([As built: C and C++](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-c-and-c-0110);
  [CAP-267: C and C++ terms read under the ABI their holder names](CAP-267.md)).
- **SystemVerilog** folds by IEEE 1800-2023. It sizes the whole expression by IEEE 1800's clause 11.6, and it folds a
  subterm wherever the subterm's literal keeps the subterm's meaning
  ([As built: SystemVerilog](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-systemverilog-0110)).

Some class (a) items still stay in the residual, as the inventory's counts record. Two dialects still have class (a)
kinds that do not fold: C Preprocessor has one, `defined`, and SystemVerilog Constraints has seven. Thirteen class (a)
shapes within folded kinds also stay. In each of those thirteen shapes, the two implementations cannot yet compute
the same result. A complex power whose exponent is not an integer, a format that depends on a locale, and a layout
that no ABI dialect stores are three examples.

## Decided by an agent, for review

The agents recorded their decisions in
[the port's API, Settled in simplification](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-simplification-for-the-users-review),
items 334 to 373, which hold the detail. Each decision remains proposed until the user reviews it. On 2026-11-15 the
user decided that where a decision chooses between two defensible behaviors, the choice becomes an option of
simplification, and the agent's choice becomes that option's default
([CAP-305: simplification's options, chosen up front](CAP-305.md)).

- **(mbse-expressions 49, TypeScript5, API 334 to 340)** The TypeScript5 simplifier models ECMAScript's values and
  abstract operations in a separate module, `Abstract`. The module's functions take the names that ECMA-262 gives to
  the operations, such as `ToPrimitive` and `IsLooselyEqual`. A simplified expression can call or read only what the
  caller's scope provides, or what the expression itself creates. When an expression uses one of ECMAScript's
  built-in methods, such as `String.prototype.toUpperCase`, the simplifier does not run the method: the expression
  stays in the residual, and the residue names the method. When the simplifier writes a computed value back as
  source text, it writes the value in ECMAScript's own syntax, so that `undefined`, `NaN` and `-0` appear by name. A
  BigInt result larger than 2^30 bits raises a `RangeError` in both implementations, because 2^30 bits is V8's limit.
- **(mbse-expressions 51, Python3, API 341 to 350)** A lambda's value is a closure. The closure binds its parameters
  as CPython does, and it raises CPython's error messages. Python leaves to the implementation whether two equal
  immutable values are the same object, so the expression `1 is 1` stays in the residual with class (b). A format
  specification that Python would refuse stays in the residual instead of raising `ValueError`. Complex arithmetic
  follows CPython's, and `abs` of a complex number is the correctly rounded `hypot` in both implementations. A complex
  power whose exponent is not an integer stays in the residual.
- **(mbse-expressions 52, C and C++, API 351 to 362)** When a value's type has no literal, as with `char` or `short`,
  the value stays in the residual, and the simplifier does not write the value as a cast of a literal. Arithmetic on
  such a value still folds. The simplifier writes a floating value as a literal wherever a binary64 literal spells the
  value exactly, as with `3.0L`. A conditional expression converts its chosen operand to the common type of its two
  operands, whenever the simplifier can know the other operand's type without evaluating that operand. `_Generic`
  matches types by C's rules of type identity. The caller's scope provides C++'s parameter packs.
- **(mbse-expressions 53, SystemVerilog, API 363 to 373)** A cast to an integral type sizes its operand as an
  assignment does, following IEEE 1800's clause 6.24.1. This rule changes the earlier behavior: the expression
  `16'(8'hFF+8'h01)` now folds to `16'h0100`. A time literal folds only when the caller's scope gives a time unit,
  and the scope has no default unit. A call can pass named and default arguments when the scope provides the
  function as a `Subroutine`. A constant pattern matches a value when the two are identical by `===`.

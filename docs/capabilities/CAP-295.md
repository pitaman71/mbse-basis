# CAP-295: simplification of single-dialect expressions with literal leaves

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Applies* [PRI-046: simplification, not evaluation](../PRINCIPLES.md#PRI-046). *Relates to* [CAP-099: partial evaluation](CAP-099.md), [CAP-106: expressions evaluated three-valued](CAP-106.md).

## As built: mbse-expressions

mbse-expressions 0.11.0 holds this capability's build. The framework's simplification procedure,
`Framework.Simplifiers`, counts a simplification as an evaluation when the residual's root is a closed constructor
expression ([VOC-034: closed constructor expression](../VOCABULARY.md#VOC-034)): a literal, a display, or a cast of
literals. `Simplified.constructed` says whether the root is one, and `Simplified.evaluate()` gives its value. Each
dialect's simplifier writes a value through two hooks: `literal`, which writes the value's literal, and `construct`,
which writes a value that has no literal as a closed constructor expression. A subterm whose value neither hook writes
stays in the residual, and the simplifier simplifies the subterm's own subterms. The simplifier names every subterm that
stays for want of a rule, together with its class in the evaluation inventory.

[The evaluation
inventory](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#evaluation-what-is-refused-and-why)
gives class (a) to every kind that is free of statements and has a value that its language defines, and to some shapes
within kinds that a dialect folds, such as a keyword argument within a call. The simplifiers of the dialects
TypeScript5, Python3, C, C++ and SystemVerilog fold all of their class (a) kinds and shapes, each by its own language's
semantics, as the simplifiers of Patterns, MATLAB and Excel do. Each family's detailed record is its As built section in
[the evaluation
proposal](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-the-framework-0110),
which this section summarizes and links to:

- **TypeScript5.** The dialect's simplifier folds by ECMA-262's abstract operations, which both implementations model in
  the `ECMAScript` module ([As built:
  TypeScript5](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-typescript5-0110)).
  The module models an object's prototype, so an object literal's `__proto__` key folds, and the simplifier writes such
  an object as a display with a `__proto__` key. ECMAScript's built-in methods and host values stay in the residual,
  because they wait on [CAP-301: simplification delegated to a surrogate dialect](CAP-301.md).
- **Python3.** The dialect's simplifier folds by CPython 3.14's semantics, which the Python implementation runs and the
  TypeScript implementation models ([As built:
  Python3](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-python3-0110)).
  It writes a non-empty set as its display, in an order that both implementations compute, and it folds a `\N{...}`
  escape by Unicode's character names. The TypeScript implementation reads those names from a data file,
  `grammars/python3-unicode-names.json`.
- **C and C++.** The two dialects' simplifiers fold by ISO/IEC 9899 and ISO/IEC 14882, and they read each type's width and
  layout from the ABI dialect that the expression's holder names ([As built: C and
  C++](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-c-and-c-0110);
  [CAP-267: C and C++ terms read under the ABI their holder names](CAP-267.md)). They write a value whose type has no
  literal of its own as a C-style cast of a literal, such as `(short)3`. The C dialect's simplifier writes an array as a
  compound literal, and it folds compound literals with nested braces and with an array of arrays.
- **SystemVerilog.** The dialect's simplifier folds by IEEE 1800-2023 ([As built:
  SystemVerilog](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/evaluation/README.md#as-built-systemverilog-0110)).
  It sizes the whole expression by IEEE 1800's clause 11.6, and it folds a subterm wherever a literal, or a cast of a
  literal such as `int'(5)`, keeps the subterm's meaning. It folds `$sformatf` with every format specification that
  computes a value, `%u`, `%z` and `%p` among them.

Some class (a) items stay in the residual, and other capabilities cover them. Two sublanguage dialects have class (a)
kinds that do not fold: C Preprocessor's `defined` and SystemVerilog Constraints' seven kinds, which [CAP-299:
simplification across a sub-dialect](CAP-299.md) covers. Four shapes within folded kinds depend on the platform, the
locale or the implementation, and they are options of [CAP-305: simplification's options, chosen up front](CAP-305.md).
Four shapes need layouts that no ABI dialect stores, which [CAP-307: layouts of bit-precise integers and `nullptr_t`
stored by the ABI dialects](README.md#CAP-307) stores.

## Decided

- A simplification is a successful evaluation when it returns a closed constructor expression as the simplified root
  ([VOC-034: closed constructor expression](../VOCABULARY.md#VOC-034)). This is the capability's acceptance
  criterion, as the user decided.
- The user decided where the class (a) items that stay belong. C Preprocessor's `defined` and SystemVerilog Constraints'
  seven kinds belong to [CAP-299: simplification across a sub-dialect](CAP-299.md). Python3's complex power with an
  exponent that is not an integer, its format spec that Python would refuse, its format spec that depends on a locale,
  and its field whose text is the implementation's belong to [CAP-305: simplification's options, chosen up
  front](CAP-305.md). C's `sizeof` and `alignof` of `_BitInt(N)` and of `nullptr_t` belong to [CAP-307: layouts of
  bit-precise integers and `nullptr_t` stored by the ABI dialects](README.md#CAP-307). The other class (a) items belong
  to this capability: the closed constructor expressions that each dialect writes, and the five shapes that its As built
  section names.

## Decided by an agent, for review

The agents recorded their decisions in
[the port's API, Settled in simplification](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-simplification-for-the-users-review),
items 334 to 373, which hold the detail. Each decision remains proposed until the user reviews it. Where a decision
chooses between two defensible behaviors, the user decided that the choice is an option of simplification
([CAP-305: simplification's options, chosen up front](CAP-305.md)).

- **(mbse-expressions 49, TypeScript5, API 334 to 340)** The TypeScript5 simplifier models ECMAScript's values and
  abstract operations in a separate module, `ECMAScript`, which takes the name of the standard that it models. The
  module's functions take the names
  that ECMA-262 gives to the operations, such as `ToPrimitive` and `IsLooselyEqual`. A simplified expression can call or
  read only what the caller's scope provides, or what the expression itself creates. When an expression uses one of
  ECMAScript's built-in methods, such as `String.prototype.toUpperCase`, the simplifier does not run the method: the
  expression stays in the residual, and the residue names the method. When the simplifier writes a computed value back
  as source text, it writes the value in ECMAScript's own syntax, so that `undefined`, `NaN` and `-0` appear by name. A
  BigInt result larger than 2^30 bits raises a `RangeError` in both implementations, because 2^30 bits is V8's limit.
- **(mbse-expressions 51, Python3, API 341 to 350)** A lambda's value is a closure. The closure binds its parameters
  as CPython does, and it raises CPython's error messages. Python leaves to the implementation whether two equal
  immutable values are the same object, so the expression `1 is 1` stays in the residual with class (b). A format
  specification that Python would refuse stays in the residual instead of raising `ValueError`. Complex arithmetic
  follows CPython's, and `abs` of a complex number is the correctly rounded `hypot` in both implementations. A complex
  power whose exponent is not an integer stays in the residual.
- **(mbse-expressions 52, C and C++, API 351 to 362)** The simplifier writes a floating value as a literal wherever a
  binary64 literal spells the value exactly, as with `3.0L`. A conditional expression converts its chosen operand to the
  common type of its two operands, whenever the simplifier can know the other operand's type without evaluating that
  operand. `_Generic` matches types by C's rules of type identity. The caller's scope provides C++'s parameter packs. A
  value whose type has no literal of its own is written as a cast of a literal, which is the default of CAP-305's first
  option.
- **(mbse-expressions 53, SystemVerilog, API 363 to 373)** A cast to an integral type sizes its operand as an
  assignment does, following IEEE 1800's clause 6.24.1. By this rule, the expression `16'(8'hFF+8'h01)`
  folds to `16'h0100`. A time literal folds only when the caller's scope gives a time unit,
  and the scope has no default unit. A call can pass named and default arguments when the scope provides the
  function as a `Subroutine`. A constant pattern matches a value when the two are identical by `===`.

- **(mbse-expressions 62, CAP-295's step, API 377 to 400)** The dialects' simplifiers write C++'s casts in C's notation,
  `(T)x`, because a functional cast such as `unsigned char(5)` is ill-formed C++. The C dialect's simplifier raises
  `TypeError` for four initializers that C leaves undefined or forbids, `(int[]){}` among them. The Python3 dialect's
  simplifier orders a set's display by value. In TypeScript, an object that the scope makes with `Object.create(null)`
  reads no built-in of Object.prototype. The SystemVerilog dialect's simplifier writes `%u` and `%z` with each word's
  bytes in little-endian order. API items 397 to 400 hold the framework's choices.

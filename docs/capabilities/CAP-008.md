# CAP-008: adjacency as a list of chips

*Implements* [FEA-003: no-code logical views](../features/FEA-003.md). Index entry:
[capabilities/README.md](README.md#CAP-008).

Given a `References.OfObject` and the name of one of its adjacencies, 
UI can obtain a logical view template, the response for which
comprises a list of immediate adjacencies 
including entry properties, the linked object's `References.OfObject`,
and chip view of the linked object.

The adjacency is named in the template's spec. For example, the people
`ada` knows, `ada` given by reference:

```python
store.transaction(lambda t: t.mutations([lambda mu: mu.map(lambda m: m.symbols([lambda p: p
    .symbols({"x": ada_reference, "y": t.crm.Person})
    .spec([lambda _: _.x.knows([_.y])])]))]))
```

## As built

mbse-rest serves this as the `adjacency` view kind: what its frames carry is in [FEA-003: no-code logical views](../features/FEA-003.md#view-kinds)'s view kinds, beside the other three.

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-rest 9)** **Adjacency** witnesses every entry of `x`'s named adjacencies that links `y`, rather than reading
  the adjacency's name from the request's spec; for the WorkTracker the two agree.

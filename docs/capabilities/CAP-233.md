# CAP-233: literals of any value

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). Index entry: [capabilities/README.md](README.md#CAP-233). *Relates to* [CAP-095: Basic terms as data](CAP-095.md), [CAP-096: collections in expressions](CAP-096.md), [CAP-071: unrestricted OfAny serializes with 1-level tag](CAP-071.md), [CAP-226: complete expression dialects](CAP-226.md), [CAP-227: the Python3 expression dialect](CAP-227.md).

## Design

Not built. As built in mbse-expressions 0.7.0, a `literal`'s `value` is an `OfAny` restricted to the five basic
scalars ([CAP-095: Basic terms as data](CAP-095.md)). It becomes an unrestricted `Schemas.OfAny`: a literal holds any
value, scalars, containers and value objects, written on the wire with the one-level tag of an unrestricted `OfAny`
([CAP-071: unrestricted OfAny serializes with 1-level tag](CAP-071.md)). A container may then be written as a literal or
by a constructor (`list`, `mapping`, [CAP-096: collections in expressions](CAP-096.md)), and a dialect or printer may
prefer either. What mbse-schemas has no schema for, such as Python's `None`, `...` and complex numbers, is not a value
`OfAny` holds: `Python3` defines a constant kind of its own for them ([CAP-227: the Python3 expression dialect](CAP-227.md)),
as a dialect defines a kind of its own where a shape differs.

A literal is a domain representation ([PRI-023: domain representations](../PRINCIPLES.md#PRI-023)), carrying three
things at once: `text`, its source spelling, unvalidated, filled by a parser and kept where it does not parse
(`0x10`, `r'\n'`, `8'hFF`); `problems`, a validation indicator for each possible error (an invalid digit, a value out
of range, an unterminated string); and `value`, the encoded value, any value as above, absent where the text is
invalid. A dialect's literal adds the other properties its text encodes: a base, digit separators, a string's prefix
and quotes, C's `u` and `f` suffixes (kept until [CAP-232: domains inferred for terms](CAP-232.md) gives them meaning).
A literal written in code has a `value` and no `text`, and a printer writes a default spelling. Whitespace and comments
between tokens are not a literal's.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **A literal holds any value** (2026-11-02, [the complete-dialects proposal](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#decided),
  Decided). Told that "the five basic scalars" was the agent's gloss of "yes restrict `literal` to scalars"
  (2026-10-30), the user: "I don't think that rule about "literal is restricted to the five basic scalars" is useful.
  May have been a hallucination or exaggeration." To the recommendation (an unrestricted `literal`, and a `Python3`
  constant kind for `None`, `...` and complex numbers): "Yes. This merits its own CAP item too". It supersedes the
  restriction to scalars ([CAP-097: value domains of published standards](CAP-097.md#decided), Decided).
- **A literal is a domain representation** (2026-11-02): asked whether a literal keeps its spelling beside its value,
  the user: "See PRI-023"; to the reading above (`text`, `problems`, `value`): "it does".

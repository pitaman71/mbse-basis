# CAP-310: a cache layer's partial-aware interpretation

*Implements* [FEA-028: one Store interface, lazy by default](../features/FEA-028.md).

A cache layer, a store over another, forwards a mutation transaction to the layer below and at once interprets it
recursively over what it holds, given the original expression, a handle to the subterm it evaluates, and, for each
symbol that should be bound there, a stream of candidates. A frame it binds fully it streams to the client at once;
where the layer below streams back a frame with the same symbol bindings that conflicts with one given, as in a
property's value, the cache takes the layer below's and gives the client that frame, which replaces the one given
before. It is part of
[the stacked stores proposal](../../proposals/STACKED-STORES.md#stacking-by-mutation-transactions); forwarding to a
layer below is [CAP-308: stacking by mutation transactions, in one round trip](README.md#CAP-308)'s.

## Decided

The user's decisions (2026-11-16):

- **A cache layer may write speculatively** (superseded, 2026-11-18: a cache layer reads its cache only and writes
  through, [the stacked stores proposal](../../proposals/STACKED-STORES.md#a-cache-layer-and-the-layer-below)): "writing speculatively is feasible because the lower-layer write will
  come back and if it has a different result the frame can be sent again". A cache layer interprets a transaction's
  writing terms as well as its reading ones over what it holds; what the layer below commits comes back as frames, and
  where they differ, the cache takes the layer below's and gives the client the frame again; where the layer below
  refuses the transaction, what the cache wrote of it is undone.
- **Deletion below is retraction** (moot while a cache layer gives no frame before the layer below's comes back): "yes, deletion below is retraction". A frame a cache layer gave early whose object
  the layer below deleted, or no longer binds, is retracted.
- **Streams**: "Python generator and Typescript observable".

## Decided by an agent, for review

- **A retraction is a frame given again.** (Superseded, as the speculative write is.) As a frame with the same symbol bindings given again replaces the one given
  before, a retraction is that frame given again, marked retracted: one rule for a client, which replaces each frame by
  its latest arrival and drops one retracted.
- **An observable of the framework's own.** mbse-schemas' TypeScript core runs without Node and depends on no package,
  so its observable is a minimal one of its own, `subscribe` with `next`, `error` and `complete` giving back what ends
  it, shaped to interoperate with the ECMAScript Observable proposal and RxJS, rather than a dependency.

# CAP-070: wire format shorthand (containers)

*Implements* [FEA-006: persistence](../features/README.md#FEA-006), [FEA-032: schema loading and wire alignment](../features/FEA-032.md). Index entry: [capabilities/README.md](README.md#CAP-070).

## As built: mbse-schemas

Met in mbse-schemas 0.26.3, with [CAP-069: wire format shorthand (scalars)](CAP-069.md#as-built-mbse-schemas), which holds the wire form of every kind and the reader's rules; checked in the code of both languages. For a container, the user's example omits the schema level, `{"container": [...]}`: that form is written where the restriction leaves one container schema, and where it holds several, the schema is wrapped too, `{"container": {"Tags": [...]}}`.

| Kind | Wrapped | Bare, the shorthand |
|---|---|---|
| a container, the restriction's one container schema | `{"container": ["dog", "cat"]}` | `["dog", "cat"]` |
| a container, one of several | `{"container": {"Tags": ["dog", "cat"]}}` | `["dog", "cat"]` |

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- The rule is [CAP-069: wire format shorthand (scalars)](CAP-069.md#decided)'s, "A restricted `OfAny` never guesses its schema", point 4.

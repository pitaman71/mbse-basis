# CAP-113: parameters bound at their definitions

*Implements* [FEA-033: model parameters](../features/FEA-033.md).

## Design

Not built. `Parametrics.BindsValue` and `BindsObject` are defined ([CAP-112: parameters modeled as schema data](CAP-112.md)), but no kind has an adjacency to either, so nothing binds a parameter: an extension's adjacency is to a relation of two links and no properties ([CAP-117: extension adjacencies to any relation](CAP-117.md)), and the parameter bindings' adjacencies were dropped (Open questions).

## Open questions

### The parameter bindings' adjacencies

*Settled*: **the parameter bindings' adjacencies, `values` and `objects`, go**, as the user decided: "lines 30 and 31 of docs/PARAMETRICS.md are no longer needed since `Parametrics.OfParameters` was introduced": a kind's one extension
adjacency is `parameters`. Stopped on before that, for a decision: the extension
mechanism refuses them: an adjacency an extension adds to a meta-schema is to a relation of two links and no
properties (Schema extension, Decided, 18 in [CAP-116: framework schemas extended, checked](CAP-116.md#decided), as built, and 22: "yes that's a compromise"), and `BindsValue` has an
entry property and `BindsObject` three links (Decided, 3), so the draft's install raises `TypeError: an extension's
adjacency 'values' is to a relation of two links and no properties, got 'Parametrics.BindsValue'`. `BindsValue` and
`BindsObject` are defined; no kind has `values` or `objects`. The choices: (a) extend the mechanism, so that a
builder's member of an extension's adjacency holds entries with their properties and links, as a proxy's adjacency
does (`o.values(lambda a: a.insert(lambda e: e.param([n]).value(3)))`), revising Schema extension, Decided, 18 in [CAP-116: framework schemas extended, checked](CAP-116.md#decided) and
22; (b) parameter bindings as objects linked by relations of two links, as formals are (Schema extension, Decided, 22 in [FEA-024: expressions as data](../features/FEA-024.md#decided)); (c)
leave parameter bindings unbuilt until something binds (Store overhaul, Decided, 12 and 28).

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(parametrics 3)** **Parameter bindings**, "yes": `BindsObject`'s `obj_ref` is a third link, `BindsValue`'s `value` an entry property.
- **A schema declares, its data binds**: "Schemas may hold parameter declarations. Parameter bindings should be held by
  the data object governed by that schema." A data object may bind its schema's parameters, and need not. [CAP-314:
  parameters bound by the data objects their schema governs](README.md#CAP-314) supersedes this capability, which bound
  a parameter at its schema.

## Decided by an agent, for review

Recorded in mbse-schemas' design, not marked as the user's: each *proposed* until reviewed.

### The framework design's Parametrics

From the framework design's Parametrics, Decided, where it was not marked as the user's:

- **No defaults.** A parameter given no argument stays unbound.
- **At a reference**, named arguments (positional ones went: `OfApply` binds by name only, Resolved), partial parameter binding, arguments that depend on the referring
  element's own parameters, and equality after substitution, each to the extent possible.

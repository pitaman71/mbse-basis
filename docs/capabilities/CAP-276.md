# CAP-276: Python's type expressions and match patterns as data

*Implements* [FEA-024: expressions as data](../features/FEA-024.md), [FEA-008: expressive program models](../features/FEA-008.md). *Relates to* [CAP-227: the Python3 expression dialect](CAP-227.md), [CAP-226: complete expression dialects](CAP-226.md), [CAP-268: standards as tagged data](CAP-268.md).

## As built: mbse-expressions

Built in mbse-expressions' retrofit of [the complete dialects](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#stages-proposed-once-decided) (its *Retrofit's design*, Python), for 0.10.0, in
both languages, by the decisions of stage 6 that a sublanguage its standard defines is a dialect, referenced from its
host's unions, with a holder of its own ([CAP-226: complete expression dialects](CAP-226.md#decided)). The choices made
where the design was silent are [the port's API, Settled in the retrofit](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-the-retrofit-for-the-users-review), items 225 to 235.

- **`Python Types`** (`Expressions.Python.Types`, tag `python_types`): the typing specification's type expressions and
  the Language Reference's type parameter lists (8.11); its `Term` lists every branch of Python3's, as an annotation, a
  bound or a default may be any expression, then mbse-programs' type parameters, `typevar`, `paramspec` and
  `typevartuple`; a parameter's `annotation` holds it, and mbse-programs' annotations, return types and type
  parameter lists hold it through its holder. A type parameter binds nothing a term scopes.
- **`Python Patterns`** (`Expressions.Python.Patterns`, tag `python_patterns`): a `match` statement's patterns
  (8.6.4), mbse-programs' eight kinds, `matchmapping` and `matchclass` each holding two lists; a pattern binds its
  capture names through the `case` that holds it (`bound_names`).
- **Each** reads Python3's terms and is read by it, records the versions of Python that have its kinds (3.0 to 3.15
  and 3.10 to 3.15, as data), prints through the family's printer, is checked complete against `ast`'s nodes kept as
  data (DIA-20), and is refused by evaluation by its own name ("Python Types typevar is not evaluated").
- **Tests**: the suites PYT and PYP, nine cases each; FRM-01, FRM-02, FRM-13 and DIA-20; the corpus cases
  `python_types` and `python_patterns`, byte-identical in both languages.

## Decided by an agent, for review

Recorded in [the port's API, Settled in the retrofit](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-the-retrofit-for-the-users-review), not marked as the user's: each *proposed* until reviewed.

- **(mbse-expressions, retrofit, API 225)** Python Types' `Term` lists Python3's branches first, then its own kinds.
- **(mbse-expressions, retrofit, API 226, 227)** An as pattern with a pattern needs a name; `bound_names` exported; no
  pattern kind refines `Let`.
- **(mbse-expressions, retrofit, API 228)** Each dialect's editions list its own kinds only.
- **(mbse-expressions, retrofit, API 229, 230)** Printing through Python3's printer, a pattern's precedence on the
  family's scale; no writers, terms written through the builders.

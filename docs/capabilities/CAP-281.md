# CAP-281: Python's, ECMAScript's and C++'s regular expressions as data

*Implements* [FEA-024: expressions as data](../features/FEA-024.md), [FEA-008: expressive program models](../features/FEA-008.md). *Relates to* [CAP-226: complete expression dialects](CAP-226.md), [CAP-227: the Python3 expression dialect](CAP-227.md), [CAP-228: the TypeScript5 expression dialect](CAP-228.md), [CAP-230: the C++ expression dialect](CAP-230.md), [CAP-268: standards as tagged data](CAP-268.md).

## As built: mbse-expressions

Built in mbse-expressions' retrofit of [the complete dialects](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#stages-proposed-once-decided) (its *Retrofit's design*, the regular
expressions, and *Cpp RegExp*), for 0.10.0, in both languages, as the user answered which regular expressions are
dialects ([CAP-226: complete expression dialects](CAP-226.md#decided), "Which regular expressions are dialects"):
every one a language's standard defines, its library's included, each built as stage 6 built a sublanguage. The
choices made where the design was silent are [the port's API, Settled in the regular expression dialects](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-the-regular-expression-dialects-for-the-users-review), items 271 to
310.

- **`Python RegExp`** (`Expressions.Python.RegExp`, tag `python_regexp`): the syntax of Python's `re` (the Library
  Reference, "Regular Expression Syntax"), Python 3.0 to 3.15, its own `conditional`, `atomicgroup` (3.11), inline
  `flags` and `comment` beside the constructs ECMAScript shares; checked with `re`'s parser's messages, and complete
  against the codes `re`'s parser writes, kept as data.
- **`TypeScript RegExp`** (`Expressions.TypeScript.RegExp`, tag `typescript_regexp`): ECMA-262's pattern grammar,
  regexpp's node types as kinds, the 5.1 Edition to the 17th (ES2026), the `v` flag's classes from the 15th and
  modifiers from the 16th; a regular expression literal, TypeScript5's `constant`, holds it as its `regexp`, beside
  its spelling.
- **`Cpp RegExp`** (`Expressions.Cpp.RegExp`, tag `cpp_regexp`): the regular expressions `std::regex` reads
  (ISO/IEC 14882, [re.grammar], [re.synopt]), one dialect for its six grammars, ECMAScript's (ECMA-262's third
  edition, as [re.grammar] modifies it), POSIX's basic and extended, awk's, grep's and egrep's, a regex naming its
  grammar among its flags, what each grammar has checked by validation; C++17 to C++23.
- **Each** names the constructs ECMAScript has as regexpp, ECMAScript's reference parser, names them (`setKind`,
  `assertionKind`, `raw`, `ref`), each family its own copy; is read by its family's other dialects and reads theirs;
  binds nothing a term scopes, a named group's name being a label; records its editions as data; prints through a
  printer of its family or its own; is checked complete against its grammar kept as data; and is refused by evaluation
  by its own name ("Python RegExp pattern is not evaluated"). No Python or C++ position holds one: a pattern is a
  string there, never guessed to be a regular expression
  ([PRI-025: never guess the schema](../PRINCIPLES.md#PRI-025)), held through its dialect's holder.
- **Tests**: the suites PYR (nine cases), TSR (seven) and XRX (ten); FRM-01, FRM-02, FRM-11 and FRM-13; the corpus
  cases `python_regexp`, `typescript_regexp` and `cpp_regexp`, byte-identical in both languages.

## Open questions

- **`Cpp RegExp`: one dialect for the six grammars**, the grammar an element of a regex's flags, as one
  `std::basic_regex` reads them all ([re.synopt]), against a kind per grammar where they differ, or a POSIX dialect
  beside an ECMAScript one. Built as one dialect, as recommended (API 293), for the user to confirm.

## Decided

The user's answers are recorded in [CAP-226: complete expression dialects](CAP-226.md#decided), "Which regular

## Decided by an agent, for review

Recorded in [the port's API, Settled in the regular expression dialects](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-the-regular-expression-dialects-for-the-users-review), not marked as the user's: each *proposed* until reviewed.

- **(mbse-expressions, regexp, API 293 to 295)** `Cpp RegExp` is one dialect for the six grammars, a regex keeping its
  flags as written; what each kind's terms may be (`HOLDS`) and what each grammar has (`FEATURES`) are checked by
  validation; a term held without a regex is read as ECMAScript's.
- **(mbse-expressions, regexp, API 271, 283, 294)** Each dialect's kinds: Python's design's and a `comment`;
  regexpp's node types, `Flags` and `ModifierFlags` helpers; the shared constructs once, with [re.grammar]'s class
  atoms and grep's list of patterns.
- **(mbse-expressions, regexp, API 302)** The three name ECMAScript's constructs as regexpp does: a character set's
  `setKind`, an assertion's `assertionKind` (regexpp's `kind`, the framework's word), a spelling's `raw`, a
  backreference's `ref`, a number or a name; a Python conditional's group is its `ref` too.
- **(mbse-expressions, regexp, API 273, 285, 296)** A spelling, `raw`, kept where the tree does not give it: a
  character's beside its code point, and a quantifier's; regexpp's derived properties (a node's position, a group's
  references) not kept.
- **(mbse-expressions, regexp, API 278, 288, 297, 303)** Editions: Python 3.0 to 3.15; ECMA-262's 5.1 Edition to the
  17th, the 17th with the 16th's kinds, its pattern grammar unchanged; C++17 to C++23, every kind in each.
- **(mbse-expressions, regexp, API 277, 289, 304)** What reads what: each family's dialects read one another, `Cpp`
  and `Cpp Types` reading `Cpp RegExp` though no position of theirs holds one; TypeScript5's `constant` holds its
  `regexp`, validated with it, not checked against its spelling.
- **(mbse-expressions, regexp, API 275, 276, 287, 290, 298)** Checks with each parser's messages where it has one; one
  printing layout each, `Cpp RegExp`'s printer its own, as its grammar is the context it writes in.
- **(mbse-expressions, regexp, API 279, 291, 300)** Completeness data: `re`'s codes, 3.0 to 3.15; regexpp 4.12.3's node
  types; [re.grammar]'s and POSIX's productions.
- **(mbse-expressions, regexp, API 305 to 307)** The three installed last, in the merge's order, the tutorials' toolkit
  installing them; their corpus cases after the retrofit's; suite TSR's cells reordered, each heading before its code.

# CAP-075: steps linked to what they matched and wrote

*Implements* [FEA-021: every generation ambiguity a parameter](../features/FEA-021.md), [FEA-017: AI in the loop via the model trace](../features/README.md#FEA-017), [FEA-018: humans in the loop via the model trace](../features/README.md#FEA-018).

Every application of a transform ([CAP-074: transforms applied step by step](CAP-074.md)) is certified, at three
levels: a history certificate records the sequence of transforms; a transform certificate records one application and
its parameters; and a sub-certificate for each frame the application took (the source, the sync and the target,
whichever are present) links that frame and the preceding transform for that pattern on the same history. The frames
bind what an application matched and what it wrote, so the sub-certificates link every step to them. This is what mbse-transforms' first release builds
([its first-release proposal](https://github.com/pitaman71/mbse-transforms/blob/main/docs/proposals/first-release/README.md)).

## Design

What the user decided is stated under Decided, below; the rest is mbse-transforms' first-release proposal, each part
*proposed* until reviewed (Decided by an agent, for review).

- **The certificates are schema data**, installed by `install(txn)`. The history certificate is a singleton's or an
  owner's, and every certificate is owned under it, so that each certificate has an object reference
  ([CAP-315: every read within a transaction or through a follow](CAP-315.md)).
- **An application writes its certificates**: once the procedure has run and been verified where asked, the application
  writes the transform certificate, linked to the transform's prototype, to the history certificate and to the
  previous transform certificate in the history, and one sub-certificate for each frame present, linked to the previous
  certificate on that frame's chain.
- **A sub-certificate holds its frame as a value**, a `References.OfFrame`
  ([CAP-130: references to objects, entries and frames](CAP-130.md)), which maps each of the frame's symbols to the
  object reference of the element it binds. The certificates are queried in the one store that holds them, as any
  data, with no store combined with another; an element that a sub-certificate links is reached by resolving its object
  reference in the store that holds the element.

## As built: mbse-patterns

mbse-patterns 0.9 to 0.9.1 linked each step to the elements it matched and wrote, each in a role, by the relations
`Transforms.Matched` and `Transforms.Wrote`, and queried the steps with those elements by combining the steps' store
with the session's (`Stores.Combined`), which mbse-schemas no longer allows
([the store overhaul](https://github.com/pitaman71/mbse-schemas/blob/main/docs/proposals/store-overhaul/README.md#decided-here),
Decided, 18: no store reaches another's objects). That precursor is the design input of mbse-transforms, not code to
port. It is retired: mbse-patterns 0.10.0, its fresh start, removes its code.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **Three levels of certificates** "form a complete audit history for transforms"
  ([the first-release proposal](https://github.com/pitaman71/mbse-transforms/blob/main/docs/proposals/first-release/README.md#the-transform-model-as-the-user-decided)):
  - a **history certificate**, "which records a sequence of transforms";
  - a **transform certificate**, "which records the application, linked to the transform's prototype, the history
    certificate, and prev/next transforms in the history"; it records the transform's parameters ("ofc those parameters
    must be recorded in the transform certificate");
  - **sub-certificates**, one "for the source, sync, and target (whichever are present)", each linking "to the
    corresponding pattern instance and to the preceding transform for that pattern on the same history".
- **A pattern instance is a frame**: "a pattern instance is a frame". A sub-certificate's pattern instance is the frame
  that the application took.
- **Provenance is the history certificate's**: "the history certificate can capture provenance"
  ([CAP-076: reruns reuse decisions](CAP-076.md#decided), Decided).
- **Python first**, as for all of mbse-transforms' first release
  ([CAP-074: transforms applied step by step](CAP-074.md#decided), Decided).

## Decided by an agent, for review

Each is *proposed* until reviewed.

- **(mbse-transforms 3)** **The design above** where the user's decisions leave it open: the certificates' ownership
  under the history certificate, and a sub-certificate holding its frame as a `References.OfFrame` value, so that the
  certificates are queried in one store and no store reaches another's objects.

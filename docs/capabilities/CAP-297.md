# CAP-297: simplification in every binding state

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Applies* [PRI-046: simplification, not evaluation](../PRINCIPLES.md#PRI-046). *Relates to* [CAP-099: partial evaluation](CAP-099.md), [CAP-106: expressions evaluated three-valued](CAP-106.md).

## As built: mbse-expressions

Built in mbse-expressions 0.11.0 (unreleased): the framework's one procedure, `Framework.Simplifiers` (#48), simplifies
an expression of any dialect fully bound, to a literal, partially bound, to a residual of the same dialect, and
unbound, to itself or simpler, each family's rules folding what they can ([CAP-295: simplification of single-dialect
expressions with literal leaves](CAP-295.md)). Integrating the families (#54) settled where an error a subterm's
folding raises goes, so that a partial binding never raises where the language would not: an error raises wherever
the language evaluates the subterm, and a subterm it may never evaluate (an untaken branch, a short circuit's right
operand, a lambda's body, `sizeof`'s operand) stays in the residual, to raise where it is evaluated. Each dialect names
those positions; the detail is [the port's API](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-simplification-for-the-users-review),
items 374 and 375.

## Decided by an agent, for review

- **(mbse-expressions 54, integration, API 374)** **Guarded subterms**: API 328's "raises, as the expression would in
  its language" read exactly. A subterm the language may never evaluate is guarded: a body its parent binds names in,
  but a let's, and the arguments a dialect's `guarded(node, index)` names (conditionals' branches, short circuits'
  right operands, lambdas' and arrows' bodies, `sizeof`'s, `alignof`'s and `_Generic`'s operands, C++'s `noexcept`'s
  and `typeid`'s, Excel's `IF`'s branches). An error folding it leaves it in the residual, naming no residue; anywhere
  else an error raises (`x + (1 + "a")` in Patterns), by default: whether such an error stays instead is an option,
  [CAP-305: simplification's options, chosen up front](CAP-305.md). Before, an untaken branch raised (`c ? 1 : null.a`
  with `c` unbound).
- **(mbse-expressions 54, integration, API 375)** **A known `undefined`**: TypeScript's simplifier wrote a known
  `undefined` as `null`, a parameter's default applying to it; it is `undefined` now, as in Python.

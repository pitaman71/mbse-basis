# CAP-258: a dialect's stored operations read once per validation

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Relates to* [CAP-098: dialects over one framework](CAP-098.md).

## Design

Not built. This capability is tech debt, incurred by mbse-expressions' domains as data, stage 2, which made a
dialect's operations data that validation reads (`Kind.operations`). Validation re-reads every
`Expressions.Framework.Operates` entry of a dialect, and recomputes each operation's arity, for every call node it
checks (`Framework/Terms.py` and `Terms.ts`, the `kind.operations` block, checked in mbse-expressions' main at
3711f8a), so its cost grows with nodes times operations. Met when the operations are read once per store for one
`validate` run, as a cache, with the same problems reported.

## Decided

- **Logged as tech debt** (2026-11-10): as the user decided, "Tech debt is capability codes, not notes in markdown",
  and "I don't know why you would expect a single feature to contain all tech debt items"; approving ("yes") that each
  debt be a capability of the feature whose work caused it, relating to [QUA-014: precise typing for bespoke and generated source code](../QUALITIES.md#QUA-014) where it concerns typing, and
  that a debt an existing capability already covers be linked to it rather than made a capability of its own.

# CAP-253: counted objects (serialization)

*Implements* [FEA-026: deterministic object identity](../features/FEA-026.md). *Relates to* [CAP-133: no durable references to counted objects](CAP-133.md), [FEA-003: no-code logical views](../features/FEA-003.md), [CAP-010: object browser](CAP-010.md), [CAP-011: relation browser](CAP-011.md).

## Design

Not built: counted objects do not survive transit between backend and frontend. A counted object has no reference
([CAP-130: references to objects, entries and frames](CAP-130.md)), so what is serialized by reference leaves it out:
the no-code views neither record nor transmit one (a frame that binds one is left out of the stream, and an entry
that links one out of `entries`), and the object and relation browsers leave out such objects and entries. This capability is that tech debt: counted objects serialized where today they are
left out.

## Decided

- **Logged as a capability of [FEA-026: deterministic object identity](../features/FEA-026.md)** (2026-11-06): "Let's log a CAP for
  "counted objects (serialization)". I'm not sure it blocks anything." It drains the tech-debt notes in
  [FEA-003: no-code logical views](../features/FEA-003.md), [CAP-010: object browser](CAP-010.md) and [CAP-011: relation browser](CAP-011.md), and the capabilities index's open item on
  the visualization capabilities.
- **What it blocks** (2026-11-06): correcting the open question this capability was first logged with, the user said: "you already told me that counted objects do not survive transit between backend and frontend". Any model
  whose views hold counted objects loses them between backend and frontend until this is met.
- **Part of [INI-040: diagrams framework](../../proposals/PRIORITIES.md#ini-040--diagrams-framework)** (2026-11-06): "CAP-253 needs to be part of INI-040 per your
  observation", the observation that counted objects do not survive transit between backend and frontend. It comes
  before [CAP-243: a diagram displayed from its mutation stream](README.md#CAP-243). Superseded on 2026-11-10, below.
- **Not part of INI-040** (2026-11-10): "Drop that ordering from INI-040". The diagram framework uses no counted
  objects: every diagram element is owned, through `Logical.Owns`, and its values are value objects; and counted
  objects are being deprecated. It is at the bottom of the priorities, among what comes later: "put CAP-253 at the
  bottom of the priorities list now".

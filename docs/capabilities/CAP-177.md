# CAP-177: sessions and identities from a validated token

*Implements* [FEA-007: property kinds](../features/FEA-007.md). Index entry: [capabilities/README.md](README.md#CAP-177). *Relates to* [CAP-015: transaction provenance](CAP-015.md), [CAP-191: private tenancy, behind login with sessions](CAP-191.md).

## As built: mbse-rest

Not met. The demo's stand-ins ([CAP-015: transaction provenance](CAP-015.md#provenance), as built): the service's identity is configured
(`MBSE_REST_USER`, `demo` by default), and the session is whatever the client names in the `x-mbse-session`
header, trusted.

## Design

The service unpacks and checks a validated token, and writes the session and identity it gives into each transaction
that writes, before executing and journaling it; the token itself is never recorded ([CAP-134: transactions recorded with provenance](CAP-134.md#decided),
provenance 6).

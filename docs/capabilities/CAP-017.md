# CAP-017: object inspector

*Implements* [FEA-005: inspector views](../features/FEA-005.md). Index entry:
[capabilities/README.md](README.md#CAP-017).

Status: complete (mbse-react, M3; editing added by [CAP-014: properties as markdown](CAP-014.md)).

A single object inspector is anchored by the object's schema and the
object's ID.

In any view, a standard UI gesture (defaulting to a click or tap) on any view of an object causes a shared inspector panel to:

- reveal if currently hidden in its standard location
- clear contents and show loading
- navigate to that object; inspector state is kept in no history, the
  browser's or its own
- fetch the logical detail view from the backend
- display the detail view in the inspector panel
- ensure that label remains at the top
- if the detail panel has action buttons, they remain 
  at the bottom while other properties and adjacencies auto-scroll
  in between

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-react 10)** **The schema of an object** is known where the UI asked for it (a chip of a schema's extent,
  [CAP-008: adjacency as a list of chips](CAP-008.md)'s `y`) or where exactly one schema fills the entry link it was
  reached through. Otherwise it is unknown: its label falls back to its path's last key alone, and the inspector lists
  its entries by relation instead of by adjacency (no [CAP-008: adjacency as a list of chips](CAP-008.md)). mbse-schemas
  finds a reference's schema from its path (`References._implied`), but privately; see the report.
- **(mbse-react 11)** **The inspector's properties** are those besides its label's and its summary's (`Views.chip` over
  the detail frame), since the label is pinned at the top and the summary shown under it.
- **(mbse-react 12)** **The inspector keeps no history** (revised twice: it was the browser's, then its own). The
  address bar's hash holds the view alone; switching views replaces its entry. Inspecting an object replaces what the
  inspector shows; closing it clears it. Going up the ownership path is the breadcrumb's (mbse-react 34); going along an
  adjacency, its pill's. An inspected object is neither in a shared link nor kept over a reload.
- **(mbse-react 13)** **The inspector's actions** are in its footer ([FEA-005: inspector
  views](../features/FEA-005.md)), centered side by side: Edit and Close, as icon buttons (a pencil, a cross; each named
  and with a tooltip), or, while editing, Cancel, Save and Close, Close disabled while saving. The footer's start and
  end hold a relation inspector's arrows (mbse-react 35). The header holds the label, the breadcrumb and the byline, no
  button.

# CAP-023: relation inspector

*Implements* [FEA-005: inspector views](../features/FEA-005.md). Index entry:
[capabilities/README.md](README.md#CAP-023).

An object navigator: the object inspector ([CAP-017: object inspector](CAP-017.md)) of one object among
its siblings, stepping to the previous or next sibling.

The relation inspector is anchored by:

- an object
- a relation that holds the object (an entry of it links the object)
- bindings for the relation's other links, and property values on the
  same relation, that define the sibling context

The sibling context is every object linked, through the same link as the
anchoring object, by the relation's entries that agree with the bindings,
ordered as an adjacency list orders them ([CAP-021: lists ordered by creation](CAP-021.md)).

- inspecting an object from an adjacency list ([CAP-019: adjacencies at the end of a detail](CAP-019.md)) opens a relation
  inspector: the adjacency's relation, the inspected object's link, and
  the adjacency's own link bound to the object whose list it is
- inspecting an owned object from the schema browser ([CAP-009: schema browser](CAP-009.md)) opens a
  relation inspector: its ownership relation, the object's link, and the
  other link bound to its owner
- inspecting an object from the object browser ([CAP-010: object browser](CAP-010.md)) opens a relation
  inspector: its directory's relation, the object's link, and the other
  link bound to the directory's singleton
- inspecting an object anywhere else opens a single object inspector
- where a previous or next sibling exists, arrow icon buttons step to it,
  left and right justified in the inspector's footer; neither is kept in
  any history

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-react 35)** **The relation inspector**: a target carries an
  optional anchor, `{ relation, link, links, properties }`: the relation holding the object, the link it fills, and
  bindings for other links (each an object's key and schema) and for property values. A pill in an adjacency list
  anchors its object: the adjacency's relation, the link the object fills in the entry, and the adjacency's own link
  bound to the list's owner, no property values. On the Schemas tab ([CAP-009: schema browser](CAP-009.md)), an owned
  object's chip anchors at its ownership relation: the link it fills, and the other bound to its owner (the last step
  before it on its ownership path), so the arrows step along its row. On the Objects tab ([CAP-010: object
  browser](CAP-010.md)), a chip anchors as a pill in its directory's list does (the directory's relation, its own link
  bound to the singleton). A singleton's chip, the Relations tab's chips and a crumb open a single object inspector. The
  siblings are read through [CAP-008: adjacency as a list of chips](CAP-008.md) from the first bound link whose object's
  schema names an adjacency to the relation through it (the views the adjacency list already read, kept by `Service`),
  its entries matched against the other link and property bindings, each object once, in [CAP-021: lists ordered by
  creation](CAP-021.md)'s order; none where no bound link has such an adjacency (a service view of a relation's entries
  under arbitrary bindings would lift that; not built). The footer shows "Previous in {relation}" and "Next in
  {relation}" as arrow icon buttons, at its start and end, only where that sibling exists and only out of editing;
  stepping keeps the anchor and no history.

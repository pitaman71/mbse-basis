# CAP-205: anonymous adjacencies, a link filled without storage on the object

*Implements* [FEA-035: clean modeling separation between value objects and reference objects](../features/FEA-035.md). Index entry: [capabilities/README.md](README.md#CAP-205).

## As built: mbse-schemas

Met since before mbse-schemas 0.20.0, the first tag after it was built, and checked in the code at 0.26.4. An adjacency is either named, by the entry that links it to its object schema, or anonymous, with no name. An anonymous adjacency declares a link the object may fill, so validation checks it, but it adds no member and holds nothing. Modules write it with no name.

Without it, an object could fill a link only through a named adjacency, a member it may not need. The meta-schemas use anonymous adjacencies at the ends where a schema is referred to ([CAP-109: schemas as linked objects in modules](CAP-109.md)). So does `Provenance`, for an object's adjacencies to its records, which [CAP-178: an object's provenance read through its own named adjacencies](CAP-178.md) replaces with named ones.

## Decided

As the user wrote it, in the workspace's former TODO.md: "It is permissible for a Schemas.OfObject to declare an adjacency without naming it. In this case, it denotes the relation has no storage on the object. It merely denotes that this object may participate in a particular link `me` of the designated relation."

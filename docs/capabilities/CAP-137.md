# CAP-137: patterns of symbols, variables and specs

*Implements* [FEA-027: mutations as queries](../features/FEA-027.md). Index entry: [capabilities/README.md](README.md#CAP-137).

## As built: mbse-schemas

Met in mbse-schemas 0.22.0: the [store overhaul](../../../mbse-schemas/docs/proposals/store-overhaul/README.md)'s 4d, patterns, released as 0.21.0, and a pattern's `spec`, built in 4e and released as 0.22.0.

### No expression dialects in mbse-schemas

- mbse-schemas has no knowledge of expression dialects: what a predicate requires of a match, its constraint, is
  mbse-patterns' and mbse-expressions' (docs/proposals/store-overhaul, Decided, 20).

### Patterns : symbols, variables, boundary constraints

`Schemas.OfPattern` comprises three things:
- a list of symbol declarations (as `Schemas.OfSymbol`) which in an instance will be "bound" to a reference object 
- a list of variable declarations (as `Schemas.OfVariable`) which in an instance will be "assigned" to a schema-governed value 
- zero or more fused constraint expressions (as `Schemas.OfConstraint`) over symbol visitors and variable visitors

`Schemas.OfSymbol` declares one symbol:
- must provide a symbol name
- may provide `schema`: reference object schema for that symbol (`schema: Schemas.OfObject`)
- may provide `schema`'s singleton: a symbol whose schema is a singleton's binds it
In some contexts, `schema` may be optional or mandatory.

`Schemas.OfVariable` declares one variable: 
- must provide a variable name
- may provide `schema` : value schema for that variable (`schema: Schemas.OfAny`)

- `Schemas.OfPattern.requires`: constraint expressions (`Schemas.OfConstraint`) over a frame

### Spec

A pattern's `spec` says what must hold of a frame: property values the symbols' objects have, and relation entries that
link them, written in the builders' notation over the frame's symbols, `lambda _: _.bob.name("Bob").knows([_.ada])`. In
a match it filters; in an upsert it is written where it does not hold. It replaces locators; a symbol whose schema is a
singleton's binds that singleton (Object identity, Decided, 76 to 78 in [CAP-124: writes all-or-nothing in transactions](CAP-124.md#decided)). A symbol may be given a
reference in place of a schema, `.symbols({"ada": reference})`: it binds the one object the reference designates, or
none where the store holds none, and its spec writes the members of that object's schema
(References, Decided, 8 in [CAP-141: queries start from a referenced object](CAP-141.md#decided)).

### Value Expressions and Constraints

`Schemas.OfExpression` is used to define the shape of an expression in terms of:
- a pattern (as Schemas.OfPattern)
- `symbols` defined by the pattern are considered free
- `variables` defined by the pattern are considered free
- `requires` defined by the pattern qualify frames as legal/illegal
- a result schema governing the result value computed when the expression is evaluated (as Schemas.OfAny)
- the root term of an expression, which expects a single frame argument

The `Schemas.OfPattern` defines the shape of frames it expects in terms of free variables and free symbols. The syntax of the expression root expects a single argument frame. This frame must map each symbol (of the pattern) to a read-only `Visitors.OfObject` and must map each variable (of the pattern) to a read-only `Visitors.OfAny`.

Expression dialects are not defined in `mbse-schemas`. Therefore
`mbse-schemas.Schemas.OfExpression` is a placeholder (for extension by `mbse-expressions`) that captures an expression. 
This refinement enables `Schemas.OfExpression` to represent value formulas, and so `Schemas.OfConstraint` boolean predicate formulas. Combine this with lambda notation and `Expressions.FromFunction`, and a very concise shorthand with little or no change to existing builder/visitor functionality should be feasible.

`Schemas.OfConstraint` is a variant of `Schemas.OfExpression` in which the result schema is `Schemas.OfBool`. It is used by Schemas.OfPattern to capture a fused (boolean) constraint over symbol/variable/property/value visitor expressions in a predicate-logic format. This constraint defines whether a particular frame matches or fails to match the pattern.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(object identity 62)** As the user decided (2026-10-19): A collector that declares neither `.commutative()` nor `.associative()`: "reject for now during validation", so a
  fold's result never depends on the order frames arrive in (57 in [CAP-144: transactions sharded and run in parallel](CAP-144.md#decided)).
- **(object identity 64)** As the user decided (2026-10-20), on how a pattern's symbol finds its objects, and on step 4d's shapes: A symbol's locator is "an ordinary schema" over three kinds: `Locators.OfSymbol` (name, next),
  `Locators.OfSingleton` (schema, next) and `Locators.OfRelation` (schema, the relation; adjacency, "name of adjacency
  to current obj"; link, "name of link to next obj"; properties, the entry's property values; next). "Only
  `Locators.OfSymbol` or `Locators.OfSingleton` may be used as the root of a locator expression"; each hop is
  reached by `next`, root first. "Locators target reference objects, not value objects. Locators can only traverse
  named adjacencies. Builder shorthand makes locators a path language." A locator is not an identity: it is a route a
  query follows, and may reach many objects, or a counted object, which has no path (55 in [CAP-118: singletons, owned and counted objects](CAP-118.md#decided)); "path" names identities
  only. This makes 60 in [CAP-139: upserts find before they create](CAP-139.md#decided)'s "symbol's locator" an `OfRelation` hop through the owning adjacency.
- **(object identity 65)** "cardinality is gone": a hop yields every object its entry's properties match, so a frame fans out where they
  leave the match open. A frame whose locator reaches nothing yields no frame, as for a constraint it cannot satisfy.
- **(object identity 66)** Step 4d's shapes ("yes"): `OfPattern`, `OfExpression` and `OfCollector` are schema kinds, named or not, defined in
  modules and written as every schema is; `OfVariable` is a member a pattern owns, as `OfSymbol` is; one kind,
  `OfExpression` (a pattern, through `Schemas.Matching`; a result schema; its terms mbse-expressions'), whose builder
  `Schemas.OfConstraint` fixes the result to the store's `OfBool`, validation refusing a pattern's `requires` of any
  other result; `requires`, the pattern's own constraints, in order (`Schemas.Requiring`); a collector's pattern,
  collected symbol and variable names, `commutative`, `associative`, `suffixes` (`current`, `next`) and `computes`
  (an `OfExpression`), validation refusing a name the pattern lacks and equal suffixes, and what a reduce requires of
  them left to 4e. 4d is schema-level only: frames, matching and the executor are 4e's.
- **(object identity 67)** As the user decided (2026-10-20), on the order of step 4 and on schema objects: `Schemas.OfPredicate` goes ("OfPredicate goes away, consider that decided"), in 4d: `OfPattern` replaces it.
- **(object identity 68)** "finish 4d then do 4g to stabilize Schemas early without complicating 4e and 4f": step 4 is done in the order 4d,
  4g, 4e, 4f, 4h.
- **(object identity 71)** `Locators.OfSymbol` has a name, the earlier symbol it starts from, and a schema, "Schemas.OfObject (must be ref)",
  by which a hop from it finds its adjacencies (amending 64).
- **(object identity 74)** A relation need not be declared as early as its first reference: "Locators.HasPath(symbol: Schemas.OfSymbol, root:
  Locators.OfRoot)", declared by Locators, links a pattern's symbol to its locator's root.
- **(object identity 76)** As the user decided (2026-10-20), on how a pattern's symbols find their objects: A pattern has a `spec`: "property values that must be assigned and relation entries that must exist for a frame to
  match the pattern"; "Schemas.OfPattern.spec completely replaces paths and locators" ("I think so"), superseding 64,
  65, 71, 74 and 75: `Locators`, `Locators.HasPath` and a symbol's `path` go. Each spec item is written in the
  builders' own notation, over the frame, whose members are the pattern's symbols, each the mutation builder of the
  object it binds (58 in [CAP-138: mutation expressions over frame streams](CAP-138.md#decided)): `lambda _: _.bob.name("Bob Massey").knows([_.ada]).directory([_.book])`. In a match, what a
  spec says must hold; in an upsert, it is written where it does not. A spec is stored as mutations, which "are
  serializable already". An owned object an upsert finds or creates is placed by its spec's owning entry, owner and
  keys, which gives its path (restating 60 in [CAP-139: upserts find before they create](CAP-139.md#decided)); paths remain owned objects' identities.
- **(object identity 77)** "singletons are denoted by their schema": a symbol whose schema is a singleton's binds that singleton, with no spec.
- **(object identity 95)** A spec ("yes"): `Schemas.OfPattern` gains `spec`, a `Mutations.OfPattern` value giving, for each symbol, the
  mutations of the object it binds (59 in [CAP-138: mutation expressions over frame streams](CAP-138.md#decided)), recorded by visitors of the symbols that write mutations rather than objects;
  `Mutations.OfAdjacency` inserts and removes entries, each through `Mutations.OfEntry`; and a reference may name a
  symbol, `{"symbol": "ada"}`, beside a path and a number. The log's verbs stay until 4f replaces the log.

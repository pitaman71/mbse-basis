# CAP-251: values of a refinement held where what it refines is declared

*Implements* [FEA-020: refinable models](../features/FEA-020.md). *Relates to* [CAP-167: schemas refined by other schemas](CAP-167.md), [CAP-153: unions and intersections of named branches and parts](CAP-153.md), [PRI-025: never guess the schema](../PRINCIPLES.md#PRI-025).

## As built: mbse-schemas

Met in mbse-schemas 0.26.10, checked in the code of both languages (`Proxies._refines`, `Plain`'s `$schema`) and by
SCH-27 and SCH-28.

"An instance of a refinement is an instance of what it refines" ([CAP-167: schemas refined by other schemas](CAP-167.md#decided)) held for reference objects, which fill a refined
schema's links (`Schemas.is_a`), but not for value objects: a property, a container's element or a union's branch
whose schema is a value object schema held a value of that schema only. mbse-expressions needs it, as the user decided
there (2026-11-05): "any expression kind that binds symbol(s) should be modeled as variations of `let`", each binding
kind refining the framework's `Let`, so that a term declared as `Let` holds a refinement of it.

- **Held.** A property, a container's element, a union's branch, an intersection's part and a value of any schema
  restricted to a value object schema each hold a value of that schema or of any refinement of it, directly or not
  (`Schemas.is_a`). A refinement's value is built standalone, through the store's builder of its registered name
  (`store.builder("D.Lambda")`), and given; a Spec builds the declared schema, as before. Read, it is itself: its
  schema, its own members and the members it inherits; updated in place, it stays of its schema. A container's index is
  held by its own schema only.
- **Written** with its own schema named, by a marker inside the value, only where its schema is not the declared one:
  `{"binder": {"$schema": "D.Lambda", "name": "f", "arity": 2}}`; the declared schema's own value is written bare, as
  before, so no corpus changed. `$schema` is one of the markers the wire keeps for itself (names starting with `$` are
  reserved), so it never collides with a property. In a restricted value of any schema, a refinement of one of its
  schemas is not one of them, so its value is always wrapped by its kind and its own name,
  `{"object": {"D.Comp": {...}}}`, never bare. A refinement with no registered name is refused when written: "a
  refinement's value is marked with its schema's registered name; its schema has none".
- **Read** by the schema declared where it is held, never by the shape of its data. A value object marked with
  `$schema` is read as the schema it names, which must be the declared schema or a refinement of it; anything else is
  refused, at the marker's path, with messages identical in both languages: "a value object's $schema is its schema's
  registered name, got int"; "no schema registered as 'Nope'"; "'D.Other' is not 'F.Let' or a refinement of it" (for a
  declared schema with no name, "is not the value object's schema or a refinement of it"); for an index, "an index is
  a value of its container's index schema, never marked with $schema". Unmarked, a value is the declared schema's, and
  a member that schema lacks is refused as before. A restricted value of any schema reads a refinement of one of its
  object schemas wrapped by its name, or bare and marked.
- **A flat union** takes the branch whose schema is the value's own; else the one branch whose schema it refines;
  where it refines the schemas of several, it is refused, never guessed: "property 'both': a value of D.Comp refines
  the schemas of several branches of the flat union, ['let', 'lambda']; write it through its branch". Validation of a
  flat union is unchanged: its branches are told apart by their own schemas.
- **Validated** by its own schema, as a root is (mbse-schemas 19 in [CAP-167: schemas refined by other schemas](CAP-167.md#decided-by-an-agent-for-review)): a member it narrows is checked as narrowed.
  **Compared** by its own schema: two value objects of different schemas are incomparable, so a refinement's value is
  not equal to its base's alike in its members.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(framework design)** **A refinement's value where what it refines is declared** (2026-11-05, mbse-schemas
  0.26.10). Asked five questions, each with options and a recommendation, the user accepted the recommendations: "yes,
  go".
  1. The wire form: a refinement's value is marked by `$schema` inside the value, `{"$schema": "P.Term2", ...}`, where
     its schema is not the declared one; the declared schema's value stays bare. Rejected: a one-level tag by
     registered name, `{"P.Term2": {...}}`, which a value object with one property of that name would collide with;
     and the restricted value of any schema's wrapper, `{"object": {"P.Term2": {...}}}`, heavier and colliding with a
     property named `object`.
  2. A flat union takes the branch of the value's exact schema if there is one, then the one branch whose schema the
     value refines, and otherwise refuses it; validation is unchanged, since reading names the branch.
  3. A restricted value of any schema accepts a refinement of one of its schemas, its existing wrapper naming the
     schema; a container's index does not.
  4. No new API: a refinement's value is built standalone and given.
  5. Recorded as a capability of its own, since a capability never grows ([the basis](../README.md#the-design-spec)).

## Decided by an agent, for review

Recorded in mbse-schemas' design, not marked as the user's: each *proposed* until reviewed.

- **(mbse-schemas 20)** An intersection's part is held as a union's branch is, by the same code, so it holds a
  refinement's value too, marked alike; `ToPlain(store)(schema, value)` and `FromPlain(store)(schema, plain)`, for a
  standalone value, take a refinement's value of `schema` as a property holding it would; `$schema` naming the declared
  schema itself is read as that schema's value; and a restricted value of any schema reads a refinement's value bare
  and marked as well as wrapped.
- **(mbse-schemas 21)** Tech debt, type specificity: in TypeScript, a value object's builder (`_RecordBuilder`) no
  longer holds its schema `readonly`: made for a union's branch or an intersection's part, it takes the schema of a
  refinement's value given to it, so its schema is mutable state, as Python's always was; it keeps the declared schema,
  `_declared`, to check what it is given. Restoring it means placing the given value in its owner rather than retyping
  the builder. Listed under the index's open items, to become a capability of a feature.

## Open questions

- **A restricted value of any schema, updated.** Found while building this, and in mbse-schemas before it: a property
  whose schema is a value of any schema restricted to two object schemas, holding a value of one, refuses, when an
  update gives it a value of the other, "property 'v' takes a value object or a Spec, got _RecordData"; written where
  nothing is held, the same value is taken. The value held fixes the schema a write may give (`_Any._of_any` returns
  early once a schema of the kind is chosen). Reported to the user, not worked around: whether an update may replace a
  value of one of its schemas with a value of another.

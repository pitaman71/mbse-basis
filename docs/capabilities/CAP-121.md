# CAP-121: owned objects deleted in cascade

*Implements* [FEA-026: deterministic object identity](../features/FEA-026.md). Index entry: [capabilities/README.md](README.md#CAP-121).

## As built: mbse-schemas

Met in mbse-schemas 0.20.0: the [store overhaul](../../../mbse-schemas/docs/proposals/store-overhaul/README.md)'s 4c, which carries out decision 48, released as 0.20.0.

### Deleting

Removing an owned object's owning entry deletes it, and in cascade everything it owns, within the transaction; a
counted object it linked lives on while anything else holds it (48).

## Open questions

### Deleting an object no entry owns

Deleting an object that no entry owns (designed, not built; tutorial 9) is deferred past step 4 of the [store overhaul](../../../mbse-schemas/docs/proposals/store-overhaul/README.md), as the user decided (2026-10-22): "4j : implement removing entries, but defer deleting objects to a later phase"; whether it is needed at all is open (its Decided, 27).

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(object identity 48)** As the user decided (2026-10-18), on the questions 41 to 47 left: Deleting an owned object ("correct"): removing its owning entry deletes it, and in cascade everything it owns,
  within the transaction; a counted object it linked lives on while anything else holds it.

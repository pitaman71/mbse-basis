# CAP-147: links validated against their schemas

*Implements* [FEA-034: analytic behavior conventions in schema](../features/FEA-034.md). Index entry: [capabilities/README.md](README.md#CAP-147).

## As built: mbse-schemas

Checked in the code of mbse-schemas 0.26.3 (origin/main), in both languages. A member is not linked into a second owner: the store refuses it as it is built, rather than validation, since a schema object with no name of its own "is linked by one schema object alone, and another links it already: name it to share it" (object identity 81 in [CAP-123: schema objects identified by path](CAP-123.md#decided)). Validation checks that a linked object's schema declares an adjacency, named or anonymous, to the relation through the link it fills (the VAL suites' VAL-04 and VAL-15), but not the schema its link declares: `Validators` reads no link's `schema`, which only the proxies and the executor consult, to choose which member takes a value given whole.

## Design

Not built. As the meta-schemas overhaul's V1 left it: "A link may have a schema, which `validate()` checks and modules write; `Validators` does not yet check a link's target against it" ([CAP-109: schemas as linked objects in modules](CAP-109.md#v1-schema-level-changes)). Validation would check a linked object against the schema its link declares, or one of its kind union's branches (object identity 97 in [CAP-109: schemas as linked objects in modules](CAP-109.md#decided)).

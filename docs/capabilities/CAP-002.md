# CAP-002: named schema list

*Implements* [FEA-003: no-code logical views](../features/FEA-003.md). Index entry:
[capabilities/README.md](README.md#CAP-002).

Backend has a designated endpoint which returns a list
of every named schema.

While [CAP-003: schema inspector](CAP-003.md) is blocked (mbse-schemas cannot yet write one schema object
as a document), it returns the store's whole schema snapshot instead, from
which the client's store takes every schema.

## As built

A client reads `GET /schemas` into its own store first (`Client.loadSchemas`, which executes it with
`Plain.FromPlain(store).Snapshot`): its store then holds every named schema, the framework's and the app's, and the
list of their names is the store's own (`schemaNames(store)`). Giving a template's symbol a schema, and reading a value
of a value object schema, needs the app's schemas there; the frames themselves need only the framework's.

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-rest 2)** **CAP-002's names** are every named schema the client's store holds once it has read the snapshot,
  the framework's included, in the store's order; choosing which to show ([CAP-009: schema browser](CAP-009.md) excludes
  `Schemas.*` and the like) is the UI's.

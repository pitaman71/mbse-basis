# CAP-228: the TypeScript5 expression dialect

*Implements* [FEA-024: expressions as data](../features/FEA-024.md), [FEA-008: expressive program models](../features/FEA-008.md). Index entry: [capabilities/README.md](README.md#CAP-228). *Relates to* [CAP-226: complete expression dialects](CAP-226.md), [CAP-036: complete kinds for Python, TypeScript and C and C++](CAP-036.md), [CAP-092: every construct of TypeScript's standards](CAP-092.md).

## Design

Not built. `TypeScript5` is a new dialect, complete by [CAP-226: complete expression dialects](CAP-226.md)'s rules:
every expression of TypeScript 5 (5.0 to 5.9) and the JavaScript it holds, with the sublanguages expressions hold (its
type nodes, destructuring patterns, and JSX, marked as an extension), its kinds the branches of `TypeScript5`'s union, `Expressions.TypeScript5.Expression`;
printed, and checked against its grammar's node list. Its kinds are mbse-programs' TypeScript expression kinds
([CAP-036: complete kinds for Python, TypeScript and C and C++](CAP-036.md)), named as typescript-estree names them;
function, arrow and class bodies stay mbse-programs' statements. Reading TypeScript's every construct is
[CAP-092: every construct of TypeScript's standards](CAP-092.md)'s. It has no translator yet, and mbse-programs no
bridge to it.

The gap, as [the proposal's survey](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/GAPS.md#typescript5) counts it: mbse-expressions has no TypeScript dialect,
so every kind is new: mbse-programs' 35 expression kinds (2 of them JSX) and 5 helpers, 11 of JSX, 4 patterns and 37
type nodes. It is the proposal's stage 4.

# CAP-316: one written form for references

*Implements* [FEA-033: model parameters](../features/FEA-033.md). *Relates to* [CAP-311: references stabilized](README.md#CAP-311),
[CAP-312: a parameter reference in place of anything with a schema](README.md#CAP-312), [the parametrics proposal](../../proposals/PARAMETRICS.md#the-wire-form).

The plain form writes a reference to an object in one form, the plain form of `References.OfObject`: `{"path": P}`. It
replaces `$ref`, a bare reference under a reserved key, which a pattern symbol's `schema` list and the nested expression
form write now, and it is the one schema of an object reference, where a link set to an object reference holds one.

## Decided

As the user decided:

- **The form is marked where it is ambiguous** ("that's fine", to the marking proposed). Where the schema that the
  reader expects at a node already says that the node holds a reference, the reference is written bare. Where the
  reader could take the node for a value of another schema, it is marked as the plain form marks any value object held
  where its schema is in doubt: `{"$schema": "References.OfObject", "path": P}`. This is the user's wire rule in
  [the parametrics proposal](../../proposals/PARAMETRICS.md#decided), and [PRI-025: never guess the schema](../PRINCIPLES.md#PRI-025).
- **A schema reference is an object reference** ("schemas have their own path"). A path from the singleton
  `"."` names a schema object and resolves through the store's schemas; any other path names data. The two need
  no second form.
- **A link's `ref` is named `reference`** ("sure that's fine"). `Mutations.OfLink.Set`'s property `ref` is renamed
  `reference`, as `Schemas.OfSymbol`'s is named, so that a link set to an object reference is written `{"reference": {"path": P}}`
  and one set to a symbol of the same transaction `{"reference": {"symbol": "0"}}`.
- **No data but the corpora is written in the forms it replaces** ("There is no legacy data other than the corpora").
  The conformance corpora of mbse-schemas, mbse-rest, mbse-expressions and mbse-programs, all written by mbse-schemas'
  plain form, are regenerated: mbse-schemas' with the change, and each dependent's when it pins the version that
  carries it.

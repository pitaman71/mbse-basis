# CAP-071: unrestricted OfAny serializes with 1-level tag

*Implements* [FEA-006: persistence](../features/README.md#FEA-006), [FEA-032: schema loading and wire alignment](../features/FEA-032.md). Index entry: [capabilities/README.md](README.md#CAP-071). Its follow-up, untagged plain data, is [CAP-170: unrestricted OfAny also accepts and roundtrips untagged plain data](CAP-170.md).

## As built: mbse-schemas

Met since before mbse-schemas 0.20.0, the first tagged release holding it, built with "`OfAny` returns" ([CAP-157: values of any schema, restricted or not](CAP-157.md#decided)); checked in the code at 0.26.4, in both languages. The writer tags an unrestricted `OfAny`'s value by one level, `{"int": 1}`, `{"crm.Phone": {...}}`: a scalar by its basic scalar's tag, any other value by its schema's registered name. The reader requires the tag: anything but a mapping of one key is refused ("a value of any schema is {schema: value}, its schema a basic scalar's tag or a registered schema's name"), and so is a name no schema is registered under, or a reference object schema's. Left so when [CAP-069: wire format shorthand (scalars)](CAP-069.md#decided) was built (its point 5).

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(framework design)** From "`OfAny` returns" ([CAP-157: values of any schema, restricted or not](CAP-157.md#decided)): "an unrestricted `OfAny` always tags, since every type is possible" ("yes"); it takes a value given as itself, never a Spec.

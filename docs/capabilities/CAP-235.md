# CAP-235: `has` translated to C++

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). Index entry: [capabilities/README.md](README.md#CAP-235). *Relates to* [CAP-230: the C++ expression dialect](CAP-230.md), [CAP-236: `has` translated to C](CAP-236.md), [CAP-103: SystemVerilog's other operations translated](CAP-103.md).

## Design

Not built. Today the C and C++ translator refuses `has`, naming the term (mbse-expressions' tutorial 8, "What has no
counterpart"): "a C struct always has its members, so there's nothing in C to translate it to". The user decided
(2026-11-03) that this is a planned gap, "filled by a CAP for C++ and a CAP for C".

In C++, an optional property is a `std::optional<T>` member, so `has(x, name)` translates to `x.name.has_value()`, and
reads back from it.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **A planned gap, filled by a capability each for C++ and C** (2026-11-03): "planned gap filled by a CAP for C++ and a
  CAP for C".

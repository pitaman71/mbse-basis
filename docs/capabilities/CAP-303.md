# CAP-303: mbse-expressions' tutorials, from domains and trivial expressions up

*Implements* [FEA-057: documentation organized by semantic role](../features/FEA-057.md). *Relates to* [FEA-024: expressions as data](../features/FEA-024.md), [CAP-226: complete expression dialects](CAP-226.md), [CAP-097: value domains of published standards](CAP-097.md).

## As built: mbse-expressions

Proposed in [mbse-expressions' tutorials proposal](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/tutorials/README.md)
(#33), built on its branch `tutorials` (#35), then tutorial 7 (#37), tutorial 8 (#38) and tutorial 8's pages (#44), and
released in 0.10.0. Each tutorial is a notebook in both languages, `python3/tutorials/` and `typescript5/tutorials/`,
one series under one README per language (*Tutorial: expressions as models, then constraints as data*), each step a
case, `## nn.k · title` after its anchor `<a id="Tnn.k"></a>`, run by both suites and committed with its outputs
([PRI-034: tutorials run as tests, committed with their outputs](../PRINCIPLES.md#PRI-034)).

- **Part I, expressions as models** (tutorials 1 to 8): a domain as data (1); one value, `42`, a domain in each
  language (2); the smallest expression, a literal (3); names (4); operators (5); calls, members and subscripts (6);
  bindings, each a variation of `let` (7); and sublanguages as dialects of their own (8), which leads to a page for
  each sublanguage dialect, 8.01 to 8.17 (`08_mm_<Name>`, anchors `T08.mm.k`), as the user asked of it (2026-11-12,
  [the basis](../README.md#the-doc-spec)). Each step pairs a language's own text with the model its dialect holds,
  written in the builders' fluent calls, and checks that the dialect's `Text.ToText` gives that text back; Python's
  twins also read Python3 with `Text.FromText`, the listed deliberate difference. Part I tells no story: it starts
  from the toolkit's `dialects()`, a store with every dialect installed and defined.
- **Part II, constraints** (tutorials 9 to 15): the seven case studies on constraints the series had, one cold chain
  story, renumbered after Part I and trimmed of what Part I teaches, each trimmed step pointing back to it; T01.3 and
  T07.5 removed, Part I teaching them whole.
- **The skill relinked** to the new anchors, and given cases from Part I for what it already taught.
- **SKL-05**, in both suites: every tutorial has the same steps in both languages, the same headings and anchors in
  the same order.
- *Values with widths*, the tutorial deferred with domain inference, joins tutorials 2, 3 and 15 as further steps when
  [CAP-232: domains inferred for terms](CAP-232.md#decided) lands, so that no anchor moves again.

## Decided

The user's request (2026-11-10): "Before moving to `mbse-programs`, `mbse-expressions/<language>/tutorials` needs an
overhaul. The content seems to focus entirely on constraints, which should be preceded by Jupyter notebooks that serve
as both tutorial and test, building up knowledge of how domains are represented, how native expressions correspond to
modeled expressions starting with trivial expressions and building up complexity." The user merged the proposal on
2026-11-11 (mbse-expressions#33), which the coordinating session took as accepting its three recommendations: the
acceptance is inferred from the merge, not stated by the user.

- **Builder calls in Part I** (its question 1, option a): every model in Part I is written in the builders' fluent
  calls ([PRI-019: fluent builder syntax](../PRINCIPLES.md#PRI-019)), and each dialect's writers are shown once, in
  03.1, as the shorthand Part II uses, asserting `Terms.same`.
- **Native text printed, and read where it can be** (question 2, option a): each model is built, then checked that its
  dialect's `Text.ToText` gives the native text; Python's notebooks also read Python3 with `Text.FromText`, under the
  same case ID. Reading the other languages is mbse-programs'
  ([PRI-011: the lowest repository that can own it](../PRINCIPLES.md#PRI-011)).
- **Tutorials 1 to 6 and Part II first, 7 and 8 after the retrofit** (question 3, option a), so that nothing is
  written twice.

## Decided by an agent, for review

- **(mbse-expressions, tutorials proposal)** One series, not two: Part I and Part II share each language's
  `tutorials/` and README, the numbers running on.
- **(mbse-expressions, tutorials proposal)** Part I has no story, and a toolkit store of its own, `dialects()`; Part II
  keeps the cold chain.
- **(mbse-expressions, tutorials proposal)** `state` is shown as a kind, with no domain, since a program's own enums get
  none and no tutorial invents a fixture domain; Excel's `error` shows a stored domain with members.
- **(mbse-expressions, tutorials proposal)** SystemVerilog's `42` is shown as `integer`, its inferred domain, with
  `int` beside it.
- **(mbse-expressions, tutorials proposal)** Two Part II steps removed (T01.3, T07.5), and the steps after T01.3
  renumbered within tutorial 9, so that no tutorial's steps have a gap.
- **(mbse-expressions, tutorials proposal)** SKL-05, new, in both suites.
- **(mbse-expressions, tutorials proposal)** One name helper in tutorials 5 and 6, `variable`, a spec named after the
  kind it writes ([PRI-004: one visitor protocol per kind](../PRINCIPLES.md#PRI-004)), not `var`, a reserved word in
  TypeScript.
- **(mbse-expressions, tutorials proposal)** The skill's "Names" section corrected for `Domains` and `Standards`, the
  keyword-tagged kinds' `getattr` listed in mbse-expressions' equivalence document; Python's `FromText` dropping
  parentheses is `ast`'s, and stays as built, 05.3 saying so.

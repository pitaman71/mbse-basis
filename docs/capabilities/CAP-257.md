# CAP-257: an object's reader typed by its schema in Python

*Implements* [FEA-025: serialization behavior conventions in schema](../features/FEA-025.md). *Relates to* [QUA-014: precise typing for bespoke and generated source code](../QUALITIES.md#QUA-014), [CAP-107: one visitor protocol reads and writes data](CAP-107.md), [PRI-015: concrete references are programmatic](../PRINCIPLES.md#PRI-015).

## Design

Not built. This capability is tech debt, incurred by the read-only view of the visitor protocol,
`Readers.OfX` ([CAP-107: one visitor protocol reads and writes data](CAP-107.md)). In Python, `Readers.OfObject` reads
an object's members through `__getattr__(self, name: str) -> Any` (checked in mbse-schemas' main at 21db1ee), so
code reading a member of an object through its reader gets `Any`, which no type checker checks. Met when an object's
reader gives each member the type its schema declares, by typed bindings for the schema
([PRI-015: concrete references are programmatic](../PRINCIPLES.md#PRI-015)).

## Decided

- **Logged as tech debt** (2026-11-10): as the user decided, "Tech debt is capability codes, not notes in markdown",
  and "I don't know why you would expect a single feature to contain all tech debt items"; approving ("yes") that each
  debt be a capability of the feature whose work caused it, relating to [QUA-014: precise typing for bespoke and generated source code](../QUALITIES.md#QUA-014) where it concerns typing, and
  that a debt an existing capability already covers be linked to it rather than made a capability of its own.

# CAP-012: logical view endpoints

*Implements* [FEA-003: no-code logical views](../features/FEA-003.md). Index entry:
[capabilities/README.md](README.md#CAP-012).

Backend has one endpoint per logical view kind, each taking a
transaction expression (a template from [CAP-004: logical view templates](CAP-004.md), its symbols given).
Endpoints take no arguments: the mutation expression in the request's
body carries the query's bindings.
Its response is a stream of `References.OfFrame` whose `assigns` and
`entries` the service fills as the view kind defines.

## As built

### Wire format

Every body that carries a schema-governed value is mbse-schemas' plain form as JSON, written and read by mbse-schemas
alone (`Plain`, `JSON`): a transaction is its expression (`Plain.ToPlain(store).Transaction`), a frame a
`References.OfFrame` value. Nothing here defines a format of its own beyond the envelopes below.

- A JSON body is `application/json`. A refusal is `{"error": "<message>"}` with a 4xx or 5xx status.
- A stream of frames is `application/x-ndjson`: one `References.OfFrame` a line, each line as
  `JSON.ToJSON(store)(References.OfFrame, frame)` writes it, each ending with `\n`. No frames is an empty body. The
  status is decided before the first frame is written: a refused transaction is a 400 with an error body, never a
  partial stream.

### Endpoints

| Method and path | For | Request | Response |
|---|---|---|---|
| `GET /schemas` | [CAP-002: named schema list](CAP-002.md) | none | the store's schema snapshot, while [CAP-003: schema inspector](CAP-003.md) is blocked: the schemas transaction of `Plain.ToPlain(store).Snapshot()` |
| `GET /schemas/{name}` | [CAP-003: schema inspector](CAP-003.md) | none | 501 until mbse-schemas writes one schema object (blocked: [CAP-003: schema inspector](../capabilities/CAP-003.md#blocked)); 404 for a name the store lacks |
| `GET /views` | [CAP-004: logical view templates](CAP-004.md) | none | `{"label": T, "chip": T, "detail": T, "adjacency": T}`, each `T` a template, a transaction's expression |
| `POST /views/{kind}` | this capability | a template of `kind`, its symbols given: a transaction's expression | the frames, NDJSON; 404 for an unknown kind, 400 for a transaction refused |

**Endpoints take no arguments**: no query parameters, and no path segment that binds anything. A view's
path names its endpoint, one per kind; the mutation expression in the request's body carries the query's bindings,
each symbol given a schema or a `References.OfObject`, and whatever the spec adds. `GET /schemas/{name}` keeps its
name for now, answering 501 while [CAP-003: schema inspector](CAP-003.md#blocked) is blocked.

### Refusals and failures (M1)

Every refusal is `{"error": "<message>"}`, `application/json`; the message is for people, not to be parsed.

| Status | When |
|---|---|
| 400 | `POST /views/{kind}`: the body is not strict JSON (mbse-schemas' `JSON.loads`), or not a transaction's expression, or the executor refuses it; or a frame it gives does not bind each of the kind's symbols. It wrote nothing. |
| 404 | a path the service does not serve, a view kind it lacks, a schema name its store lacks |
| 405 | a method a path does not take |
| 500 | a fault of the service's own |
| 501 | `GET /schemas/{name}` ([CAP-003: schema inspector](CAP-003.md)), until [CAP-003: schema inspector](../capabilities/CAP-003.md#blocked) is unblocked |
| 503 | the plugin failed: a transaction that wrote could not be journaled, and is undone, so that it may be sent again; or, after that, the store could not be read back from the plugin, and then every request answers 503 until the service restarts |

- **One transaction at a time**: every endpoint holds the service's lock while it reads or writes the store; a view's
  frames are computed and written as JSON under it, then streamed (`StreamingResponse`, chunked) once the status is
  decided.

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-rest 1)** **Paths and methods** as in this capability's
  endpoints; `POST` for a view, since its body is a transaction's expression.
- **(mbse-rest 10)** **NDJSON** for the stream, its status decided before the first frame (the server computes the
  frames, then writes them).
- **(mbse-rest 11)** **Writes through view endpoints** are accepted and journaled ([CAP-013: an in-memory store
  journaled to DynamoDB](CAP-013.md)'s flow), detected by an `upsert` or `update` term in the expression.
- **(mbse-rest 13)** **One transaction at a time**: the service holds one lock over its store (transactions on one store
  do not nest).
- **(mbse-rest 19)** **Every refusal answers the contract's error body**, including FastAPI's own (an unknown path, 404;
  a method, 405), and a body that is not strict JSON is a 400, not FastAPI's 422.
- **(mbse-rest 20)** **A frame that does not bind the kind's symbols** is a 400 (it was a `KeyError` answered as one),
  checked before the transaction is journaled.

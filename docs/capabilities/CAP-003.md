# CAP-003: schema inspector

*Implements* [FEA-003: no-code logical views](../features/FEA-003.md). Index entry:
[capabilities/README.md](README.md#CAP-003).

Given a schema's name, UI can obtain the full
detail for that schema. Definitions for unnamed schemas
must be included in the response. Named schemas
may be included only in referenced form.

## As built

This capability's intended body, once mbse-schemas can write it: the schema as a document of one upsert, as the snapshot's
first transaction writes each schema (a schema with no name of its own defined where it is linked, `{"def": ...}`;
a named one referred to by path, `{"ref": {"path": ...}}`).

<a id="blocked"></a>
## Blocked

Reported, not worked around (mbse-rest's `AGENTS.md`): a gap in mbse-schemas.

**One schema object cannot be written as a document.** `Plain.ToPlain(store).OfObject(meta, schema)` refuses a
schema object: Python raises `AttributeError` (`_ObjectData` has no `as_schema`); given the schema's builder
instead, `ValueError: a 'Schemas.OfObject' is owned through an adjacency with no name`; TypeScript raises
`TypeError: root.as_schema is not a function`. Only the whole store's schemas are written, as the snapshot's first
transaction. This capability answers 501 until it can.

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-rest 3)** **This capability** answers 501 with an error body until it is unblocked ([Blocked](#blocked)); the path is fixed now.

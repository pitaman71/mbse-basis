# CAP-256: a value object's builder holding its schema `readonly`

*Implements* [FEA-020: refinable models](../features/FEA-020.md). *Relates to* [QUA-014: precise typing for bespoke and generated source code](../QUALITIES.md#QUA-014), [CAP-251: values of a refinement held where what it refines is declared](CAP-251.md).

## Design

Not built. This capability is tech debt, incurred by [CAP-251: values of a refinement held where what it refines is declared](CAP-251.md) in mbse-schemas 0.26.10.
In TypeScript, a value object's builder (`_RecordBuilder`) no
longer holds its schema `readonly`: made for a union's branch or an intersection's part, it takes the schema of a
refinement's value given to it, so its schema is mutable state (`public _schema`, checked in mbse-schemas' main at
21db1ee; `readonly _schema` at 0.26.9), as Python's always was; it keeps the declared schema, `_declared`, to check
what it is given. Met when a builder's schema is `readonly` again: restoring it means placing the given value in its
owner rather than retyping the builder.

## Decided

- **Logged as tech debt** (2026-11-10): as the user decided, "Tech debt is capability codes, not notes in markdown",
  and "I don't know why you would expect a single feature to contain all tech debt items"; approving ("yes") that each
  debt be a capability of the feature whose work caused it, relating to [QUA-014: precise typing for bespoke and generated source code](../QUALITIES.md#QUA-014) where it concerns typing, and
  that a debt an existing capability already covers be linked to it rather than made a capability of its own.

# CAP-004: logical view templates

*Implements* [FEA-003: no-code logical views](../features/FEA-003.md). Index entry:
[capabilities/README.md](README.md#CAP-004).

Backend has a designated endpoint (no arguments) that for every 
supported logical view, returns a template for that logical view 
as a mutation query beginning with a Mutations.OfMap with
at least one symbol. When the UI uses the template it gives each symbol
(`Schemas.OfSymbol`) in the outermost `Mutations.OfMap` expression exactly
one of a schema or a `References.OfObject`. A symbol given a schema always
has universal interpretation: it ranges over every extant object of that
schema. A symbol given a reference binds the one object it designates.
The UI may also add to the pattern's spec, for example naming the
adjacency a [CAP-008: adjacency as a list of chips](CAP-008.md) view follows.

Variables in templates are deferred.

## As built

### Templates

A template is one map whose one pattern declares the kind's symbols, each given neither a schema nor a reference:

```json
{"mutations": [{"map": {"symbols": [{"symbols": {"x": {}, "y": {}}}]}}]}
```

| Kind | Symbols | The client gives |
|---|---|---|
| `label` | `x` | `x` a schema (every object of it) or a `References.OfObject` (that one object) |
| `chip` | `x` | as `label` |
| `detail` | `x` | as `label`; usually a reference |
| `adjacency` | `x`, `y` | `x` a reference, `y` a schema; and adds to the pattern's spec `_.x.<adjacency>([_.y])`, naming the adjacency |

The client builds the filled template with mbse-schemas' builders, `Views.request(store, kind, given, adjacency?)`,
never by editing JSON: for example, the capabilities of a goal,

```typescript
Views.request(store, "adjacency", { x: goalReference, y: store.registered("work.Capability") }, "capabilities");
```

A template carries no spec; the client may add to it, as the `adjacency` view does to name the adjacency
it follows, a member of `x`'s schema, in plain builder notation, as above.

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-rest 4)** **Templates**: kinds `label`, `chip`, `detail`, `adjacency`; symbols `x` (the object viewed) and `y`
  (what `x` links); each template one map of one pattern, its symbols unassigned (`{}`), which the executor refuses as
  such.

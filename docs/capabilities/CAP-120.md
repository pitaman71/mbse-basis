# CAP-120: owned objects named and placed when built

*Implements* [FEA-026: deterministic object identity](../features/FEA-026.md). Index entry: [capabilities/README.md](README.md#CAP-120).

## As built: mbse-schemas

Met in mbse-schemas 0.20.0: the [store overhaul](../../../mbse-schemas/docs/proposals/store-overhaul/README.md)'s 4a (`owner()`, `.pattern(...)` on key properties) and 4b (ownership filled at build), released in 0.20.0.

### Naming

A key that continues a path may take a naming pattern, on the ownership relation's key property:
`Schemas.OfProperty.pattern(r"DEF-\d+\d\d")`. Where a key is not given, its value is generated from the pattern,
strictly increasing among the owner's entries; a value given that does not match the pattern raises when written:
`e.name('hello')` against `DEF-\d+\d\d` (13, 22). Patterns are only on such key properties (41 in [CAP-118: singletons, owned and counted objects](CAP-118.md#decided)).

### Building

An owned object can be built in the apparently isolated manner of today. When its transaction ends, an object whose
ownership adjacency is still empty is given the one owner possible, the singleton at the owning end, its keys generated
from their patterns; where none or more than one is possible, the transaction aborts, naming the ownership missing
(15, 33).

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(object identity 6)** A suffix given for a schema with a `ref` pattern that it does not match: "raise". (The pattern moves to a property,
  13; a value given that does not match it still raises, 22.)
- **(object identity 13)** "the name-picking regex moves out of Schemas.OfObject.ref(), which no longer takes a pattern at all, and into
  Schemas.OfProperty.pattern(r"FEA-\d+\d\d")".
- **(object identity 15)** "building a non-singleton reference object can be coded in the apparrently isolated manner as it is today.
  However, the builder must recursiely trace ownership links back to a singleton. If the ownership adjacency is
  already populated according to the builder, recursion continue. Any adjacencies along the ownership path not
  already extant (as a relation entry) will need to be added and any property values for that relation entry will
  need to be generated per their regex."
- **(object identity 22)** A key value given that does not match its property's pattern: "raise when written".
- **(object identity 33)** Building an object whose ownership adjacency is empty links it only where one owner is possible, its schema
  through `HasInstance` or the singleton at the owning end, a key generated per its pattern; otherwise it raises,
  naming the ownership missing ("agreed"). (Its `HasInstance` case is superseded by 37 in [CAP-118: singletons, owned and counted objects](CAP-118.md#decided).)
- **(object identity 34)** A schema's naming pattern stays on the object schema, `OfObject.pattern`, and names the entries of
  `Schemas.HasInstance` that own its objects ("Keep OfObject.pattern (Recommended)"); an explicit ownership relation's
  key takes its own property's pattern (13). Where a schema gives none, a `HasInstance` key is its local name
  lowercased, a dash and a counter, `contact-1` ("local-name-N (Recommended)"). (In question since 37 in [CAP-118: singletons, owned and counted objects](CAP-118.md#decided); see Open
  questions, 1.)

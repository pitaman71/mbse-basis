# CAP-010: object browser

*Implements* [FEA-004: index site browser views](../features/FEA-004.md). Index entry:
[capabilities/README.md](README.md#CAP-010).

A large UI view used to browse extant objects.
There is a section for each schema that names a singleton (a directory),
headed by the singleton's name. Its chips are the objects the singleton
holds, through its adjacencies other than its own ownership; the
singleton's own chip is not shown. Data is populated from the logical
"adjacency" view ([CAP-008: adjacency as a list of chips](CAP-008.md)), whose objects are chips.

Counted objects, which have no reference, are left out (short-term tech
debt). Until view paging, each extent is loaded whole. Objects appear in
frame order for now.

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-react 7)** **CAP-010's sections** (revised for this capability's singletons): one per
  app schema that names a singleton, in the store's order, headed by the singleton's name. Its chips are the objects the
  singleton holds: [CAP-008: adjacency as a list of chips](CAP-008.md) from the singleton's reference ([CAP-006: chip
  view](CAP-006.md) over its schema gives it) over each named adjacency but its ownership one, for each schema the
  adjacency links; each object once, in frame order. The singleton's own chip is not shown.

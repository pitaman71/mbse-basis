# CAP-277: TypeScript's types and destructuring patterns as data

*Implements* [FEA-024: expressions as data](../features/FEA-024.md), [FEA-008: expressive program models](../features/FEA-008.md). *Relates to* [CAP-228: the TypeScript5 expression dialect](CAP-228.md), [CAP-226: complete expression dialects](CAP-226.md), [CAP-279: names an expression binds found alike in every language](CAP-279.md).

## As built: mbse-expressions

Built in mbse-expressions' retrofit of [the complete dialects](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#stages) (its *Retrofit's design*, TypeScript), for
0.10.0, in both languages. The choices made where the design was silent are
[the port's API, Settled in the retrofit](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-the-retrofit-for-the-users-review), items 236 to 245.

- **`TypeScript Types`** (`Expressions.TypeScript.Types`, tag `typescript_types`): TypeScript5's `Type` union, its 37
  type kinds and the helpers only types hold, moved out of `TypeScript5` into a dialect of its own, its branches
  unchanged; `tsmappedtype`, `tsfunctiontype` and `tsconstructortype` refine `Let`.
- **`TypeScript Patterns`** (`Expressions.TypeScript.Patterns`, tag `typescript_patterns`): ECMA-262's binding and
  assignment patterns, TypeScript5's `Pattern` union, moved likewise; a pattern binds through what holds it.
- **A term's data is unchanged**, written by the same branch tags; the moved schemas' names change
  (`Expressions.TypeScript.Types.TSUnionType`), with no alias. Each dialect reads TypeScript5's terms and is read by it,
  records TypeScript 5.0 to 5.9, prints through the family's printer, and is checked complete against
  typescript-estree's node types kept as data (DIA-23).
- **Tests**: the suites TST (five cases) and TSP (four); DIA-21 to DIA-23, FRM-01, FRM-02, FRM-04, FRM-11 and FRM-13; the
  corpus cases `typescript_types` and `typescript_patterns`.
- **JSX** stays TypeScript5's extension kinds, as the user decided ([CAP-226: complete expression dialects](CAP-226.md#decided), "JSX stays `TypeScript5`'s").

## Decided

- **One name for what a pattern binds** (2026-11-12, on the retrofit's fifth open question): "5 - yes as you
  suggested". TypeScript's `binding_names` (`bindingNames`) is renamed `bound_names` (`boundNames`), the name Python's
  and SystemVerilog's patterns and the C family give what a pattern binds, in both languages, its callers, tests,
  skill and mbse-expressions' equivalence document following, with no alias.

## Decided by an agent, for review

Recorded in [the port's API, Settled in the retrofit](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-the-retrofit-for-the-users-review), not marked as the user's: each *proposed* until reviewed.

- **(mbse-expressions, retrofit, API 237)** A type's and a pattern's terms are terms, not helpers, so containers,
  labels and messages within them change.
- **(mbse-expressions, retrofit, API 239)** TypeScript Types declares its own `identifier`, a type's name, never
  reported unbound.
- **(mbse-expressions, retrofit, API 240)** An assignment's target is a reference, not a name it binds.
- **(mbse-expressions, retrofit, API 241, 243)** Type parameters optional; each dialect's editions list its own kinds,
  TypeScript5's no longer the types' and patterns'.
- **(mbse-expressions, retrofit, API 262)** An identifier in a pattern, TypeScript5's kind, is refused as TypeScript5's,
  and a literal a type holds evaluates as TypeScript5's (the coordinator's decision on owners).

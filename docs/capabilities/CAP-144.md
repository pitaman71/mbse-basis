# CAP-144: transactions sharded and run in parallel

*Implements* [FEA-027: mutations as queries](../features/FEA-027.md). Index entry: [capabilities/README.md](README.md#CAP-144).

## Design

Not built: "4e builds only the in-memory, sequential executor" (the [store overhaul](../../../mbse-schemas/docs/proposals/store-overhaul/README.md), question 11).

### Shards

A transaction holds the terms of a mutation expression ([FEA-027: mutations as queries](../features/FEA-027.md)). The query
executor may divide its execution into shards (52, 53), allocating their ids, but shards are the executor's alone: what
a transaction does does not depend on how it is sharded, so nothing records them, and a journal holds the transactions
as submitted, replayed by executing them again (56 in [CAP-129: journals replayed by execution](CAP-129.md#decided)). Where execution would otherwise depend on the order in which
frames arrive, it is made independent of it (57).

### Map and reduce, sharded

Map and reduce are meant in MapReduce's sense, so that a transaction can be sharded and run in parallel (Object identity, Decided, 52 to 57): a map works on each frame alone, emitting zero or more, and may be sharded freely; a reduce groups frames by what remains bound to them and folds each group with a collector that is commutative or associative, as MapReduce's reduce and combiner do, so that partial folds combine across shards. Whether this states the user's design of map and reduce, a symmetry in which a reduce ignores extra copies rather than folding them, is open: [CAP-142: expressions evaluated in queries](CAP-142.md#open-questions).

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(object identity 52)** As the user decided (2026-10-19), with mutations as queries ([FEA-027: mutations as queries](../features/FEA-027.md)): A transaction's structure: "Mutations.OfTransaction [ -> Mutations.OfShard ] -> Mutations.OfTerm ...". (The
  shard is the executor's, not on the wire: 56 in [CAP-129: journals replayed by execution](CAP-129.md#decided).)
- **(object identity 53)** "Shard id is allocated by the query executor".
- **(object identity 57)** A transaction's effect does not depend on how it is sharded or in what order frames arrive: keys generated from a
  pattern are given in a canonical order of the frames that need them, and `Mutations.OfReduce`'s fold is made
  independent of order (see Open questions, 1).

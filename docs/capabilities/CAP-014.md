# CAP-014: properties as markdown

*Implements* [FEA-007: property kinds](../features/FEA-007.md). Index entry:
[capabilities/README.md](README.md#CAP-014).

- anything currently represented as Schemas.OfStr is to be interpreted as
  markdown
- in object detail panel click/tap on 'edit' button toggles from view mode to edit mode
- in object detail panel view-mode, clicking on property value also toggles from view mode to edit mode
- properties participating in an ownership key are not editable here
- in edit mode 'cancel' button discards changes, 'save' button commits
- during commit, inspector toggles from edit mode to save mode
- in save mode values cannot be modified, close is disabled, save shows busy
- when services confirm edits are accepted and committed, inspector panel toggles back to view mode
- no UI or services validation at this time. all data is good data for now

## As built

### Edits

An edit writes an object's properties and gives back its detail: the detail view's template, `x` given the object's
`References.OfObject`, then an `update` whose spec writes each property given, a value of its property's schema, or
none to clear it, posted to `POST /views/detail`. The endpoint takes no new arguments: the expression carries the
edit, as it carries any view's bindings. The service commits and journals it ([CAP-013: an in-memory store journaled to DynamoDB](../capabilities/CAP-013.md)) before it fills the
frames, so the response is the object's detail as the edit left it; a refused edit is a 400 and writes nothing.

- **The client**: `Views.edit(store, reference, values)` builds it, and `client.edit(store, reference, values)` sends
  it and reads the detail back. An edit of no property is refused by the client, and one of a property the object's
  schema lacks by mbse-schemas' spec recorder, before anything is sent.
- **The corpus**: `edit-task-title` (markdown written into a task's title and description) and `edit-task-clear` (a
  description cleared), each on a fresh server, since they write.
- What a UI may edit, and how text is shown, is the UI's: this capability reads every `Schemas.OfStr` as markdown and leaves
  ownership keys uneditable; the service does not validate what it is given.

## Decided by an agent, for review

Where this capability was silent, the simplest default consistent with it and with mbse-schemas, each *proposed*
until reviewed, labeled with the repository and number it was decided under.

- **(mbse-rest 26)** **An edit is an `update` after the detail view's map**, posted to the detail view, rather than an endpoint of its own: its response is the detail the
  inspector shows next, and the view endpoints already accept and journal writes (11).
- **(mbse-react 18)** **What is markdown**: every `Schemas.OfStr` value the UI shows: labels and summaries in chips and
  in the inspector, and the inspector's text property values. Rendered with `react-markdown`; inline (a label, a chip)
  unwraps paragraphs and shows links as their text, so that a chip stays one button. A chip's abbreviated property
  values stay plain text, since cutting markdown short can break it.
- **(mbse-react 19)** **What is editable**: the inspected object's own properties whose schema is `Schemas.OfStr`, set
  or not, in its schema's order (`textProperties`). An ownership key is a property of the directory's entry, never the
  object's, so none is editable here, as this capability requires; entries' properties (a
  plan's dates) and values nested in value objects or containers are not edited in this capability. Where the UI does not know the object's schema (mbse-react 10), it offers no Edit.
- **(mbse-react 20)** **The editor replaces the detail** while editing: one text area per text property, starting from
  what the object holds; the adjacencies return in view mode.
- **(mbse-react 21)** **Saving**: only properties whose text changed are sent, through mbse-rest's `client.edit`
 ; a text area emptied clears its property. A save that
  changes nothing returns to view mode without a request. While the service commits, save mode disables the text areas,
  Cancel, Close, and Save, which reads "Saving…"; once committed, the inspector shows the detail the service gave back.
  A refused save returns to edit mode with the draft kept and the refusal shown.
- **(mbse-react 22)** **After a save, every view kept is dropped** (`Service.edit`), since an edit may change a chip, a
  label or an entry anywhere; navigating to another object discards an unsaved draft.
- **(mbse-react 23)** **Against the corpus**, only the edits it holds are accepted (`edit-task-title`,
  `edit-task-clear`); any other is refused (599), as any view the corpus lacks is.

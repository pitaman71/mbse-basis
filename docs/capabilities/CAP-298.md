# CAP-298: simplification over type parameters

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Applies* [PRI-046: simplification, not evaluation](../PRINCIPLES.md#PRI-046). *Relates to*
[CAP-296: simplification over literals, variables and parameters](CAP-296.md), [CAP-319: contexts as schema data](README.md#CAP-319),
[the parametrics proposal](../../proposals/PARAMETRICS.md#simplified).

An expression that involves type parameters, but no type algebra, is simplified, a type parameter that its context
assigns substituted as any parameter is.

## Design

- **Two levels of type parameter.** In an expression, a dialect's types are terms of its type dialect, held in term
  places, so that a type is data, and a type parameter is a parameter reference standing where a type term is expected
  ([CAP-312: a parameter reference in place of anything with a schema](CAP-312.md)). Its context assigns it a type term as its `value`, and declares its kind by its `schema`, as
  [CAP-296: simplification over literals, variables and parameters](CAP-296.md#decided) decided. In a model's schemas, a type is a schema, and a type parameter
  stands where a schema object links another, as a property's `schema`; that level stays open, below.
- **Substituted as any parameter.** With [CAP-296: simplification over literals, variables and parameters](CAP-296.md) built, a type parameter is substituted by the same rule, and
  what its substitution lets the dialect fold, as a cast's type or a size, folds. A type parameter that the context
  neither assigns nor binds stays in the residual.
- **Cases in type positions.** A C cast's type, a Python annotation, and a SystemVerilog named type, each given by a
  type parameter.
- **Not covered.** A type parameter where a schema object links another, as a property's `schema`, is schema data,
  deferred from [CAP-312: a parameter reference in place of anything with a schema](CAP-312.md#decided) to this capability, and stays open: no simplifier reads schema objects' links.

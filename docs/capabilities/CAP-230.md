# CAP-230: the C++ expression dialect

*Implements* [FEA-024: expressions as data](../features/FEA-024.md), [FEA-008: expressive program models](../features/FEA-008.md). Index entry: [Capabilities](README.md#CAP-230). *Relates to* [CAP-226: complete expression dialects](CAP-226.md), [CAP-229: the C expression dialect](CAP-229.md), [CAP-100: six languages' expression dialects](CAP-100.md), [CAP-036: complete kinds for Python, TypeScript and C and C++](CAP-036.md), [CAP-093: every construct of C's and C++'s standards](CAP-093.md), [CAP-091: Ccpp expressions bridged to C and C++ source](CAP-091.md).

## Design

Not built. `Cpp` is a complete dialect by [CAP-226: complete expression dialects](CAP-226.md)'s rules: every
expression of C++17, C++20 and C++23 (ISO/IEC 14882), one dialect each kind of which records as data the standards
that have it, its kinds the branches of `Cpp`'s union, `Expressions.Cpp.Expression`; printed, and checked against its grammar's node list. With
[CAP-229: the C expression dialect](CAP-229.md) it replaces today's Ccpp dialect
([CAP-100: six languages' expression dialects](CAP-100.md)). Its kinds are mbse-programs' Ccpp expression kinds
([CAP-036: complete kinds for Python, TypeScript and C and C++](CAP-036.md)); a lambda's body stays mbse-programs'
statements. C++26's pack indexing, reflection and splices are outside it. Reading C++'s every construct is
[CAP-093: every construct of C's and C++'s standards](CAP-093.md)'s, and a bridge to C++ source
[CAP-091: Ccpp expressions bridged to C and C++ source](CAP-091.md)'s.

The gap, as [the proposal's survey](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/GAPS.md#cpp17-cpp20-cpp23) counts it: beyond C's (in
[CAP-229: the C expression dialect](CAP-229.md)), every C++ expression is only in mbse-programs: `this`, qualified,
template, operator, conversion and destructor names; functional and named casts, `typeid`; `new`, `delete`,
`throw`, `noexcept`, `sizeof...`; raw strings and user-defined literals; lambdas; pack expansions and folds;
`requires` expressions; `co_await`, `co_yield` and `<=>`; designated initializers; and C++23's `a[i, j]`. It
is the proposal's stage 5.

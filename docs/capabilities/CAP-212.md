# CAP-212: dates, times, durations and intervals in ISO 8601

*Implements* [FEA-048: date/time dialect](../features/FEA-048.md). Index entry: [Capabilities](README.md#CAP-212). *Relates to* [CAP-134: transactions recorded with provenance](CAP-134.md), [CAP-211: text as words, phrases, paragraphs and documents](CAP-211.md).

## Design

Not built. As the user wrote it, under "object properties as text/date"; the new repository `mbse-domains`, and
mbse-demo-apps' use of these forms over `Schemas.OfStr`, are [CAP-211: text as words, phrases, paragraphs and documents](CAP-211.md)'s:

> - in `mbse-domains`, define `Dialects.ISO8601.CalendarDate`,
> `Dialects.ISO8601.OrdinalDate`, `Dialects.ISO8601.Duration`, `Dialects.ISO8601.Interval`, etc. Each carries the three things a domain representation carries: a property for the string representation, which may contain invalid data; a validation indicator for each possible validation error; and properties that encode the date in ISO8601 format

Until it is met, provenance keeps its times as UTC ISO 8601 text, as the user decided: "yes ISO8601 text for now"
([CAP-134: transactions recorded with provenance](CAP-134.md#decided), provenance 4), until a date domain exists, which this is.

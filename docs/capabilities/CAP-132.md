# CAP-132: paths retired for references

*Implements* [FEA-026: deterministic object identity](../features/FEA-026.md).

## Design

A path, a `Paths.OfRoot` value, is internal to an object reference, a `References.OfObject`, which holds one. No API
takes or returns a bare path. The documents speak of object references alone. The code still works by path in these
places, in Python and TypeScript, in mbse-schemas:

- `Paths.of(x)` gives an object's path; `References.of(store, x)` gives its object reference, and replaces it.
- `store.held(path)` finds a schema object by its path; it takes an object reference instead.
- `Proxies._Unresolved`, the placeholder for an object a loaded entry links that is not yet loaded, holds the object's
  path; it holds its object reference instead.
- The messages that name an object by its path, such as "the path 'crm.Contact' names another schema object already",
  name it by its object reference.

`Paths` and its schemas stay, inside the object reference, written `{"path": P}`
([CAP-316: one written form for references](README.md#CAP-316)).

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(references 4)** Paths stay for now, overlapping, marked deprecated in favor of References in docs, tutorials and examples; their
  removal is tech debt.
- **A path is internal to an object reference**: no API takes or returns a bare `Paths.OfRoot`, and the documents speak
  of object references alone.

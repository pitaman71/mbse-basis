# CAP-132: paths retired for references

*Implements* [FEA-026: identity and transactions](../features/FEA-026.md). Index entry: [capabilities/README.md](README.md#CAP-132).

## Design

Not built: paths overlap references, deprecated, and their removal is tech debt with no stage yet (the [store overhaul](../../../mbse-schemas/docs/proposals/store-overhaul/README.md): "no stage yet: the workspace's TODO.md, "Eliminate Paths"").

### Paths as data, deprecated

> **Deprecated in favor of References** (store overhaul 4n; [CAP-130: references to objects, entries and frames](CAP-130.md)): a reference
> to an object, a relation entry or a frame is a `References.OfObject`, `OfEntry` or `OfFrame`, made by
> `References.of(store, x)` and resolved by `References.resolve(store, reference)`; an object's path is one branch of
> `References.OfObject`. Paths stay, overlapping, until their removal, which is tech debt; the wire's `$ref` still
> writes a path.

### Paths, meanwhile

"temporarily leave Paths as having overlapping function with References, mark them as deprecated where they appear in
the docs, tutorials, examples in favor of References, and log tech debt to eliminate Paths later". The wire keeps
writing an object a document does not hold as its path (`$ref`); the corpora do not change. Removing `Paths` is tech
debt (TODO.md).

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(references 4)** Paths stay for now, overlapping, marked deprecated in favor of References in docs, tutorials and examples; their
  removal is tech debt.

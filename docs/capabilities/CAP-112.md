# CAP-112: parameters modeled as schema data

*Implements* [FEA-033: model parameters](../features/FEA-033.md). Index entry: [capabilities/README.md](README.md#CAP-112). How every kind of schema takes its parameters, by extension, is [CAP-171: parameters attached to every schema kind by extension](CAP-171.md).

## As built: mbse-schemas

Met in mbse-schemas 0.24.0: the [store overhaul](../../../mbse-schemas/docs/proposals/store-overhaul/README.md)'s 4m, built in two stages and released as 0.24.0 (their history is [CAP-171: parameters attached to every schema kind by extension](CAP-171.md)'s).

### The model, in the user's notation

*REF* denotes Schemas.OfObject
*REL* dentoes Schemas.OfRelation
*VAL* dentoes Schemas.OfAny

#### Modeling

`mbse-schemas/Parametrics` is defined normal schemas and one extension.

REF `mbse-schemas/Schemas.OfParameter` - just a name and a description
PROPS `mbse-schemas/Schemas.OfParameter.{name, description}`
REF `mbse-schemas/Parametrics.OfParameters` - nest of named parameters
REL `mbse-schemas/Parametrics.Defines(parameters, name, parameter)`
REL `mbse-schemas/Parametrics.ForValue(param: Schemas.OfParameter, schema: Schemas.OfAny)` - parameter that can bind to a value (*:1)
REL `mbse-schemas/Parametrics.ForObject(param: Schemas.OfParameter, schema: Schemas.OfObject)` - parameter that can bind to an object ref (*:1)

REL `mbse-schemas/Parametrics.HasParameters(defn, params: Schemas.OfParameters)` # unique in both directions
PROPS `mbse-schemas/Parametrics.value`
REL `mbse-schemas/Parametrics.BindsValue(defn, param: Schemas.OfParameter, value)`
REL `mbse-schemas/Parametrics.BindsObject(defn, param: Schemas.OfParameter, obj_ref)`

### Parametrics as a module

Parametrics, as the user rewrote it (2026-10-22), takes parameters out of the core meta-schemas
into a module of their own, `Parametrics`: "normal schemas and one extension", installed before use. Today a parameter
is a name every kind declares through `Schemas.HasParameter` (Store overhaul, Decided, 20: "Names only"), checked for
its name and description, written in snapshots, and read by nothing else: nothing binds it, substitutes it or says
what it stands for. This draft builds the user's model in place of that, and moves every use to it.

### The model, as the user wrote it

- `Schemas.OfParameter` stays: a reference object, its `name` and `description`.
- `Parametrics.OfParameters`: a reference object, a set of named parameters, holding each through
  `Parametrics.Defines(parameters, name, parameter)`, keyed by `name`.
- What a parameter can be bound to, one schema each (`*:1`):
  - `Parametrics.ForValue(param, schema: Schemas.OfAny)`: a value of that schema;
  - `Parametrics.ForObject(param, schema: Schemas.OfObject)`: a reference to an object of that schema.
- `Parametrics.HasParameters(defn, params: Parametrics.OfParameters)`, unique in both directions: a definition has one
  set of parameters, and a set belongs to one definition.
- Bindings, at the definition that binds them:
  - `Parametrics.BindsValue(defn, param, value)`, `value` an entry property (`Parametrics.value`);
  - `Parametrics.BindsObject(defn, param, obj_ref)`.

The extension that attaches a set to every kind is [CAP-171: parameters attached to every schema kind by extension](CAP-171.md).

### Declaring parameters

A schema then declares its parameters where `parameters` links its set, the set defined in place (linked once, by the
one definition it belongs to). The corpus's `Grid`, as it would read:

```python
store.transaction(Parametrics.install)

def module(txn):
    S = txn.Schemas
    return txn.uid("corpus.module/1").mutations([lambda mu: mu.upsert(lambda u: u.exists([lambda p: p
        .symbols({"Grid": S.OfObject, ...})
        .spec([
            lambda _: _.Grid.name("Grid").parameters([txn.Parametrics.OfParameters(lambda ps: ps.parameters({
                "n": lambda d: d.parameter(lambda p: p.description("Its side").for_value([S.OfInt])),  # keyed: its name
                "x": lambda d: d.parameter(lambda p: p),
            }))]).properties({...}),
            ...
        ])]))])
```

### Validation

- **Validation moves to `Parametrics.Defines`**, as the user decided ("move it to Parametrics.Defines"): what a kind's
  `validate()` checks of its parameters today (a name starting with `$` reserved; a description not a string; in a
  pattern, a name used as both a symbol or a variable and a parameter) is checked of a set's `Defines` entries.

### Corrected (2026-10-26)

- **Corrected (2026-10-26):** `ForValue` and `ForObject` were built `.uniques("param")`, which makes the schema
  determine the parameter, so that a schema could be the value or object schema of one parameter only, against Decided
  ("*:1": a parameter has one schema, which many share), as [CAP-155: `unique` clauses on relation schemas govern relation cardinality](CAP-155.md) reads `unique(S)`: the links
  outside `S` determine `S`. Both are `.uniques("schema")`: a parameter determines its schema. Found by the session
  coordinating mbse-rest; the corpus's `Grid`, whose `n` and `x` are both for a value of `OfInt`, held the case.

### A parameter

A parameter is a variable of a schema, or of anything else that declares it, that is determined where that element is
referred to, not by data. mbse-patterns' symbols are the other kind of variable: a predicate's symbol ranges over a
store's data, and its parameters are given where the predicate is applied. In the terms of
[MBSE.md](../../MBSE.md#what-a-specification-is-made-of), an argument is a value constraint (`rows = 3`) and a parameter
without one is an unrestricted variable, so inferring a shape (a concatenation's length, the sum of its parts') is
resolving constraints.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(schema extension 14)** Parameters (section 4): "parameters that denote domains are moved to mbse-expressions entirely"; mbse-schemas
  keeps parameters that denote schemas (`List[T]`), so today's value parameters (`Matrix(rows, cols)`, a `Word`'s
  width `w`) move with their bindings.
- **(parametrics 1)** As the user decided (2026-10-22), on the questions this draft put: **A parameter is for a value or for an object, exactly one.** A parameter with neither `ForValue` nor `ForObject`
  "should fail validation" (a check of `Parametrics.Defines`' entries, beside the others). The corpus's bare names
  so each take one when moved: chosen while building, and recorded there.
- **(parametrics 2)** **Adjacency names**, "sure": on `Parametrics.OfParameters`, `parameters` (to `Defines`); on
  `Schemas.OfParameter`, `for_value` and `for_object`.
- **(parametrics 4)** The order of 4m and its two stages: [CAP-171: parameters attached to every schema kind by extension](CAP-171.md)'s.

- **(framework design)** **Parameters are names only** (0.17.0; [Store overhaul, Decided, 20 and
  21](../../../mbse-schemas/docs/proposals/store-overhaul/README.md#decided-here)), as the user decided. A schema's parameters are "Names only
  (Recommended)": a parameter is a declared name, a symbol ([PRI-015: concrete references are programmatic](../PRINCIPLES.md#PRI-015)) standing for a schema; its `type` goes
  with the value parameters, which move to mbse-expressions, and `Parameters.Bind` and `Parameters.Apply` (Store
  overhaul, Decided, 12) bind parameters later. `Schemas.Meta` is "Defer it (Recommended)": nothing reads level 3
  yet. Carried out with schema extension 5 to 7 in [FEA-024: expressions as data](../features/FEA-024.md#decided) (`requires` "moves out of
  mbse-schemas all the way out to `mbse-patterns`"; "all bindings will need to move into mbse-expressions"; `Form`
  "should go"):
  - `OfApply`, `Argument`, `Form` and its `Term`, a scalar's `bits` and `bytes`, a predicate's `requires`, a
    parameter's `type`, `Schemas.structure`, `Schemas.Evaluate` and `Schemas.equivalent` are removed, with their
    relations (`Applying`, `HasArgument`, `Binding`, `ArgumentTerm`, `Operands`, `Requires`, `BitWidth`,
    `ByteWidth`);
  - the abstract bases `Schemas.Schema`, `Type` and `Typed` go: each kind declares its own `name`, `description`,
    `parameters` and the adjacencies of every relation it is at an end of (Store overhaul, Decided, 10);
  - a property an extension adds to a schema holds a container where its type is one (BLD-06), as a term's
    `attributes` did.

## Decided by an agent, for review

Recorded in mbse-schemas' design, not marked as the user's: each *proposed* until reviewed.

### Parametrics 4m-1, fixed by the agent

*Fixed by the agent, for the user's review* (1 and 6, the extension's, are [CAP-171: parameters attached to every schema kind by extension](CAP-171.md)'s):

- (2) **How validation is reached**: `Parametrics.validate(store, defn)`, the problems of a definition's parameters,
  checked of its set's `Defines` entries: a name starting with `$` (reserved), a description not text, a parameter
  for neither a value nor an object or for both (Decided, 1), and, of a pattern, a name used as both a symbol or a
  variable and a parameter. The messages are the core's (`names used as both symbol and parameter: ['x']`) and, for
  Decided, 1, `parameter 'x' is for neither a value nor an object: a parameter is for one` (`... for both a value
  and an object ...`). It also checks `HasParameters`' uniqueness in both directions (`it has 2 sets of parameters:
  a definition has one`; `its set of parameters belongs to 2 definitions: a set belongs to one`), which nothing
  else checks: validation checks data, and the set's end of `HasParameters` is anonymous. A kind's own `validate()`
  does not read the extension's entries: the core does not know `Parametrics`. Chosen over the kinds' `validate()`
  reading them where installed, which would keep the core knowing what it no longer holds.
- (3) **A set is a counted object**, owned by nothing. The draft's `.owner(True)` on `OfParameters`' `parameters` would
  make a set owned by its parameter, `owner()` marking the owned end (a member's, in `Schemas.install`). Owned by its
  definition, through `HasParameters`, a set could not be read by a store without `Parametrics`: the owning entry is
  ignored there (Store overhaul, Decided, 19), and an owned object no entry owns is refused. Nor does a set own its
  parameters: a parameter is a schema object, and validation refuses an adjacency that would make a counted object
  an owner.
- (4) **`Schemas.OfParameter` also declares its end of `Defines`**, anonymously (`me("parameter")`), so that a set's
  entry defines its parameter where it links it (`d.parameter(lambda p: p.for_value([S.OfInt]))`): a link's schema
  is the one object schema that declares an adjacency to it.
- (5) **`BindsValue`'s `value` is `S.OfAny(lambda a: a)`**, a value of any schema, defined where it is linked: `S.OfAny`
  alone names the meta-schema, whose instances are schemas.

### The framework design's Parametrics

From the framework design's Parametrics, Decided, where it was not marked as the user's:

- **A parameter is a variable whose binder is a schema** (or, elsewhere, a predicate, a statement, a definition).
  Its `OfParameter` declares it; a reference to it is an ordinary variable, mbse-expressions' `OfVariable` (or a
  dialect's `identifier`), resolved by name to the innermost binder that declares it, as a `let` or an `import`
  resolves its names. A parameter shadows the same name declared further out. (This replaces an earlier decision, that
  a reference holds its parameter by link: within a binder the name resolves to exactly one declaration, which is the
  link, and a reference reads the same in a schema, in an expression and in a module.)
- **A term in a schema is written as a nested form**, `Schemas.Form`: mbse-expressions' `Terms.Form` is this class.
  (Superseded: since 0.17.0 mbse-schemas holds no term; Store overhaul, Decided, 20.)

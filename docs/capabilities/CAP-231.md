# CAP-231: the SystemVerilog expression dialect, complete

*Implements* [FEA-024: expressions as data](../features/FEA-024.md), [FEA-008: expressive program models](../features/FEA-008.md). *Relates to* [CAP-226: complete expression dialects](CAP-226.md), [CAP-100: six languages' expression dialects](CAP-100.md), [CAP-063: complete kinds for Verilog and SystemVerilog](CAP-063.md), [CAP-094: every construct of Verilog's and SystemVerilog's standards](CAP-094.md), [CAP-090: SystemVerilog expressions bridged to Verilog source](CAP-090.md).

## As built: mbse-expressions

Built in mbse-expressions' stage 6 of [the complete dialects](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#stages-proposed-once-decided)
(branch `stage6-systemverilog`, its pull request), for 0.10.0, in both languages, by the decisions recorded in
[the proposal's Decided for stage 6](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#decided-for-stage-6-systemverilog-and-after-2026-11-05)
(its principles, Q1 to Q12, the namespace) and [CAP-226: complete expression dialects](CAP-226.md#decided). The choices
made where they were silent are [the port's API, Settled in stage 6 (SystemVerilog)](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-stage-6-systemverilog-for-the-users-review),
items 162 to 216, which hold the detail this section only bridges.

- **Six dialects of one family**, each at `Expressions.SystemVerilog.<Dialect>`, with its singleton, its `Term`, its
  holder refining `Expressions.Framework.Expression`, its install, its `define` and its printer: `Expressions` (IEEE
  1800 clause 11 and A.8; 38 kinds, mbse-programs' in its names and shapes, replacing the 17 constraint kinds it had),
  `Types` (clauses 6 and 7), `Patterns` (12.6), `Assertions` (clause 16's sequences and properties), `Constraints`
  (18.5) and `Preprocessor` (clause 22's directives and macro usages, and comments). A sublanguage is named with its
  family (`SystemVerilog Types`, tag `systemverilog_types`) (API 162, 163).
- **Positions hold a sublanguage's `Term`**, which lists `Expressions`' branches besides its own kinds ("(b)", Q1): a
  cast's type `Types`', a `matches`' pattern `Patterns`', a call's arguments `Assertions`', `randomize() with`'s items
  `Constraints`', which holds the Preprocessor's directives and comments too (Q6); `macrousage` stands in every
  expression position. Each dialect reads the other five's terms (`Terms.Dialect`'s `reads`, code, not data naming
  what a dialect uses: no reason to reinstate `Uses`, [CAP-098: dialects over one framework](CAP-098.md#decided)), and
  the six installs run in any order after the standard dialects' (API 164 to 169, 173).
- **Literals** (Q3): `literal` refines the framework's, adding `base`, `signed`, `separators`, `unit` and `triple`;
  `constant` holds `null`, the fills and 4-state vectors, exactly one of `singleton`, `fill` and `bits`
  ([CAP-233: literals of any value](CAP-233.md)) (API 170).
- **Names** (Q4): `nameexpression` holding its `Name`, and no `variable` (API 171).
- **Binders** (Q8): `arraymethodwithexpression` and `foreachconstraint` refine `Let`; a `matches` binds through its
  holder's scopes; `Terms.is_binder` (API 167, 172, 199).
- **A kind may hold several containers of terms**, read in declaration order, a form's attributes giving each one's
  size, so that `SolveBeforeConstraint` (`solve`, `before`) and `IfdefDirective` (`items`, `alternative`, `has_else`)
  are mbse-programs' shapes ([CAP-098: dialects over one framework](CAP-098.md), API 210 to 212).
- **Standards as data** ([CAP-268: standards as tagged data](CAP-268.md)): each `define` covers its editions by
  designation, IEEE Std 1364-1995, 2001 and 2005 and IEEE Std 1800-2005 to 2023, each with its own kinds from
  mbse-programs' `SINCE`; `Expressions`, `Types` and `Preprocessor` cover all eight, `Patterns`, `Assertions` and
  `Constraints` the five of IEEE 1800 (API 177).
- **Completeness as data** (Q9): `grammars/systemverilog-slang.json` lists slang's 533 syntax kinds (pyslang 12.0.0),
  229 mapped to the six dialects' kinds and helpers, 304 not expressions, each with its reason; DIA-29 checks each
  dialect exactly in both languages, with no slang dependency (API 179 to 186).
- **Evaluation keeps what it did** (Q11, Q12): the replacements of the 17 former kinds evaluate on the stored domains;
  every other kind is refused by name, and a conditional's `matches` before its branches are sized (API 175, 213).
- **Printing**: mbse-programs' printer ported, byte-identical in both languages, from any of the six holders (API 176,
  190, 196, 202, 208).
- **Tests**: DIA-27 to DIA-29, the suites SVP, SVA, SVC and SVD (37 cases), FRM's samples of every kind of each, and
  four corpus cases, `systemverilog_patterns` to `systemverilog_preprocessor`, byte-identical in both languages
  (API 215).

## Open questions

- **Gaps in mbse-programs** found while building, for its port, reported rather than worked around
  ([PRI-032: a sibling's gap is reported, not worked around](../PRINCIPLES.md#PRI-032)); none keeps this capability
  from being met, as reading SystemVerilog is mbse-programs':
  [CAP-094: every construct of Verilog's and SystemVerilog's standards](CAP-094.md#open-questions) and
  [CAP-086: programs printed](CAP-086.md#open-questions) record them, mbse-programs' not importing against today's
  mbse-schemas (`Visitors.Native`) among them.
- **A constant described as `None` in refusal messages** ("SystemVerilog constant None of logic [7:0] ..."): left as it
  is, for the user (API 216).

## Decided by an agent, for review

Recorded in [the port's API, Settled in stage 6 (SystemVerilog)](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-stage-6-systemverilog-for-the-users-review),
items 162 to 216, not marked as the user's: each *proposed* until reviewed. Those most worth reviewing:

- **(mbse-expressions, stage 6, API 162, 163)** A sublanguage's dialect is named by its family too
  (`SystemVerilog Types`, tag `systemverilog_types`).
- **(mbse-expressions, stage 6, API 164 to 166, 168)** A dialect reads its family's terms through `reads`, a callable
  called once; installs run in any order, each naming the others' `Term`s and creating any not yet installed.
- **(mbse-expressions, stage 6, API 167, 172, 199)** `Let`'s `name` stays unset on a binder that binds names it does not
  write itself, its kind's scopes saying what it binds.
- **(mbse-expressions, stage 6, API 169)** The `Term`s as the installs leave them: `Assertions.Term` holds Constraints'
  `distexpression`, `Constraints.Term` the Preprocessor's directives and `comment`, and every `Term` but the
  Preprocessor's `macrousage`.
- **(mbse-expressions, stage 6, API 170)** A literal's encoded properties (`base`, `signed`, `separators`, `unit`,
  `triple`), and a constant holding exactly one of `singleton`, `fill` and `bits`.
- **(mbse-expressions, stage 6, API 177)** The editions' common names (`Verilog-1995` ... `SystemVerilog-2023`), as
  mbse-programs labels them.
- **(mbse-expressions, stage 6, API 180 to 186)** The slang data's mappings, an entry holding kinds and helpers
  together, a shared kind written under the dialect that defines it; `BadExpression`, `ConditionalPattern`,
  `VoidCastedCallStatement`, `Delay3` and `OneStepDelay` uncertain.
- **(mbse-expressions, stage 6, API 187, 192, 198, 204)** Each sublanguage's `Term`, helpers and positions:
  `patternmember` a kind; Assertions' `expression_or_dist` positions; `LoopVariable`; the Preprocessor's directives'
  branches holding Constraints' terms.
- **(mbse-expressions, stage 6, API 213)** A conditional's condition sized first, so a `matches` is refused by name
  (the coordinator's decision).

# CAP-107: one visitor protocol reads and writes data

*Implements* [FEA-025: serialization behavior conventions in schema](../features/FEA-025.md). Index entry: [capabilities/README.md](README.md#CAP-107).

## As built: mbse-schemas

Met: mbse-schemas 0.26.3 (origin/main). The protocol was built in the meta-schemas overhaul's V2 and V3 (Status, below).

### The visitor pattern, reversed

After phase 4, the user found the visitor pattern backwards (Decided, below, The visitor pattern; the
Visitor pattern), which phases V1 to V4 build before phase 5, whose meta-schemas are read and
written through it. Decision C's first step in mbse-expressions is reverted: relation operations are the visitor
protocol's, not Basic's.

### V2 and V3, the protocol and its consumers

- V2 and V3 (built), one phase, with no side-by-side period ("G1 (a) no side by side period"): the old protocol and `accept`
are deleted first, so that nothing of them shapes the new one, and the commits in between do not pass.
- V2. **The visitor protocol**: `Visitors.OfX` as Visitor pattern declares it, and
  `Specs`, and the read-only views `Readers.OfX`; `Proxies.OfX.Data` (read-only) and `Proxies.OfX.Builder`
  implement it, a builder reading back its pending writes.
- V3. **Consumers pull**: `Plain`, `JSON`, `YAML`, `Validators`, `Comparison`, `Reachable` and `Modules` read and
  write through the protocol; `Bindings`, `Paths` and `Reflection` are removed, and so are `Validators.properties_of`
  and `entries_of`. With them goes what V1 left without a use: `Comparison`'s paths between value objects (`OfLink` compares by identity only), and the state's references
in a value object's entries (`Bindings`, "no snapshot holds the value"), which only a two-link relation of a value
object, now invalid, could hold.

### Status

The protocol through which code reads and writes data of any schema, as the user designed it; the decisions it
records are under Decided, below, "The visitor pattern". It is built ([CAP-109: schemas as linked objects in modules](CAP-109.md)): the schema-level changes in V1 (`as_*` names refused, `Schemas.OfScalar`, value objects
never linked, and `Schemas.OfEntry`, `Schemas.OfSymbol` and `Schemas.OfPredicate`), and the protocol, implemented by
proxies and read and written through by every consumer, in V2 and V3. Identity (V4), meta-schemas as linked objects
and `root_module()` (phase 5) and generated code (phase 6) are not built yet. `as_identity` below is superseded: an
object's identity is its path, read by `Paths.of` (Object identity, Decided, 43 in [CAP-119: owned objects found by path](CAP-119.md#decided) for data, 81 for schema objects).

### Purpose

Enable programmers to write compactly and precisely express schemas, expressions, and patterns:

- as serialization-compatible data
- in terms of operations over schema constructs
- where expressions and patterns do not need a priori understanding or closure of the schema itself
- in a format that is language-neutral
- in a manner that is dialect-extensible with datatypes and operators

### Reminders:

- a constraint is a pair of predicates over the same object symbols
- the evaluator binds each *symbol* to a Visitors.OfObject `osv`

- Visitors.OfObject and Visitors.OfEntry may only define methods named `as_Y` most of which have the form:

```python
def as_Y(self, cb: Specs.Callback[Visitors.OfY]) -> Self: ...
```

- Builders.OfX now implements Visitors.OfX directly, and so do data instances (such as Proxies.OfX.Data).
- Proxy and generated data instances and builders also have a member for named adjacencies, properties and links.
- Therefore no schema-defined property, adjacency, or link may be named `as_*` by convention to prevent collisions with Visitor methods in the generated data instances and builders.

### Reference vs. Value objects

- the dichotomy between reference and value objects remains declared via `Schemas.OfObject.Builder`: `.ref()` makes a reference object schema, and without it an object schema is a value object schema (`.value()` is dropped for now)
- reference objects may not be used as a property's value schema
- value objects are copied by value, never shared

### Specs as queries

A widely used callback pattern that can serve either as a mutator or a limited value-matching query.

```
Specs.Callback[V in Visitors.Of*] = Visitors.DataType[V] | Callable[[V], V]
```

### Mutability

- the mutableness of a visited object is a mode of the visitor itself
- value objects are mutable only during construction or cloning

- One protocol per kind: `Visitors.OfX` both reads and writes (`get`, `set`, `clear`, `insert`, ...); whether a write
  takes effect is the visitor's mode. There is no separate `Mutators.OfX`.
- Data instances (such as Proxies.OfX.Data) visit read-only, and their named members and the scalar dunders
  (`str(card.name)`, Scalar accessors) are the compact read-only interface that allows analysis expressions
  to be compactly and efficiently written without '.get' operators.
- Builders (such as Proxies.OfX.Builder and <generated>.OfX.Builder) can be configured to permit or forbid writes.
- A visitor hands its mode to the child visitors it hands over (`<propName>`, `as_value`, `as_scalar`, `<adjName>`,
  `as_adjacencies`, ...); a value object is writable only under a builder that is constructing or cloning it; a link's
  target (`<linkName>`) is read-only through an entry (Seams).
- A write through a read-only visitor raises: refuse, never silently lose ([PRI-002: preserve, don't lose](../PRINCIPLES.md#PRI-002)).
- Writer methods return nothing: a write that the visitor's mode, or the value itself, forbids raises. A write that
  loses nothing does not: inserting an entry equal to one a set relation holds elides it, and removing where no entry
  agrees removes nothing.
- Each language also declares a read-only static view of each `Visitors.OfX`, `Readers.OfX`, holding its reading
  methods only (a TypeScript interface, a Python `Protocol`). It is a type, not a second implementation: code that must
  not write (evaluators, validators, comparison, codegen's readers) takes a `Readers.OfX`, so that the type checker
  enforces it.

### Seams

Where one protocol for reading and writing meets the code around it:

- code that must not write: the read-only static view (`Readers.OfX`), checked by type.
- writes to read-only data: raise, by the visitor's mode.
- a member is written by calling it, never by assignment: assigning to a builder's property or adjacency, or to any
  visitor, raises.
- children of a visitor: inherit its mode; value objects follow their owner's construction or cloning; a link's
  target is read-only through an entry: an entry's builder relinks (`env.<linkName>(spec)`), and an object is edited
  through its own builder.
- a link member on a data instance is the linked instance itself (`entry.phone is p`); data instances are callable, so
  that calling one, a write, raises.
- one member both getter and setter on data instances and builders (`ent.linkName` read, `ent.linkName(spec)` write):
  Python's `__getattr__`/`__call__`; in TypeScript a `Proxy` with a function target, its `name` and `length` hidden, and
  generated declarations for the static types.
- reading inside a builder: readback of pending writes must be guaranteed
- journals (TODO.md, Journals): a journal that records writes implements the whole protocol, readback of pending writes included.

### Property accessors

```python
# assumed
osv: Visitors.OfObject

# visit a specific property (schema aware)
osv.<propName> -> Visitors.OfProperty: ...

# singleton and iterable shorthands - type must match exactly
# all of these set the property value - no merging
osv.<propName>(value_: T) -> Visitors.OfObject: ...  # a value of the property's schema: a scalar, a value object, ...
osv.<propName>(value_: Iterable[T | Specs.Callback[Visitors.OfAny]]) -> Visitors.OfObject: ...  # a container's elements
osv.<propName>(value_: Map[str, T | Specs.Callback[Visitors.OfAny]]) -> Visitors.OfObject: ...  # by index
# each element of a container given as an iterable or a map is a value, or a callback writing it through its visitor:
#   c.arguments([lambda e: e.variable(lambda v: v.name("x")), one])

# precisely configure the property value
osv.<propName>(cb: Specs.Callback[Visitors.OfProperty]) -> Visitors.OfObject: ...

# a property, or a container's element, whose value has one kind - an object, a union or an intersection - answers
# that kind's members: its properties, branches or parts, as through as_value and as_object, as_union or
# as_intersection. Read, a member reads the value held (empty where none is); written, it writes the value. A name
# that is not a member is not an attribute (Python: AttributeError; TypeScript: undefined).
osv.<propName>.<memberName> -> Visitors.OfY: ...
#   r.term(lambda t: t.call(lambda c: c.function("add")))
#     for r.term(lambda t: t.as_value(lambda a: a.as_union(lambda u: u.call(lambda c: c.function("add")))))
#   root.term.call.function.get()  # "add"

# iterate over all properties (schema unaware)
osv.as_properties -> Iterable[Visitors.OfProperty]
osv.as_properties(cb: Specs.Callback[Visitors.OfProperty]) -> Visitors.OfObject: ...

# explicit `get` on scalar returns native-typed value; as_scalar has no attribute form
card.name.as_scalar(lambda s: names.append(s.get()) or s)  # "Ada", or None when absent

# implicit `set` or `clear` on scalar
b.name.as_scalar(lambda s: s.clear())
b.name.as_scalar(lambda s: s.set("Ada")) # a write, through a Spec's callable form
b.name.as_scalar("Ada")            # shorthand for `set`, through a Spec's value form

# dunder shorthands = syntactic sugar over `get`, on Visitors.OfScalar and, passing through as_scalar, on
# Visitors.OfProperty
# raise when not set or mistyped: each needs the scalar's own type (int() an int, str() a str, ...)
# bool : same as others, not semantically overloaded with "is_valid"
int(card.age)
float(card.weight)
str(card.name)
bool(card.vip)
bytes(card.photo)

# comparison: a scalar visitor compares, orders and hashes as its value

# read-only visitors are hashable, writable ones not
card.name == "Ada"
card.age < 40
{card.name}

# TypeScript: [Symbol.toPrimitive] and valueOf, as far as they reach (EQUIVALENCE.md); `===` cannot be overloaded,
# so a scalar is compared once read: card.name.get() === "Ada"
```

### Another new problem:

Quite a few other convenience methods have been born like OfProperty.name, OfObject.has which are not necessary and whose names introduce possible collisions between the adjacency and property names and Visitor methods. Instead every `Visitors.OfX` will have a method `as_schema() -> Schemas.OfX`

### Mappings for keyed adjacencies

**Mappings for keyed adjacencies** (Decided, below). An adjacency whose relation has exactly two links and one
property may be given a mapping in place of the peer-shorthand list. Its visitor is then a flat union of the entry's
visitor and the linked object's: it exposes and delegates the entry's property and the linked object's properties and
adjacencies. Each item of the mapping, in order, is one entry: its key is the value of the entry's property, and its
value is given to that flat visitor. A callback is called with it, the property already written; any other value goes
to the one member that accepts it, the entry's other link or one of the linked object's properties and adjacencies, and
is refused where none does or several do. So `{"ada": Person}` and `{"ada": lambda s: s.schema([Person])}` are both
`[lambda s: s.name("ada").schema([Person])]`. As the list form does, it inserts entries; since keys are distinct,
entries sharing a property value need the list form. In TypeScript a mapping is a `Map` or a record. The definition
above may so be written `.symbols({"OfSymbol": txn.Schemas.OfObject})` and `.properties({"name": txn.Schemas.OfStr})`.

### From the framework design

- No relation builder is exposed to the caller; entries are added through adjacency accessors on the object builder,
  which take an entry `Spec`, e.g. `.addresses(lambda x: x.address(addr1).label('work'))`. A link takes an existing
  object or a `Spec` that builds a new one.
- `clone()` copies the source's adjacency entries to the clone.
- Building a new object inline through a link (`x.phone(lambda y: ...)`) requires an unambiguous inference of its
  schema: exactly one registered object schema may declare an adjacency to that relation via that link; otherwise it
  is an error. Pass an existing object instead when inference is ambiguous.
- A property that is not set reads as `None` (0.8.4), not an error, on proxies, value objects and entries, so that code
  reads proxies and generated classes alike: no property holds `None` as a value, so `None` means absent, and absent
  properties are still left out of what is written. Reading a name the schema does not declare still raises.

- Adjacencies are members (0.8.3): a proxy reads an adjacency as the entries it holds, and an entry's links and
  properties as attributes, as generated classes will, so that code reads either without change.
- Generated code (mbse-codegen-*) will have the same members as proxies, so code that reads objects works on proxies and generated code alike ([PRI-010: proxies and generated code read alike](../PRINCIPLES.md#PRI-010)): each schema's `<schemaName>.Data`, `.Builder` and `.Schema` ([FEA-022: code generation](../features/README.md#FEA-022)); see Decided, The visitor pattern.

## Open questions

- **A set sorted by a comparator.** An adjacency is any iterable; a set sorted by a comparator, which would serve retrieval, is open.
- **Reserved names (F2).** Names starting with `$` are reserved for the wire format, and `as_` for the visitor protocol
  (see Decided). Other property and adjacency names that collide with a visitor's own members (e.g. `create`, or
  names starting with `_`; `then` in JavaScript) cannot be set through a builder's member or read as members in some
  bindings, and `validate()` accepts them. Should schemas reject names that any target language reserves, or should bindings rename them?
- **Reading an object's entries back (e.g. a contact's phones), and removing an entry through a builder.** (Possibly stale: an adjacency's entries are read by iterating it, `as_iterable` ([CAP-108: containers of any index and element](CAP-108.md), V5), and `remove` is built ([CAP-140: entries removed through a spec](CAP-140.md), Store overhaul 4j).)

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(framework design)** **Mappings for keyed adjacencies** (step 4e of the store overhaul; [Schema extension](CAP-116.md),
  Injection), as the user proposed and decided ("I like your idea", "yes that seems sensible"): an adjacency whose
  relation has exactly two links and one property may be given a mapping in place of the peer-shorthand list. For such
  a relation the adjacency's visitor is "a flat union of the Entry visitor and the Object visitor": it "exposes and
  delegates the properties of both the entry and the linked object as well as adjacencies of the linked object itself".
  Each item, in order, is one entry: its key is the value of the entry's property, and its value is given to that flat
  visitor, a callback called with it, the property already written, any other value given to the one member that
  accepts it (the entry's other link, or one of the linked object's properties and adjacencies), refused where none
  does or several do. `{"ada": Person}` and `{"ada": lambda s: s.schema([Person])}` are both `[lambda s:
  s.name("ada").schema([Person])]`. It inserts entries, as the list form does; keys being distinct, entries sharing a
  property value need the list form. In TypeScript a mapping is a `Map` or a record. Not a wrapper: one rule of the
  builder protocol, for every builder and schema ("wrapping fluent builder syntax is forbidden").
- **(framework design)** **The visitor pattern** ([Visitor pattern](CAP-107.md), which holds the protocol as the user designed it), as
  the user decided, finding that the framework had the pattern backwards: "the Visitors interface is supposed to expose
  an api to the caller to access a data structure whose schema the calling code may or may not know in advance";
  "Analysis and transformation algorithms accept a visitor as an argument and use the visitor - and also possibly
  knowledge of the schema at coding/compilation time - to access the values/objects/properties/relations/etc."; the
  serializers' writers "implementing the visitors protocol" are "precisely backwards"; and "`Visitable.accept` is a
  hallucination". So:
  - one protocol per kind, `Visitors.OfX`, reads and writes ("one interface, not one class definition"); builders
    implement it ("Builders implement Visitors - full stop"), and so do data instances: "with these changes I think we
    can declare that data instances also implement Visitors", the changes being named members (`osv.<propName>`,
    `env.<linkName>`) and `Specs.Callback[V] = Visitors.DataType[V] | Callable[[V], V]`, a value or a callable, which
    serves "either as a mutator or a limited value-matching query"; `Visitors.DataType[Visitors.OfAdjacency]` is
    `Iterable[Visitors.OfEntry]`, "with implied 'insert' semantics (not replace)"; an adjacency member reads as a
    "`Visitors.OfAdjacency` that is also iterable"; the scalar dunders (`int`, `float`, `str`, `bool`, `bytes`) are
    sugar over `get`, raise when the value is not set or of another type, and pass through from
    `Visitors.OfProperty` ("bonus points if they can also be called on Visitors.OfProperty directly (pass thru via
    as_scalar)"), TypeScript's `[Symbol.toPrimitive]` going as far as it reaches; unions, intersections and
    predicates take the member style, a branch or a part giving the visitor of its type's kind directly (the
    `Visitors.OfProperty` between being "an implementation detail"; "symmetry with properties isn't particularly
    important"); `Visitors.OfAny` has `clear()`, which `Visitors.OfScalar.clear()` aliases; a link member on a data
    instance is the linked instance itself, data instances being callable so that calling one, a write, raises ("yes"); `as_scalar`, `as_value` and
    `as_adjacencies` gain no attribute form ("no"; "as scalar has no attribute form"), so a
    scalar is read compactly through the property's dunders (`str(card.name)`), and its presence through
    `Visitors.OfProperty.get()`, a pass-through to `as_scalar` (the user chose it, "1", over an `as_scalar` attribute
    form and equality as presence). (Before that, the user had agreed
    that data instances not implement it, correcting "and so do data instances", which I had inferred.) There is no
    separate mutator protocol;
  - code generation generates, for every schema, the analogues of a proxy: "`<schemaName>.Data` - instance form",
    "`<schemaName>.Builder` - mutator form implementing Visitors", "`<schemaName>.Schema` - alias for schema itself";
    so `Bindings`, which bound a program's own classes to schemas through their states, goes ("yes, remove Bindings"),
    and so do `Paths` ("yes, remove Paths"), ahead of V4, and `Reflection` ("yes, remove Reflections"), whose part
    `root_module()` takes in phase 5; `Validators.properties_of` and `entries_of` go, the protocol reading properties
    and entries;
  - "the mutableness of a visited object is a mode of the visitor itself": builders "can be configured to permit or
    forbid writes", a visitor hands its mode to the child visitors it hands over, except a link's target, read-only through an
    entry, an object being edited through its own builder ("the 'children inherit their parent's mode' was overly
    simplified"), and
    "value objects are mutable only during construction or cloning"; writer methods return nothing, and a write the
    mode or the value forbids raises; a read-only static view of each protocol (`Readers.OfX`) types the code that
    must not write; a builder's visitor reads back its pending writes ("must be guaranteed");
  - `Visitors.OfObject` and `Visitors.OfEntry` "may only define methods named `as_Y`", so "no schema-defined property,
    adjacency, or link may be named `as_*`", which `validate()` refuses; every `Visitors.OfX` has `as_schema()`, in
    place of conveniences such as `OfProperty.name` and `OfObject.has`, so `Schemas.OfEntry` (and its meta-schema)
    "must exist"; an object's identity is a scalar, `as_identity`;
  - relations are modified "entirely" through `Visitors.OfAdjacency` (`select`, since replaced by `as_iterable`;
    `insert`, `remove`), whose `remove` removes "all that match"; relation operations are the visitor protocol's, not
    an expression dialect's ("Relation operators do not belong in Expressions.Basic. They never did");
  - anything that has a builder has a `Spec`, "a callable taking and returning that builder", or "an instance of the
    built object" ([PRI-004: one visitor protocol per kind](../PRINCIPLES.md#PRI-004), amended);
  - `OfScalar` "completely displaces" `OfNative`, in `Schemas` and `Visitors`: a module writes `{"scalar": {"format":
    ..., "token": ...}}` (superseded since 0.18.0: a scalar has no token; Store overhaul, Decided, 22);
  - a reference object is named by its global name if it has one, otherwise by "a UUID on creation by `.create()` or
    `.clone()` that is saved on the wire" (refined by Reference identity: a naming pattern may take the UUID's place;
    superseded since 0.20.0 by Object identity: no UUIDs); "value objects are never shared"; "value objects cannot be referenced by
    entries"; a value object may have adjacencies only to one-link relations, of "zero or more" properties (since
    Containers, above, a value object has none: its lists are containers); "Paths go away";
  - `.ref()` declares a reference object schema, and an object schema without it is a value object schema ("drop the
    `.value()` for now");
  - `Schemas.OfPredicate` (superseded since 0.21.0 by `Schemas.OfPattern`; [CAP-137: patterns of symbols, variables and specs](CAP-137.md#decided), Patterns), after mbse-patterns'
    predicate: its symbols, its parameters and its constraint as a
    `Schemas.Form`, mbse-schemas knowing no dialect; finding matches and `Patterns.Stores.update`, which returns a
    certificate ("a compact record ... that can be used to track the effect of the write in a lazy distributed
    system"), are mbse-patterns'.
  - `Schemas.OfEntry` is an element the relation holds, carrying the entries' links and properties (the user agreed to
    that description), and it follows the pattern of every element: "`Schemas.OfEntry.Builder` is responsible fo[r]
    building `Schemas.OfEntry.Data`", with a `Spec`, and `Schemas.OfRelation.Data.entry` holds what it builds, as
    `Schemas.OfObject.Data.adjacencies` holds what `Schemas.OfAdjacency.Builder` builds (the user, on an entry built
    on each read instead: "no idea why you would hallucinate something rather than follow the pattern"). Its links
    and properties are by name, in declaration order. "It's okay for the `links` and `properties` adjacencies to stay
    where they are": a relation's module form keeps its `links` and `properties` lists, and the relation's builder
    its `.links(...)` and `.properties(...)`, which declare the entry schema.
  - a predicate's symbols and an entry's links are both `Schemas.OfSymbol`s, after the user's "maybe
    `HasSymbols(Schemas.OfPredicate, Schemas.OfSymbol)` and `HasLinks(Schemas.OfEntry, Schemas.OfSymbol)`" (phase 5's
    meta-relations; until then, lists): a symbol is a name with an optional reference object schema, which a
    predicate's symbols require and an entry's links may leave unset;
  - a predicate's `requires` is one `Schemas.Form` ("one form"; Superseded by Parameters are names only (0.17.0): `requires` is mbse-patterns').
  - a member is written by calling it, never by assignment: "refuse all direct writes to properties and adjacencies"
    on a builder, as on a data instance, so that assigning to any visitor's member raises `AttributeError` in both
    languages rather than being silently lost ([PRI-002: preserve, don't lose](../PRINCIPLES.md#PRI-002));
  - scalar equality stays idiomatic, the user's concern being "the loss of language-idiomatic equality between scalars
    including strings", and their decision the recommendation they accepted ("I accept your recommendation"): in Python
    a scalar visitor compares, orders and hashes as its value (`card.name == "Ada"`, `card.age < 40`), sugar over
    `get()` as the dunders are, a value of another kind comparing by its identity, a read-only visitor hashable and a
    writable one not; TypeScript, where `===` cannot be overloaded, compares a scalar once read
    (`card.name.get() === "Ada"`), `==` converting but not being the idiom; data instances' scalar members stay
    visitors in both languages, not primitives;
  - the protocol is VISITOR_PATTERN.md's, as the user streamlined it; the user decided its gaps so:
    `Proxies.OfX.Data` and `Proxies.OfX.Builder` implement it; the old protocol is removed before the new one is built,
    "no side by side period", since keeping both could make the new surface act like the old; the spec is "intentionally
    exception free", so reads never raise, and the one raise is a write that the visitor's mode or the value forbids;
    and every callback is always called ("If they don't always call the callback, there is no way to set the value"),
    the visitor it is given reporting an absent value, or a value of another kind, as empty.

  It supersedes: [PRI-004: one visitor protocol per kind](../PRINCIPLES.md#PRI-004) as it stood (amended); here, "Objects outside snapshots are named by paths (0.8.2)",
  The meta-schemas overhaul's "we can keep paths", and decision C in mbse-expressions; and, in the sections above, what
  the reverse protocol built (`accept`, `Plain`'s writers and `Validators`' and `Comparison`'s recorders implementing
  `Visitors`, `Bindings.accept`, `Reflection`'s `accept`), value objects that links target, and `Paths`. It is built:
  links that target only reference objects, and value objects' adjacencies to one-link relations only (since gone:
  Containers, above), in META_SCHEMAS.md's V1, and the protocol itself, with `Bindings`, `Paths` and `Reflection` removed, in V2 and V3.
- **(framework design)** **Adjacencies, as specified:** "adjacencies are always stored in a class under the name of the adjacency and must
  store an Iterable over full relation entries, such as `Proxies.OfEntry.Data` or generated equivalent." So: the one
  member, named after the adjacency, in every implementation, proxies and every mbse-codegen-* alike; it holds an
  Iterable (a tuple, a frozen array, or any other: the type is not part of the contract); each item is a full entry,
  every link the owner's own included, and its properties, an object of `Proxies.OfEntry.Data` or of the generated
  entry class. Only the wire form leaves out the link the adjacency implies (0.8.3, 0.9.1).

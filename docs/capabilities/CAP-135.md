# CAP-135: provenance records reproducible and attributable

*Implements* [FEA-030: transactions](../features/FEA-030.md). Index entry: [capabilities/README.md](README.md#CAP-135).

## Design

Not built: the placeholder records [CAP-134: transactions recorded with provenance](CAP-134.md#decided-by-an-agent-for-review) settles (its points 3 and 4) are tech debt.

### Tech debt

- **Placeholder records** (Decided, 3 in [CAP-134: transactions recorded with provenance](CAP-134.md#decided): "Use placeholder data as needed and log tech debt to get it
  right"): an imperative scope's record (`with store.transaction():`, or a document read outside a transaction), and
  that of an expression naming no `uid`, `when` or session, has placeholder data: a random `uid`, so that a replay never
  finds its record again; the clock's `when`, not reproducible; and the one shared session `unknown`, whose identity is
  `unknown`. So it is neither reproducible nor attributable.

### Getting it right

Give an imperative scope a way to name its uid, time and session (for instance `store.transaction(uid=...,
when=..., session=...)`), or journal it as an expression, so that its record is reproducible and attributable.

## Open questions

- **Placeholder sessions**: one per process, rather than the one shared session `unknown`?

# CAP-170: unrestricted OfAny also accepts and roundtrips untagged plain data

*Implements* [FEA-032: schema loading and wire alignment](../features/FEA-032.md). Index entry: [capabilities/README.md](README.md#CAP-170). *Relates to* [FEA-020: refinable models](../features/FEA-020.md), [QUA-002: open-world models](../QUALITIES.md#QUA-002). It follows [CAP-071: unrestricted OfAny serializes with 1-level tag](CAP-071.md).

## Design

Not built. As the user directed: restore the legality, but not the requirement, that any plain data is acceptable as an unrestricted `OfAny`'s value, and that it round-trips. The one-level tag of [CAP-071: unrestricted OfAny serializes with 1-level tag](CAP-071.md) stays legal, and a tagged value is read as today; untagged plain data is accepted too, and written back as it was read.

## Open questions

- **Holding and reading untagged data without guessing.** How untagged plain data is held, and read, without guessing a schema from its shape ([PRI-025: never guess the schema](../PRINCIPLES.md#PRI-025)); and how a later, restricted reading of it applies, which implies a schema change between writing and reading.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **(wire format)** "in the unrestricted case of `Schemas.OfAny` the wire format is simply plain data". As the user put it, "a complex case that deserves its own CAPABILITY id and name. it seems to involve open world modeling that allows the wire format to be written unrestricted and read restricted which implies a schema change between writing and reading. I think that may be correct interpretation and possibly useful but I don't want to get stuck litigating it."

# CAP-083: policies with guards and distributions

*Implements* [FEA-021: every generation ambiguity a parameter](../features/FEA-021.md), [FEA-017: AI in the loop via the model trace](../features/README.md#FEA-017), [FEA-018: humans in the loop via the model trace](../features/README.md#FEA-018).

## Design

### Policies, in the core

- **Policies, in the core**, are clauses that each weigh one transform's candidates with given arguments. Guards (an
  `OfPattern` over the match) and distributions over a parameter's domain are designed above and not built yet.

### Policies as data

- `Transforms.Policy`: clauses, each a transform, a guard (an `OfPattern` of mbse-schemas and its arguments), preferences over
  arguments or a distribution over a parameter's domain, and a weight.

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- **A guard is an `OfPattern`** of mbse-schemas over the match, not a predicate of mbse-patterns, which holds none from
  0.10.0 ([CAP-150: predicates as data](CAP-150.md#decided)), as the user decided (2026-11-05), asked whether a guard should now be an `OfPattern`: "yes".

## Open questions

- **A dependency on mbse-patterns.** Distributions are mbse-patterns', so policies weighed by them would make
  mbse-transforms depend on mbse-patterns ([mbse-transforms' charter](https://github.com/pitaman71/mbse-transforms/blob/main/docs/proposals/charter/README.md#risks), Risks).

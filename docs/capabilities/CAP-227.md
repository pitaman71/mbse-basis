# CAP-227: the Python3 expression dialect

*Implements* [FEA-024: expressions as data](../features/FEA-024.md), [FEA-008: expressive program models](../features/FEA-008.md). *Relates to* [CAP-226: complete expression dialects](CAP-226.md), [CAP-100: six languages' expression dialects](CAP-100.md), [CAP-036: complete kinds for Python, TypeScript and C and C++](CAP-036.md), [CAP-038: every construct of Python's standards](CAP-038.md), [CAP-089: Python expressions bridged to Python source](CAP-089.md).

## As built: mbse-expressions

Built in mbse-expressions' stage 3 of [the complete dialects](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#stages-proposed-once-decided)
(main at 7d85127, PR #16) and released in 0.8.0, in both languages, its schemas named by the namespace rename
(`Expressions.Python.Python3`, [CAP-226: complete expression dialects](CAP-226.md#decided), Decided); every choice made where the decisions were silent is in
[the port's API, Settled in stage 3 (Python3)](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-stage-3-python3-for-the-users-review), items 50 to 69,
which hold the detail this section only bridges. `Python3` is a complete dialect by
[CAP-226: complete expression dialects](CAP-226.md)'s rules: every expression kind of CPython's `ast`, 3.0 to 3.15, a
branch of the dialect's value union, `Expressions.Python.Python3.Term`, whose holder is `Expressions.Python.Python3.Expression`; its
statements, and the `match` patterns and type parameters that belong to them, stay mbse-programs'. Reading Python's
every construct is [CAP-038: every construct of Python's standards](CAP-038.md)'s, and the bridge it replaces
[CAP-089: Python expressions bridged to Python source](CAP-089.md)'s.

- **The kinds**: each of `ast`'s, `Expressions.Python.Python3.<Name>`, in mbse-programs' names and shapes, its properties in
  source order, tagged by its name lowercased (`binop`, `generatorexp`), the expression context not represented (items
  50 and 51). The framework's `variable`, `list` and `let` are reused where the shape matches; Python3's own `dict`
  replaces `mapping`, since a `**m` item has no key (item 52). `let`, `import` and `importfrom` are extensions, and
  `parenthesized` and `concatenatedstring` keep concrete syntax (items 55 and 56). Each kind records the versions that
  have it as data, which nothing reads yet (item 57).
- **Binding targets**: `Expressions.Python.Python3.Pattern` lists the kinds Python's grammar allows as a target
  (`variable`, `tuple`, `list`, `starred`, `attribute`, `subscript` and `parenthesized`), each the schema `Term`
  lists, no new kinds; a comprehension's and a named expression's `target` hold it, read as a helper, and a lambda's
  `arg`s stay as they are. Added in stage 4 (main at 8804e1e, PR #18), as decided (below); the wire and the corpus are
  unchanged, and DIA-19 checks it (item 86). Since stage 5 it also lists `error` and `missing`, and Python3's
  evaluator refuses them by name, "Python3 error is not evaluated" (API 101).
- **The helpers**: what a kind holds that is not a term (a `keyword`, a `comparison`, a `comprehension`, a lambda's
  `arguments` and `arg`s, an f-string's parts) is read by `Terms.form` as a `Terms.Part` and written back by
  `Dialect.make`, so that translation patterns match its structure; a `Kind` declares what its role does not say, its
  optional slots, the names each argument binds, a chain's operators, its unfolding and its spelling (items 58 to 60).
- **The replaced kinds**: the five narrower than `ast`'s are replaced, `subscript` and `index` by one `subscript`
  whose index is any term (with `slice` and `tuple` for a tensor's indices), `generator` by `generatorexp` of
  `comprehension`s, a comparison of one operator by a chain, `and` and `or` of two by a `boolop` of n `values`, and a
  call without keywords by one with `keywords` (item 50).
- **Constants**: a basic scalar is Python3's `literal`, `Expressions.Python.Python3.Literal`, which refines the framework's
  ([CAP-167: schemas refined by other schemas](CAP-167.md)) and adds what its text encodes
  ([CAP-233: literals of any value](CAP-233.md)); what no schema holds, `None`, `...` and complex numbers, is Python3's
  own `constant`, `Expressions.Python.Python3.Constant` (item 53).
- **Printing**: `Text.ToText` prints every kind in both languages, by Python's precedence, a literal by its spelling
  where it has one (item 64).
- **`FromText`** reads every `ast` kind, in Python, keeping each literal's spelling and what it encodes, adjacent
  strings, and an f-string's or a t-string's text as written; it reads `(lambda name: body)(value)` as a `let` (items
  56 and 65). It stays here until mbse-programs reads `Python3`
  ([CAP-226: complete expression dialects](CAP-226.md#decided), Decided).
- **Completeness as data**: `grammars/python3-ast.json` lists each node of `ast` an expression is or holds, 3.0 to
  3.15, each mapped to a kind, a helper or an operator, or listed as not an expression with its reason. DIA-20 checks
  it in both languages and, in Python, against the running interpreter's `ast`; DIA-19 checks the new kinds; the
  corpus's `python3` case holds every kind (items 66 and 68).
- **Evaluation stays shallow**, as decided ([CAP-226: complete expression dialects](CAP-226.md#decided), Decided):
  what was evaluated keeps evaluating in its complete shape, and every other kind, `constant` among them, and what an
  evaluated kind holds beyond that, is refused by name, "Python3 lambda is not evaluated" (item 62). The translators keep what
  they translated (item 63).

## Decided

As the user decided (2026-11-03, in building mbse-expressions' stage 4,
[the proposal's Decided](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/dialects/README.md#decided)):
adopted, the rule as stated, quoted where the wording matters.

- **Python3's binding targets hold its `Pattern` union.** Asked "is this done consistently across typescript5 and
  python3? can it be?", and shown (i) each dialect following its own grammar (`TypeScript5` a `Pattern` union,
  `Python3`'s targets holding its `Term`) or (ii) a uniform rule where every dialect has a `Pattern` union for binding
  targets, the user: "(ii)". `Python3` gains `Expressions.Python.Python3.Pattern`, listing the term kinds a binding target may
  be, no new kinds, one schema in several unions; a comprehension's and a named expression's `target` hold it; a
  lambda's parameters, `arg`s, stay as they are. The rule for every dialect is
  [CAP-226: complete expression dialects](CAP-226.md#decided)'s.

## Decided by an agent, for review

Recorded in [the port's API, Settled in stage 3 (Python3)](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-stage-3-python3-for-the-users-review), and item 86 in
[Settled in stage 4 (TypeScript5)](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md#settled-in-stage-4-typescript5-for-the-users-review), not
marked as the user's: each *proposed* until reviewed.

- **(mbse-expressions port, API 51)** **mbse-programs' shapes over the brief's wording**: a comparison chain is
  `left` and `comparisons`, each a `comparison` (`op`, `comparator`), not `ast`'s parallel `ops` and `comparators` as
  the brief's parenthetical had it, and a dict display is `items`, each a `dictitem` (`key`, `value`, no key for
  `**value`), not `keys` and `values`, since the decision is mbse-programs' kinds, names and shapes
  ([CAP-226: complete expression dialects](CAP-226.md#decided), Decided).
- **(mbse-expressions port, API 54)** **A lambda's body is a term**, a slot of `lambda`: it is an expression in
  Python. That "a body is not part of the term" ([CAP-226: complete expression dialects](CAP-226.md#decided),
  Decided) is read as concerning statement bodies (a function's, a class's), which are mbse-programs' owned reference
  objects.
- **(mbse-expressions port, API 60)** **A named expression's scope**: it binds its target within itself only. In
  Python it binds the name in the enclosing scope, which a term does not model, so a later use of the name is the
  caller's to bind.
- **(mbse-expressions port, API 53)** **Two constant kinds, divided by what a schema holds**: a basic scalar is a
  `literal`, Python3's refining the framework's; `None`, `...` and a complex number are Python3's `constant`
  (`singleton`, or `real` and `imag`, exactly one of them, with `text`, `problems` and `separators`), and one writer,
  `constant(value, text)`, writes either by its value.
- **(mbse-expressions port, API 63)** **Chains and n-ary `and` and `or` unfolded for translation**: no translator has
  a rule of its own for them; `Kind.unfold` reads a chain as the `and` of its links, its middle operands written in
  each (evaluated twice where Python evaluates them once), and n values as two, nested, so that `2.0 <= c <= 8.0` read by
  `FromText` translates into Patterns as before. As a side effect, Patterns' nested `and`s are Python3's nested
  `boolop`s, printed in Python as `(a and b) and c`, as `ast.unparse` writes them.
- **(mbse-expressions port, API 86)** **A binding target read as a helper**, a `Terms.Part`, as TypeScript5's patterns
  are: its terms follow the clause's own (a comprehension's iterable and conditions, a named expression's value), so a
  form's arguments are reordered; a target's own checks (a name an identifier, a target present) are its holder kind's,
  as validation does not read a helper; and a hole may stand within a helper's attributes in a translation pattern, as
  a comprehension's target does in the rules of `all`, `any` and counting.
- **(mbse-expressions port, API 62)** **The new refusals by evaluation**: `NotImplementedError` by name for each kind
  not evaluated before, and for what an evaluated kind holds beyond its former shape ("Python3 keyword is not evaluated",
  "Python3 dict's ** item is not evaluated", "Python3 async comprehension is not evaluated", "Python3 tuple target is
  not evaluated"), and for an operator its open vocabulary has but no implementation ("Python3 binop '@' is not
  evaluated", "Python3 compare 'is' is not evaluated").

# CAP-163: parameters bound, applied and generated beyond mbse-schemas

*Implements* [FEA-033: model parameters](../features/FEA-033.md). Index entry: [capabilities/README.md](README.md#CAP-163). *Relates to* [CAP-113: parameters bound at their definitions](CAP-113.md), [CAP-114: parameter bindings are substituted and checked](CAP-114.md), [FEA-024: expressions as data](../features/FEA-024.md).

## Design

Not built. What mbse-schemas' Parametrics ([CAP-112: parameters modeled as schema data](CAP-112.md)) leaves to the repositories that depend on it, as the framework design listed it ("Later, elsewhere"):

- mbse-expressions: binding (`Parameters.Bind`, `Parameters.Apply`), value parameters, terms and domains (widths);
  schemas as binders, so that `free` sees their parameters; an evaluator for terms.
- mbse-patterns: a predicate's parameters become `OfParameter`s, and applying one binds its symbols and its parameters
  apart (today both are one positional list). Both are variables the predicate binds; they differ in what
  determines them, data or the application.
- mbse-programs: statements and definitions bind and refer to parameters.
- mbse-codegen-*: a parametric schema as each language's own construct. Where a language has no value parameters
  (Python, TypeScript), how to express one is a parameter of the generating step.

In mbse-codegen-python, type parameters are [CAP-049: type parameters in Python3](README.md#CAP-049); in TypeScript5, [CAP-058: type parameters in TypeScript5](README.md#CAP-058).

## Open questions

- **Equality of differently written applications** that substitute alike (`Matrix(n, n)` and `Square(n)`), from the framework design's "Parametrics, beyond the proposal". Applications (`OfApply`) are mbse-expressions' since 0.17.0.

## Decided by an agent, for review

Recorded in mbse-schemas' design, not marked as the user's: each *proposed* until reviewed.

From the framework design's Parametrics, Decided, where it was not marked as the user's:

- **Parameters stay parameters in generated code.** Each target language expresses them as its own construct (a C++
  template parameter, a SystemVerilog `parameter`), not as values substituted before generating. (mbse-codegen-python records the user's "DropParametric? Absolutely not." in [CAP-027: Python3 source generated from schemas](CAP-027.md).)

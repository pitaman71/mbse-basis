# CAP-259: TypeScript's Patterns evaluators independent of domain inference

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Relates to* [CAP-232: domains inferred for terms](CAP-232.md).

## Design

Not built. This capability is tech debt, incurred by mbse-expressions' value domains in code ([CAP-097: value domains of published standards](CAP-097.md)), before 0.6.0,
and carried from Basic to Patterns. TypeScript's Patterns evaluator and partial evaluator find a value's native type through `Domains.nativeDomain`
(`Patterns/Expressions/Evaluators.ts`, `domainOf`; `Partials.ts`, `literal`; checked in mbse-expressions' main
at 3711f8a), which is inference's code (`Dialect.infer`'s domains, in code), that [CAP-232: domains inferred for terms](CAP-232.md) replaces; Python's use plain native
types (`_is_native`, `type(value) in Schemas.SCALAR_TYPES`). Met when TypeScript's evaluators use a native-type check
of their own, as Python's do, so that replacing inference's code leaves evaluation as it is.

It implements [FEA-024: expressions as data](../features/FEA-024.md) rather than [FEA-019: equivalent implementations](../features/README.md#FEA-019): both languages pass the same cases, so the two
implementations' behavior does not differ; what differs is which code TypeScript's evaluators depend on, and that
dependency was incurred by the work on value domains, under [FEA-024: expressions as data](../features/FEA-024.md). [FEA-019: equivalent implementations](../features/README.md#FEA-019) is reinforced by
principles rather than capabilities.

## Decided

- **Logged as tech debt** (2026-11-10): as the user decided, "Tech debt is capability codes, not notes in markdown",
  and "I don't know why you would expect a single feature to contain all tech debt items"; approving ("yes") that each
  debt be a capability of the feature whose work caused it, relating to [QUA-014: precise typing for bespoke and generated source code](../QUALITIES.md#QUA-014) where it concerns typing, and
  that a debt an existing capability already covers be linked to it rather than made a capability of its own.

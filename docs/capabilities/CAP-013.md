# CAP-013: an in-memory store journaled to DynamoDB

*Implements* [FEA-006: persistence](../features/FEA-006.md), [FEA-045: a Python, FastAPI and DynamoDB service stack](../features/FEA-045.md).

The service loads the store into memory at startup and executes
transactions over it. Each committed transaction is persisted to DynamoDB
as a journal entry, with occasional snapshots; startup reads the latest
snapshot and replays the journal after it.

Superseded by [CAP-289: journals kept in DynamoDB](README.md#CAP-289), which refines it: a journal kept in DynamoDB
is the only record, with an index kept current from it from which a store reads one object, and no snapshot, as
[the journal storage proposal](../../proposals/JOURNAL-STORAGE.md) and [the stacked stores
proposal](../../proposals/STACKED-STORES.md) decide. mbse-rest's service is a store stacked on it, which loads what it
is asked for rather than holding the whole store in memory, and persists by that journal alone
([CAP-290: a service's store stacked, with no snapshot](CAP-290.md)); the persistence plugin through which the service
journaled and snapshotted, and mbse-dynamodb's implementation of it, go with it.

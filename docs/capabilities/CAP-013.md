# CAP-013 · in-memory store journaled to DynamoDB

From the workspace's `VISUALIZATION.md`. *Implements* [FEA-006](../features/FEA-006.md). Index entry:
[capabilities/README.md](README.md#CAP-013).

The service loads the store into memory at startup and executes
transactions over it. Each committed transaction is persisted to DynamoDB
as a journal entry, with occasional snapshots; startup reads the latest
snapshot and replays the journal after it.

- UI proposes a mutation query using a mutation template (CAP-004)
- `mbse-rest/typescript5/mbse/Services/Rest/Client.ts` translates the mutation query into well-formed REST call(s)
- REST request is sent and received
- `mbse-rest/python3/mbse/Services/Rest/Service.py` unpacks the REST payload into mutation expression form
- mbse-schemas' executor runs the mutation expression over the in-memory store
- for a transaction that writes, `mbse-dynamodb/python3/mbse/Persistence/DynamoDB/Plugin.py` journals it to DynamoDB when it commits
- `Service.py` fills each frame's `assigns` and `entries` as the view kind defines (CAP-012; decided by the agent, for review), serializes the frame stream and returns it as response data
- `Client.ts` reads the frame stream back for the UI

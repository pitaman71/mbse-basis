# CAP-314: parameters assigned or bound by the data objects their schema governs

*Implements* [FEA-033: model parameters](../features/FEA-033.md). *Supersedes* [CAP-113: parameters bound at their definitions](CAP-113.md). *Relates to*
[CAP-313: parameter references valid where their parameters are assigned or bound](README.md#CAP-313), [CAP-312: a parameter reference in place of anything with a schema](CAP-312.md), [the parametrics proposal](../../proposals/PARAMETRICS.md#decided).

A schema may declare parameters, and a reference object that the schema governs may assign a value to any of them,
through `Parametrics.AssignsValue`, or bind any of them to an object, through `Parametrics.BindsObject`; each links the
object and the parameter. A parameter that the object leaves unassigned and unbound stays so. A schema assigns or binds
none of its own parameters.

## Decided

As the user decided, besides the decisions the parametrics proposal records:

- **A schema's objects assign and bind through an extension** ("yes Parametrics.extend"; named adjacencies, "Yeah
  ofc"). `Parametrics.extend` gives a schema two named adjacencies, `assigned_values` and `bound_objects`, through
  which its objects assign and bind its parameters, as `Provenance.extend` gives a schema its records' adjacencies.
- **Values are assigned, objects bound**: "Values are not bound. Values are assigned." A parameter is assigned a value
  through `Parametrics.AssignsValue`, and bound to an object through `Parametrics.BindsObject`.
- **The object bound needs no opt-in** (the latter of the options offered). `BindsObject`'s `obj_ref` links any
  reference object, whose schema declares nothing for it.
- **Schemas of schemas are not extended**: "schema of schemas" names the plain schemas whose instances are schemas
  (`Schemas.OfObject`, ...), and "meta-schema" names the static classes one level up (`Schemas.Meta.OfObject`), as the
  user corrected. `Parametrics.extend` refuses a schema of schemas, as it refuses a value-object schema.
- **Value objects bind differently** ("Value objects bind differently. For expression terms, a parameter binding term
  can be a kind of term."). A value object is never linked, so that `AssignsValue` and `BindsObject` serve reference
  objects alone. In mbse-expressions, a term assigns or binds parameters as a kind of term of its own.
- **The bound object's link is named `object`** ("yes as you suggest"). `AssignsValue` links `object` and `param`, its
  value the property `value`; `BindsObject` links `object`, `param` and `obj_ref`.

## Design

- An assignment or a binding names a parameter that the object's schema declares, and one of any other parameter is
  refused when its transaction commits.
- Whether an assigned value, or a bound object, is of the schema that its parameter is for is validated by
  [CAP-313: parameter references valid where their parameters are assigned or bound](README.md#CAP-313).

## Open questions

- **Value objects outside expressions.** How does a value object that is not an expression term, such as a matrix
  held as a value, assign or bind parameters?

# CAP-296: simplification over literals, variables and parameters

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Applies* [PRI-046: simplification, not evaluation](../PRINCIPLES.md#PRI-046). *Relates to*
[CAP-295: simplification of single-dialect expressions with literal leaves](CAP-295.md), [CAP-312: a parameter reference in place of anything with a schema](CAP-312.md),
[CAP-313: parameter references valid where their parameters are assigned or bound](CAP-313.md), [CAP-319: contexts as schema data](README.md#CAP-319),
[the parametrics proposal](../../proposals/PARAMETRICS.md#simplified).

An expression of one dialect whose leaf terms mix literals, arguments or variables, and parameters is simplified by its
dialect, each known leaf substituted and each closed subterm folded. A parameter reference is a leaf: the simplifier
substitutes what its context assigns or binds to the parameter, and leaves a parameter that its context neither assigns
nor binds in the residual, where an ancestor may still fold it away (`false && p`).

## Design

- **The context.** A simplifier takes a context as its scope ([CAP-319: contexts as schema data](README.md#CAP-319)): a
  `Contexts.OfContext`, whose `parameters` give each parameter's value or object, apart from its `variables`, so that a
  parameter and a variable of one name never collide. A dialect's own statements that assign or bind a name make a
  sub-context, copied from the context around them ([the Context + References + Changes cleanup proposal](../../proposals/CONTEXT-REFERENCES-CHANGES.md#decided)).
- **Where it is built.** A parameter reference stands in a term place in place of a term
  ([CAP-312: a parameter reference in place of anything with a schema](CAP-312.md)). The framework's term readers and its simplifier meet it, once for every dialect, rather
  than each dialect's simplifier. The dialects whose simplifiers read terms by another route, SystemVerilog, C and
  TypeScript5, are given the parameter resolved or left as a leaf before they read the term.
- **Substituted.** A parameter that the context assigns a value is replaced by the value, lifted into a term of the
  dialect as a variable's value is; a parameter that the context binds to an object is replaced by the object, where
  the place takes one. A parameter given something of the wrong kind or schema is left in the residual, and validation
  reports it ([CAP-313: parameter references valid where their parameters are assigned or bound](CAP-313.md)).
- **Left in the residual.** A parameter that the context neither assigns nor binds is written back where it stood,
  through the place's `as_parameter`, and the result names it among its free parameters, beside its free variables.

## Decided by an agent, for review

- **Structural sameness compares a parameter reference by its name.** `Terms.same`, which tells whether two terms are
  written alike, and which translators and tests use, compares two parameter references by their names, so that terms
  differing only in their parameters' names differ. Comparison of values halts on a parameter reference, giving its
  unknown result, as [CAP-312: a parameter reference in place of anything with a schema](CAP-312.md#decided) decided; sameness asks only whether two terms are written alike.

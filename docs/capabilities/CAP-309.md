# CAP-309: errors annotated on frames

*Implements* [FEA-027: mutations as queries](../features/FEA-027.md).

An error that occurs while a mutation transaction is processed is annotated on the frames it concerns; an unresolvable
error partway through interpreting the expression gives a partially bound frame, preferred to none. It is part of
[the stacked stores proposal](../../proposals/STACKED-STORES.md#stacking-by-mutation-transactions), whose layers stream
frames, errors among them, rather than raise.

## Decided

The user's decisions (2026-11-16):

- **A transaction with an error on a frame is uncommitted, whole** ("yes, the whole transaction is uncommitted"): no
  write of it commits, as [CAP-124: writes all-or-nothing in transactions](CAP-124.md) has it, and its caller is given its frames,
  each annotated with what failed, in place of none.
- **Errors while frames are made are annotated; errors in the expression itself are raised** ("yes to both, split as
  you suggested"): an error that arises as a term processes a frame, as a unique clause broken, an object reference that
  resolves to nothing or a value that does not decode, is annotated on that frame, which stays as bound as it was; an
  error found in checking the expression before it runs, as a term using a symbol none binds, is raised, before any
  frame is made.
- **The shape** ("yes to the shape"):
  - `References.OfFrame` gains `errors`, each naming the subterm, the kind of error and its message;
  - in memory, a frame is a mapping of its symbols as it is, with the errors annotated on it, so that what reads a
    frame today reads it still;
  - `store.transaction(...)` raises where it refuses a transaction, as it does, the error carrying the annotated
    frames;
  - a layer of a stack ([CAP-308: stacking by mutation transactions, in one round trip](README.md#CAP-308)) streams the annotated frames, and does not raise.

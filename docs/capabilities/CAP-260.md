# CAP-260: a dialect extending Patterns validated against its own operations

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Relates to* [CAP-098: dialects over one framework](CAP-098.md).

## Design

Not built. This capability is tech debt, incurred by mbse-expressions' domains as data, stage 2. Patterns' validation
finds the dialect whose operations it reads by a fixed path, `store.Instances.Expressions.Patterns.Expressions`
(Patterns' `call` kind, `operations`, in both languages; checked in mbse-expressions' main at 3711f8a), so a dialect
extending Patterns would validate against Patterns' operations, not its own. No dialect extends Patterns, and no case
tests one. Met when a dialect extending Patterns validates against the operations it defines, with a case in both
languages.

## Decided

- **Logged as tech debt** (2026-11-10): as the user decided, "Tech debt is capability codes, not notes in markdown",
  and "I don't know why you would expect a single feature to contain all tech debt items"; approving ("yes") that each
  debt be a capability of the feature whose work caused it, relating to [QUA-014: precise typing for bespoke and generated source code](../QUALITIES.md#QUA-014) where it concerns typing, and
  that a debt an existing capability already covers be linked to it rather than made a capability of its own.

# CAP-097: value domains of published standards

*Implements* [FEA-024: expressions as data](../features/FEA-024.md). *Relates to* [CAP-232: domains inferred for terms](CAP-232.md).

## As built: mbse-expressions

### Value domains

As built in mbse-expressions 0.7.0 (the port's stage 3): domains are data, owned by the dialect that defines them,
and their kinds' semantics are code, unused by evaluation. A term carries no domain (Decided, below): evaluation takes
values by the schemas they are written with, ints unbounded and floats binary64, and giving each term its domain, with
the widths, formats, conversions and typed literals that need it, is
[CAP-232: domains inferred for terms](CAP-232.md)'s. Each domain names a published standard where one exists, with
only the parameters that standard defines, and today's natives are their defaults. The settled points are the port's
[API](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/API.md), Settled in stage 3, 16 to 29.

| Domain kind | Parameters | Default (today's native) |
|---|---|---|
| `ieee754` | `format`: `binary16`, `binary32`, `binary64`, `binary128`, `decimal64` or `decimal128`; `rounding`: one of the standard's rounding-direction attributes, `roundTiesToEven`, `roundTiesToAway`, `roundTowardPositive`, `roundTowardNegative` or `roundTowardZero` | `binary64`, `roundTiesToEven` (`float`) |
| `integer` | `width`, optional (unbounded without it); `signed`; `overflow`: `wrap`, `saturate` or `raise` | unbounded (`int`) |
| `bits` | `width` | |
| `bytes` | `width`, fixed or variable | variable (`bytes`) |
| `unicode` | none | `str` |
| `ieee1164` | `width`, optional: one state without it (`std_logic`), that many with it (`std_logic_vector`) | |
| `enum` | its `members` | |
| `packed` | its `codes`, one per member of the enum it packs; its enum and its representation linked by `Packs` | |
| `bool` | none | `bool` |

- **Domain kinds are data.** A domain is an `Expressions.Framework.Domain`, a reference object holding its `kind`, a
  value of the kind union `Expressions.Framework.DomainKind`, whose branches Basic's install adds, one per row above
  (API 17).
- **A dialect owns its domains: `Expressions.Framework.Defines(dialect, name, domain)`**, unique `[dialect, name]` and
  `[domain]`, the domain's adjacency `dialect` its owner, so a domain's path is its dialect's singleton then its name
  (`basic.domains({"name": "uint8"})`): snapshots write it, documents refer to it, and a document of a domain or a
  dialect reads back as the object the store holds (API 17). A dialect is a singleton of its own schema,
  `Expressions.<Dialect>.Dialect` (Basic's: `Expressions.Basic`), a branch of the kind union
  `Expressions.Framework.Dialect`, with the adjacencies `domains` and `operations` (API 16). Data owned by a schema
  object fails to write in mbse-schemas, which this ownership works around (API 26).
- **`Expressions.Framework.HasDomain(schema, domain)`**, unique both ways, relates a domain to its schema, a named
  `Schemas.OfAny` restricted to the scalar it narrows, defined by the dialect's install in its module
  (`Expressions.Basic.uint8`, `Expressions.Basic.binary32`, ...); `Schemas.OfAny` gains the extension adjacency
  `domain` (API 19). Basic defines `bool`, `int`, `float`, `str`, `bytes`, `uint8`, `binary32` and `std_logic`,
  written in fluent syntax by `Basic.define`; the corpus's `domains` case is Basic's dialect, one document, with an
  enum and a domain packing it into `uint8` (API 27).
- **A packed domain links its enum and its representation through `Expressions.Basic.Packs(packed, domain,
  representation)`**, unique `[packed]`, the domain's adjacency `packs`: a value cannot hold a reference object, so the
  link is to the domains' paths (API 18).
- **The kinds' semantics are kept as code, unused by evaluation.** `Domains.read(domain)` gives a stored domain's data
  (`OfX.Data`, compared by structure), whose `contains`, `compare`, `fit` and `validate` stay, unused by evaluation
  until domain inference (API 19). `Terms.Dialect.domain_of` (a literal's domain by the scalar it is written with, for
  `infer`) and `Kind.typed` (the domain a kind's own attributes give it, C's `type` of a constant or a cast,
  SystemVerilog's vector, for their own evaluation) stay; neither reads a term's domain, which no term has (API 24).
  Typed values (`Domains.Value`) go; IEEE 754's arithmetic, conversions and encodings stay, which C's and
  SystemVerilog's evaluators use (API 25).
- **Domains name standards.** `ieee754` is IEEE 754-2019's interchange formats, with their values, special values and
  overflow (to infinity, with its exceptions) as the standard defines them; a format outside it (fp8, `bfloat16`, x87's
  80-bit format) would be a domain of its own, named for its specification, and none is defined yet. `ieee1164` is
  VHDL's nine-valued `std_logic`; SystemVerilog's four-state `logic` is its subset `{0, 1, X, Z}`. `integer` is two's
  complement, the only signed representation C23 and C++20 allow, so ones' complement and sign-magnitude are not
  domains.
- **`bits` and `bytes` are unformatted.** `bytes(n)` and `bits(8n)` hold the same patterns, but they are separate
  domains.
- **`unicode` values are sequences of code points, compared by code point.** An encoding (UTF-8, UTF-16, UTF-32) is
  representation only: equal code points are equal strings in any encoding. Canonical equivalence is not equality. A
  lone surrogate is not a value of `unicode`. A `unicode` domain has no width: a maximum length is a constraint of the
  data, and belongs in the schema.
- **`enum` is a domain in its own right**: a C or SystemVerilog `enum`, one bit's states, or an enumeration of
  mbse-schemas. Its members are unordered; a `packed` enum orders by its representation, as C compares enums by their
  integers.
- **Packing is its own domain**: an enum paired with a fixed-size domain and the representation of each member in it,
  so one enum can be packed several ways (SystemVerilog's `enum logic [1:0] {IDLE, RUN}` is an enum packed as
  `bits(2)`).
- **Operations as data, beside the domains.** A dialect names its operations through
  `Expressions.Framework.Operates(dialect, name, operation)`, unique `[dialect, name]` and `[operation]`, owning
  nothing: an operation is a `Schemas.OfExpression` its module owns (`Expressions.Basic.<name>`), its pattern's
  variables its arguments, positional in their declared order, its `result` its return (API 20, 21). A call to an
  operation Basic does not define is refused by validation and evaluation (API 22). The container constructors `list`
  and `mapping` are framework kinds (API 23). Other dialects' operations as data are a follow-up: each has its
  singleton, empty, its vocabulary code (API 28). A failure of mbse-schemas under some runtimes, seen while building,
  was resolved by mbse-schemas 0.26.5 (API 29).

## Design

### Domains and scalar values (mbse-schemas' schema extension, 2)

Moving `.bits` and `.bytes` means associating a domain to a scalar schema: built as `HasDomain` between a domain and
its schema, a named `Schemas.OfAny` restricted to the scalar it narrows (As built, above). A literal's value is an
`OfAny` of the five basic scalars ([CAP-095: Basic terms as data](CAP-095.md)), so no value properties per scalar are
needed.

### Relocating things from mbse-schemas (mbse-schemas' schema extension, 3)

Definitely:

- constraining the size of Schemas.OfScalar : move to mbse-expressions via `HasDomain` per above
- allowing schemas to define parameters on definition and bind them to expressions on instantiation : keep in mbse-schemas except for typing via `HasDomain`
- allowing Schemas.OfScalar (maybe others) to be bound to an expression

### Parameters (mbse-schemas' schema extension, 4)

In mbse-schemas, a parameter can only denote a schema
In mbse-expressions, a parameter can denote a schema or a domain

## Decided

As the user decided: adopted, each the rule as stated, quoted where the wording matters.

- (Superseded by the port's stage 3, below: a term carries no domain, and domains are objects their dialect defines
  by name.) **A term's domain is a registered name until the port's stage 3** (2026-10-30, "yes", on what the port's
  stage 2b raised; [the port](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/README.md#decided), Decided), translators'
  conversions registering the domains they hand back included. Stage 3 makes domains objects that dialects define by
  name ([FEA-024: expressions as data](../features/FEA-024.md#decided), Decided, "Porting to the stabilized
  mbse-schemas", 4), in place of the process-wide registry.
- **The port's stage 3** (2026-10-30, reviewing a first draft that made domains objects a term named;
  [the port](https://github.com/pitaman71/mbse-expressions/blob/main/docs/proposals/port/README.md#decided-for-stage-3), Stage 3's model, Decided,
  1 to 6, and the answers on A, B and C):
  1. **A term carries no domain.** "Terms do not designate their schema. Whatever reference object owns the root term
     must specify its schema." Every kind loses `domain`, the framework's and each dialect's. This supersedes "wait,
     all terms have a domain" (2026-10-28) and mbse-schemas' Schema extension, Decided, 21's "A term has a domain"
     ([FEA-024: expressions as data](../features/FEA-024.md#decided)).
  2. **No domain inference yet**, and what needs a term's domain deferred with it: [CAP-232: domains inferred for terms](CAP-232.md#decided),
     where it is recorded.
  3. **Terms hold values.** "terms are not restricted to scalars. Terms can have any value (Schemas.OfAny)"; then
     "yes restrict `literal` to scalars, but also provide container constructors as terms". A `literal` stayed an
     `OfAny` of the five basic scalars (the agent's gloss of "scalars"); new kinds construct containers from terms.
     *Superseded* (2026-11-02): a literal holds any value ([CAP-233: literals of any value](CAP-233.md#decided)).
  4. **Expressions deal in values.** "CORRECTION: 'expressions only deal in scalars' -> 'expressions only deal in
     values'" (Schema extension, Decided, 13).
  5. **Every domain a schema.** "(i) can we make every domain a schema too?", and on the proposal that answered it
     (A): "you can choose to keep the schema and domain separate and track them through a relation with unique, or use
     schema extension". Chosen: both kept separate and related, since an extension adds only an adjacency to a
     relation of two links and no properties, so a domain's parameters need an object of their own either way. The
     domain's schema is a named `Schemas.OfAny` restricted to its scalar, defined in its dialect's module
     (`Expressions.Basic.uint8`); the domain is an `Expressions.Framework.Domain`, holding its `kind`;
     `Expressions.Framework.HasDomain(schema, domain)`, unique both ways, relates them, and an extension adjacency
     `domain` on `Schemas.OfAny` reads it from the schema.
  6. **Dialects model their operations.** "(ii) dialects also define operation models which arguments as
     Schemas.OfVariable and return value as Schemas.OfAny", and on the proposals for it and for container
     constructors (B and C): "okay for now". An operation is a `Schemas.OfExpression` its dialect names, its pattern's
     variables its arguments and its `result` its return; `list` and `mapping` are framework kinds.
- **Each dialect a singleton by name** (2026-11-01, confirming the coordinating agent's proposal built on the user's
  direction of 2026-10-30, "It's not hard to add an ownership path to the schema" and "ah, schema *extension* is the
  preferred form"): "yes, each dialect has a singleton by name"; with Decided, 4 of the port, it owns its domains
  through `Defines(dialect, name, domain)` (As built, above).

## Decided by an agent, for review

Recorded in mbse-expressions' design, not marked as the user's: each *proposed* until reviewed.

- An `Ieee1164` domain of a `width` is VHDL's `std_logic_vector`, its value that many states, the most significant
  first; without one it is a single `std_logic`. SystemVerilog's binary vectors and those with x or z bits are its
  counterparts.
- An `Enum` is unordered unless packed, when it orders by its representation. (The conversions moved to
  [CAP-232: domains inferred for terms](CAP-232.md), which restores them; a literal stored without a domain, and
  writers leaving defaults out, went with the literal's `domain` at stage 3.)
- (Superseded where a term's domain is named: by stage 3, Decided, above, a term carries no domain.) A literal holds its
  domain by value, as a value object, written by name when the domain is registered and by value
  otherwise; domains compare by structure. A packed domain packs an enum into a fixed-width integer or bits, with an
  integer code per member.
- Value domains name published standards where one exists (`Ieee754`, `Ieee1164`), with only the parameters the
  standard defines, rather than free representation parameters: no float format by widths and flags, no ones'
  complement or sign-magnitude integers, no `Decimal` apart from IEEE 754's decimal formats. The dialect keeps its
  name, Basic, which mbse-schemas' neutral token format (`basic`) shares.

# FEA-005 · inspector views

From the workspace's `VISUALIZATION.md`. Index entries: [FEATURES.md](../FEATURES.md#FEA-005), [CAPABILITIES.md](../CAPABILITIES.md). A capability without an ID is not in plan yet.

## <a id="CAP-017"></a>CAP-017 · object inspector

Status: complete (mbse-react, M3; editing added by CAP-014).

A single object inspector is anchored by the object's schema and the
object's ID.

In any view, a standard UI gesture (defaulting to a click or tap) on any view of an object causes a shared inspector panel to:

- reveal if currently hidden in its standard location
- clear contents and show loading
- navigate to that object; inspector state is kept in no history, the
  browser's or its own
- fetch the logical detail view from the backend
- display the detail view in the inspector panel
- ensure that label remains at the top
- if the detail panel has action buttons, they remain 
  at the bottom while other properties and adjacencies auto-scroll
  in between

## <a id="CAP-018"></a>CAP-018 · adjacency inspector

Inspector view of an adjacency which permits viewing and modification
of property values across the entry and an "outbound" object that may
be extant or proposed.

The adjacency inspector view is anchored at:

- a relation schema
- designation of an "inbound" link name and an "outbound" link name
- identity of an object on the "inbound" side which must be extant
- optional identity of an object on the "outbound" side which may be proposed 

- "+" on every adjacency list opens it with a proposed outbound object of
  the schema that fills the relation's other link (the user picks one
  where several do); saving commits the new object and its entry in one
  transaction
- its editor shows the entry's and the outbound object's properties: text
  as markdown (CAP-014), booleans as checkboxes (CAP-022)

## <a id="CAP-019"></a>CAP-019 · adjacencies at the end of a detail

An object's adjacencies are shown only in its detail (CAP-007), after its
properties, in its schema's declared order: comments last where a schema
declares them last. Where a chip is expected, only chips are shown: no
adjacency list is nested under a chip, in a browser or in an adjacency
list. Deeper levels are reached by inspecting a linked object: a topic's
detail ends with its threads, and a thread's detail with its replies.

An adjacency is previewed as a single chip per entry, divided into two
columns. The left column shows the entry's properties. The right column
shows a pill `{object key} : {object label}` of the linked object, which
is clicked to inspect it. An object without a label of its own (a
comment) is named by its summary, else its first text property, shown as
prose. Where the object has a creation identity and datestamp (CAP-020),
the pill is headed by `{identity} @ {datestamp}`, in italics and a reduced
font.

Adjacencies that are part of the object's ownership path may be shown
abbreviated in breadcrumb form.

## <a id="CAP-020"></a>CAP-020 · provenance display

Where a detail frame carries provenance (CAP-015), the inspector shows who
created the object (its creating session's identity), when it was created
and when last modified, in the browser's locale and time zone; an
adjacency list shows each linked object's author and creation time.

## <a id="CAP-021"></a>CAP-021 · lists ordered by creation

Adjacency lists order their linked objects by creation time where
provenance (CAP-015) is present, and in frame order otherwise.

## <a id="CAP-023"></a>CAP-023 · relation inspector

An object navigator: the object inspector (CAP-017) of one object among
its siblings, stepping to the previous or next sibling.

The relation inspector is anchored by:

- an object
- a relation that holds the object (an entry of it links the object)
- bindings for the relation's other links, and property values on the
  same relation, that define the sibling context

The sibling context is every object linked, through the same link as the
anchoring object, by the relation's entries that agree with the bindings,
ordered as an adjacency list orders them (CAP-021).

- inspecting an object from an adjacency list (CAP-019) opens a relation
  inspector: the adjacency's relation, the inspected object's link, and
  the adjacency's own link bound to the object whose list it is
- inspecting an owned object from the schema browser (CAP-009) opens a
  relation inspector: its ownership relation, the object's link, and the
  other link bound to its owner
- inspecting an object from the object browser (CAP-010) opens a relation
  inspector: its directory's relation, the object's link, and the other
  link bound to the directory's singleton
- inspecting an object anywhere else opens a single object inspector
- where a previous or next sibling exists, arrow icon buttons step to it,
  left and right justified in the inspector's footer; neither is kept in
  any history

# FEA-006 · persistence

From the workspace's `VISUALIZATION.md`. Index entries: [FEATURES.md](../FEATURES.md#FEA-006), [CAPABILITIES.md](../CAPABILITIES.md). A capability without an ID is not in plan yet.

## <a id="CAP-013"></a>CAP-013 · in-memory store journaled to DynamoDB

The service loads the store into memory at startup and executes
transactions over it. Each committed transaction is persisted to DynamoDB
as a journal entry, with occasional snapshots; startup reads the latest
snapshot and replays the journal after it.

- UI proposes a mutation query using a mutation template (CAP-004)
- `mbse-rest/typescript5/mbse/Services/Rest/Client.ts` translates the mutation query into well-formed REST call(s)
- REST request is sent and received
- `mbse-rest/python3/mbse/Services/Rest/Service.py` unpacks the REST payload into mutation expression form
- mbse-schemas' executor runs the mutation expression over the in-memory store
- for a transaction that writes, `mbse-dynamodb/python3/mbse/Persistence/DynamoDB/Plugin.py` journals it to DynamoDB when it commits
- `Service.py` fills each frame's `assigns` and `entries` as the view kind defines (CAP-012; decided by the agent, for review), serializes the frame stream and returns it as response data
- `Client.ts` reads the frame stream back for the UI

## Not yet planned

### store over DynamoDB

`Visitors.OfStore` implemented directly over DynamoDB, so that the store
need not fit in memory.

`mbse-rest` provides server-side and client-side adapter
components that translate query requests and responses, formatted 
as mutation expressions and frame streams. `mbse-dynamodb` 
implements `Visitors.OfStore` via a mutation expression executor 
that translates to and from dynamodb queries.

- UI proposes mutation query using mutation template
- `mbse-rest/typescript5/mbse/Services/Rest/Client.ts` translates mutation query into well-formed REST call(s)
- REST request is sent and received
- `mbse-rest/python3/mbse/Services/Rest/Service.py` unpacks REST payload into mutation expression form
- (persistence plugin) is called with mutation expression
- `mbse-dynamodb/python3/mbse/Persistence/DynamoDB/Plugin.py` query as mutation expression -> dynamo-db queries 
- Dynamodb receives query, processes, and responds
- dynamo-db response -> response as frame streams
- (persistence plugin) responds with stream of frames
- `mbse-rest/python3/mbse/Services/Rest/Service.py` serializes frame stream and returns as response data

# FEA-058: parametric schema templates

*Confers* [QUA-008: usable without code](../QUALITIES.md#QUA-008), [QUA-003: no second-order inventions](../QUALITIES.md#QUA-003).

A template declares, in one schema declaration, the relations that cooperate to give a model a kind of container, an
ordered, sequenced or indexed one, so that a model takes the container whole rather than declaring each relation of it
itself.

## Decided

The user's decisions (2026-11-12):

- **Relation entries have no order, permanently**: "Relation entries have no ordering. That is intentional and
  permanent. Retrofitting any mechanism to entries to give them order counts as a 'second order invention'." A kind of
  container is relations instead: "Indexed containers can have their index encoded as entry props. Ordered and/or
  sequenced containers can use combinations of relations in cooperation":
  - `Contains(container, a)`: a is contained in the container;
  - `Before`/`After(container, a, b)`: in the container, a immediately precedes or follows b;
  - `Precedes`/`Follows(container, a, b)`: in the container, b occurs no earlier than a, or a no earlier than b;
  - `First`/`Last(container, a)`: in the container, a is the first or last element.
- **A feature of its own, with no dependency on parameters yet**: "Currently, tuples of relations that cooperate to
  represent scalable containers exist only in the data schema. There is no proven way to declare a template of
  multiple relations that create particular container behaviors in a single schema declaration. Parameters should
  allow that in the future, but let's not pull that in as a dependency." Until it is built, a model declares a
  container's relations in its own schemas. *Relates to* [FEA-033: model parameters](FEA-033.md).

## Capabilities

- [CAP-292: a sequenced container declared by one template](../capabilities/README.md#CAP-292): not met

# FEA-001 · schema-driven UI

From the workspace's `VISUALIZATION.md`. Index entries: [FEATURES.md](../FEATURES.md#FEA-001), [CAPABILITIES.md](../CAPABILITIES.md). A capability without an ID is not in plan yet.

MVP components:

- `mbse-schemas` : semantic shapes for scalable data
- `mbse-rest` : transactional framework over REST endpoints
- `mbse-dynamodb` : adds persistence in DynamoDB
- `mbse-react` : adds react UI with multiple views

`mbse-dynamodb/python3/mbse/Persistence/DynamoDB` (`mbse.Persistence.DynamoDB`) : where the DynamoDB code lives, in the consolidated package space

## <a id="CAP-001"></a>CAP-001 · no-code index view

Service + UI code must be able to present a useful and usable
"index site" driven exclusively by the schema.

## Not yet planned

### low-code custom views

Service + UI code should allow graceful extension by schema-aware
code provided by developers (e.g. FastAPI endpoints or React components).

# FEA-056: fungible diagramming keeps agents and humans in the loop

*Confers* [QUA-001: AI and humans in the loop](../QUALITIES.md#QUA-001), [QUA-006: the same in every language](../QUALITIES.md#QUA-006). *Relates to* [FEA-001: schema-driven UI](FEA-001.md).

Keeping "humans and agents in the loop" requires transforms to be 
gamified; that is broken into steps at which all possible next moves
are presented, recommendations are offered, and the human or agent
can negotiate exactly what happens next.

This also affects visualization. Static diagramming tools are no longer
sufficient. Rather, diagramming tools must render this kind of "humans and agents in the loop" ongoing negotiation as a fungible and rewindable
editing process.

## Design

[The diagrams proposal](../../proposals/DIAGRAMS.md) holds the design until it is built: 

- a diagram's layout is a deterministic function of its logical layout's mutation sequence, so that humans and agents can
edit it at any step.
- source data is projected onto a *logical layout* of points, vectors and shapes with no coordinates
- each entity in the logical layout has an orientation
- logical layout is projected onto a *container layout* of cells, in both languages
- logical + container layouts are projected onto a *physical layout* that assign coordinates to every point, in TypeScript only
- one incremental algorithm over both layers that processes a mutation sequence, never the model whole

## Decided

The user's decisions (2026-11-03):

- **A vector's rotation is a hard rule.** "There is no situation where it cannot be satisfied."
- **The layout is never re-snapshotted in response to an interactive gesture.** A snapshot is taken when a UI first
  shows a logical layout; each gesture after that is one mutation. Snapshot order is deferred: "It won't hit us because
  the logical layout will itself be a mutation sequence."
- **Every rule-like statement in the design is a rule.** "Everything in the doc that reads like a rule is a rule."
- **Container layout is in both languages, physical layout components in TypeScript only.** "Frontend components need
  not be provided in python"; container layout "both languages". Container layout knows no coordinates of any kind.
- **The physical layout's schemas are in both languages**, though its components are in TypeScript only: "yes ofc".
- **An adjacency spec that reordering cannot satisfy is ignored**, by the rule that ignores the later of two
  incompatible rules: "then the adjacency is ignored, as already stated".
- **A grid may reject or quantize an arbitrary rotation.**
- **One mutation per shape**: a shape is created, with its points and vectors, in one mutation.
- **The logical layout has vectors, not lines**: "vectors not lines".
- **How domain data becomes a logical layout is out of scope.**

# FEA-028: one Store interface, lazy by default

*Confers* [QUA-008: usable without code](../QUALITIES.md#QUA-008), [QUA-017: distributed or local, decided at runtime](../QUALITIES.md#QUA-017), [QUA-018: lazy or eager, decided at runtime](../QUALITIES.md#QUA-018).

Every access to data goes through one store interface, the store's protocol `Visitors.OfStore`, lazy by default: a
store gives what it is asked for, when it is asked, so that any store serves any code alike, and whether it is
distributed or local, lazy or eager, is decided when it runs.

## Decided

The user's decisions (2026-11-12):

- **One Store interface, lazy by default**: "There is one Store interface that is lazy by default." "Store
  implementations primarily deal in schemas, constraints, mutations, changes, and frames"; "remote APIs like mbse-rest
  must implement all methods of Store interface" and "may reject modes offered by the Store interface"; and they offer
  "mutation streams and dynamically tunable cache views over snapshots": "the 'snapshot' data structure violated this
  rule".

## Capabilities

- [CAP-149: data accessed through the store protocol](../capabilities/CAP-149.md): met
- [CAP-161: isolated stores, with no global registry](../capabilities/CAP-161.md): met
- [CAP-283: a store given a store below](../capabilities/README.md#CAP-283): not met
- [CAP-284: objects loaded on demand](../capabilities/README.md#CAP-284): not met
- [CAP-285: writes through, others' writes in](../capabilities/README.md#CAP-285): not met
- [CAP-286: an extent through ownership](../capabilities/README.md#CAP-286): not met
- [CAP-287: lazy or eager, tuned when it runs](../capabilities/README.md#CAP-287): not met

Not yet met: mbse-schemas' `Builders.Store` holds everything it has, and moves data between stores as snapshots
([CAP-127: snapshots made of transactions](../capabilities/CAP-127.md)); mbse-rest persists by snapshot. [The stacked stores proposal](../../proposals/STACKED-STORES.md) proposes what replaces them.

# FEA-003 · no-code logical views

From the workspace's `VISUALIZATION.md`. Index entries: [features/README.md](README.md#FEA-003), [capabilities/README.md](../capabilities/README.md). A capability without an ID is not in plan yet.

Logical views define specific query formats
that must be accessible from the backend via a mutation
expression.

Backend interaction is batched by allowing logical views
to be either requested in isolation or sensibly nested
in a single response. Sensibly nested usually involves

- treating a query as graph traversal
- query-specific limited adjacency traversal rules
- query-specific level of detail per visited object/adjacency

Each logical view kind defines which properties, adjacencies and closures
its response includes.

Objects and relation entries are designated by mbse-schemas References:
`References.OfObject` for an object and `References.OfEntry` for a relation
entry. A response is a stream of `References.OfFrame`, whose `assigns`
(`References.OfProperties`) and `entries` (`References.OfEntry`) carry the
view's data.

Only singletons and owned objects have references. Counted objects are
not recorded or transmitted (tech debt, to revisit).

## Not yet planned

### logical view of object as detail with closures

Extends [CAP-007](../capabilities/CAP-007.md): the response also comprises the closures of the object.

### logical view of closure as list of chips

Given a `References.OfObject` or `References.OfEntry`, 
UI can obtain a logical view template, the response for which
comprises a list of transitively adjacent objects each of
which includes the linked object and a chip view of that object.

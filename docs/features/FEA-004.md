# FEA-004 · index site browser views

From the workspace's `VISUALIZATION.md`. Index entries: [features/README.md](README.md#FEA-004), [CAPABILITIES.md](../CAPABILITIES.md). A capability without an ID is not in plan yet.

Lists of chips should default to auto scroll on overflow rather than
wrapping.

## <a id="CAP-009"></a>CAP-009 · schema browser with scrollable chip previews

A large UI view used to browse defined schemas. 
Each schema is represented by a section. Inside of each section
is the label and description for the schema itself. Then
there is a scrollable list of object preview chips, in frame order for now.

Only schemas which have a *registered name* and a description are included,
and of those only the app's reference object schemas: framework schemas
(`Schemas.*`, `Paths.*`, `Mutations.*`, `References.*`) are excluded.

## <a id="CAP-010"></a>CAP-010 · object browser with scrollable chip previews

A large UI view used to browse extant objects.
There is a section for each schema that names a singleton (a directory),
headed by the singleton's name. Its chips are the objects the singleton
holds, through its adjacencies other than its own ownership; the
singleton's own chip is not shown. Data is populated from the logical
"adjacency" view (CAP-008), whose objects are chips.

Counted objects, which have no reference, are left out (short-term tech
debt). Until view paging, each extent is loaded whole. Objects appear in
frame order for now.

## <a id="CAP-011"></a>CAP-011 · relation browser with adjacency chip previews

A large UI view used to browse relation entries.
Each relation entry is represented by a section inside of which 
there is a chip showing the relation entry properties aside
chip views for each linked object.

Entries that link a counted object are left out (short-term tech debt).
